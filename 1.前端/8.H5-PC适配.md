# H5 / PC 适配

> 图标说明：⭐ 重点｜🔥 高频｜⚠️ 注意｜💡 提示｜📌 重点记忆

## 适配基础

### 1. 🔥 为什么需要 H5 / PC 适配

**简要总结：**

- H5 主要面向移动端，屏幕窄、触摸交互、网络环境复杂
- PC 主要面向桌面端，屏幕宽、鼠标键盘交互、信息密度更高
- 适配目标是让同一套业务在不同设备上都可读、可用、可操作
- 常见方案：响应式布局、移动端 rem/vw、媒体查询、组件级断点

**面试口语：**

H5 和 PC 适配不是简单把页面缩放一下，而是根据设备宽度、交互方式、信息密度重新组织布局。移动端更强调单列、触摸区域和首屏重点；PC 端可以展示更多列、更多筛选项和更复杂的表格操作。

**底层原理 / 背后逻辑：**

浏览器最终渲染的是 CSS 盒模型。适配的本质是让不同 viewport 下的盒子尺寸、排列方式、字体和交互区域合理变化。移动端如果直接用固定 px，很容易在小屏溢出或在大屏显得过小；PC 如果照搬移动端单列布局，又会浪费横向空间。

📌 重点记忆：适配解决的是“不同 viewport 和交互方式下的可用性”，不是单纯缩放页面。

### 2. 🔥 viewport

**简要总结：**

- viewport 是浏览器可视区域
- 移动端必须正确设置 viewport
- `width=device-width` 让布局视口等于设备宽度
- `initial-scale=1.0` 设置初始缩放比例

**面试口语：**

移动端页面通常要设置 viewport，否则浏览器可能按默认宽布局视口渲染，再整体缩小，看起来字体和元素都会很小。

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0" />
```

**底层原理 / 背后逻辑：**

移动浏览器为了兼容早期 PC 网页，引入了布局视口和视觉视口的概念。如果不设置 viewport，页面可能按 980px 左右的布局视口排版，再缩放到手机屏幕里。设置 `width=device-width` 后，CSS 像素宽度和设备视口建立更合理的对应关系，响应式布局才有基础。

### 3. 🔥 响应式布局

**简要总结：**

- 使用百分比、flex、grid、媒体查询适配不同屏幕
- 常见断点：移动端、平板、桌面端
- 一套代码根据屏幕宽度展示不同布局
- 适合官网、中后台、内容页、多端通用页面

**面试口语：**

响应式布局的核心是让布局根据屏幕宽度自动变化。移动端可以单列展示，PC 端可以多列展示。实现上通常用 flex/grid 做弹性布局，用媒体查询处理关键断点。

```css
.list {
  display: grid;
  grid-template-columns: 1fr;
  gap: 12px;
}

@media (min-width: 768px) {
  .list {
    grid-template-columns: repeat(2, 1fr);
  }
}

@media (min-width: 1200px) {
  .list {
    grid-template-columns: repeat(4, 1fr);
  }
}
```

**底层原理 / 背后逻辑：**

响应式不是为每台设备写一份样式，而是根据布局临界点调整规则。断点应该来自内容什么时候放不下，而不是死背某个设备尺寸。比如卡片在 700px 以下一行放两个会挤，就在这个附近切成一列。

### 4. ⭐ rem / vw 移动端适配

**简要总结：**

- `rem` 基于根元素 `font-size`
- `vw` 基于 viewport 宽度
- 移动端常用 rem 或 vw 做等比缩放
- 适合视觉稿还原要求高的 H5 页面

**面试口语：**

移动端活动页经常用 rem 或 vw 做适配。rem 的思路是根据屏幕宽度动态设置根字体大小，页面元素用 rem 写，这样元素会跟着屏幕等比缩放。vw 则是直接按视口宽度计算尺寸。

```js
function setRootFontSize() {
  const designWidth = 375
  const width = document.documentElement.clientWidth
  document.documentElement.style.fontSize = `${(width / designWidth) * 16}px`
}

setRootFontSize()
window.addEventListener('resize', setRootFontSize)
```

```css
.button {
  width: 10rem;
  height: 2.75rem;
}
```

**底层原理 / 背后逻辑：**

rem 适配本质是改变单位换算比例。CSS 里写的 `1rem` 等于根元素字体大小，根字体越大，所有 rem 元素一起变大。vw 适配则把屏幕宽度分成 100 份，`1vw` 等于视口宽度的 1%。面试要说明：rem/vw 更适合强视觉还原的移动端，不一定适合复杂 PC 中后台。

### 5. ⭐ Flex 和 Grid 选择

**简要总结：**

- Flex 适合一维布局：横向或纵向排列
- Grid 适合二维布局：行和列一起控制
- 移动端常用 flex 做按钮、导航、表单排列
- PC 端复杂面板和卡片区更适合 grid

**面试口语：**

Flex 解决的是一条轴上的分布问题，Grid 解决的是二维网格问题。比如按钮组、左右布局用 Flex 很顺；仪表盘卡片、复杂面板区用 Grid 更清晰。

```css
.toolbar {
  display: flex;
  align-items: center;
  justify-content: space-between;
}

.dashboard {
  display: grid;
  grid-template-columns: 240px 1fr;
  gap: 16px;
}
```

### 6. 🔥 移动端 1px 问题

**简要总结：**

- 设备物理像素和 CSS 像素不是一回事
- 高清屏下 `1px` CSS 可能对应多个物理像素
- 视觉上边框可能显得更粗
- 常见方案：伪元素 + `transform: scaleY(0.5)`

**面试口语：**

移动端 1px 问题本质是 DPR 导致的。CSS 的 1px 是逻辑像素，在 DPR 为 2 或 3 的屏幕上会对应多个物理像素，所以边框看起来偏粗。

```css
.hairline {
  position: relative;
}

.hairline::after {
  position: absolute;
  left: 0;
  right: 0;
  bottom: 0;
  height: 1px;
  content: '';
  background: #ddd;
  transform: scaleY(0.5);
  transform-origin: bottom;
}
```

**底层原理 / 背后逻辑：**

DPR 表示一个 CSS 像素对应多少物理像素。视觉稿里的细线希望接近物理 1 像素，但 CSS `border: 1px` 在高 DPR 屏上可能更粗。伪元素缩放是让一个 CSS 像素的线在视觉上压到更细。

### 7. ⭐ 安全区域适配

**简要总结：**

- 刘海屏、底部手势条会占用安全区域
- iOS 可用 `env(safe-area-inset-*)`
- 底部固定按钮、吸底栏要特别注意

**面试口语：**

移动端底部固定按钮如果不处理安全区域，可能被 iPhone 底部手势条遮住。可以用 `safe-area-inset-bottom` 给底部留出空间。

```css
.bottom-bar {
  position: fixed;
  left: 0;
  right: 0;
  bottom: 0;
  padding-bottom: env(safe-area-inset-bottom);
}
```

### 8. 🔥 H5 和 PC 交互差异

**简要总结：**

- H5 主要是触摸交互，点击区域要足够大
- PC 有 hover、右键、快捷键、多列信息
- H5 避免过小按钮和复杂表格
- PC 可以提供更高信息密度和更强筛选能力

**面试口语：**

H5 适配不能只看宽度，还要看交互方式。移动端没有 hover，手指点击精度不如鼠标，所以按钮和输入区域要更大。PC 端可以利用 hover、表格、多列筛选提升效率。

**底层原理 / 背后逻辑：**

适配最终服务于操作效率。移动端屏幕小，用户常在弱网络和单手场景下操作，要减少层级和输入成本；PC 端屏幕大，用户更关注批量操作、对比和扫描效率，所以布局可以更密集。
