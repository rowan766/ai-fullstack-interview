# 前端基础 JS & TS

> 图标说明：⭐ 重点｜🔥 高频｜⚠️ 注意｜💡 提示｜📌 重点记忆

## JavaScript 基础

### 1. ⭐ 数据类型

**简要总结：**

- 基本类型：`String`、`Number`、`Boolean`、`Null`、`Undefined`、`Symbol`、`BigInt`
- 引用类型：`Object`、`Array`、`Function`、`Date`、`RegExp` 等
- 基本类型按值存储，引用类型按引用地址访问

**面试口语：**

JS 数据类型分为基本类型和引用类型。基本类型保存的是值本身，引用类型保存的是引用地址，所以对象或数组赋值后修改内部属性，可能会互相影响。

📌 重点记忆：`null` 用 `typeof` 判断会得到 `object`，这是 JS 历史遗留问题。

### 2. 🔥 类型判断与类型转换

**简要总结：**

- `typeof`：适合判断基本类型和函数
- `instanceof`：判断对象是否在某个构造函数的原型链上
- `Object.prototype.toString.call()`：判断类型最稳定
- `Array.isArray()`：专门判断数组
- `Number.isNaN()`：更准确判断 `NaN`

**面试口语：**

类型判断常用 `typeof`、`instanceof` 和 `Object.prototype.toString.call()`。其中 `typeof` 判断基本类型比较方便，但不能准确区分数组、对象和 `null`；更精确时一般用 `Object.prototype.toString.call()`。

```js
typeof 'abc' // 'string'
typeof null // 'object'
Array.isArray([]) // true
Object.prototype.toString.call([]) // '[object Array]'
```

⚠️ 注意：`isNaN('abc')` 会先隐式转换，结果是 `true`；`Number.isNaN('abc')` 不会转换，结果是 `false`。

### 3. ⭐ 运算符

**简要总结：**

- 算术：`+`、`-`、`*`、`/`、`%`、`**`
- 比较：`==`、`===`、`!=`、`!==`、`>`、`<`
- 逻辑：`&&`、`||`、`!`、`??`
- 可选链：`?.`
- 展开 / 剩余：`...`
- 三元：`condition ? a : b`

**面试口语：**

运算符里最常考的是 `==` 和 `===`。`==` 会做隐式类型转换，`===` 不会，所以开发中优先使用 `===`，减少类型转换带来的不确定性。

📌 重点记忆：`??` 只在左侧是 `null` 或 `undefined` 时取右侧，`||` 会把 `0`、`''`、`false` 也当成假值。

### 4. 🔥 变量声明

**简要总结：**

- `var`：函数作用域，可以重复声明，有变量提升
- `let`：块级作用域，可以重新赋值，不能重复声明
- `const`：块级作用域，不能重新赋值，不能重复声明

**面试口语：**

`var` 是函数作用域，会变量提升；`let` 和 `const` 是块级作用域，有暂时性死区。开发中一般优先用 `const`，需要重新赋值时再用 `let`。

⚠️ 注意：`const` 限制的是变量绑定不能改，不代表对象内容不能改。

```js
const user = { name: 'Tom' }
user.name = 'Jerry' // 可以
```

### 5. 🔥 作用域

**简要总结：**

- 全局作用域
- 函数作用域
- 块级作用域
- 词法作用域：作用域在代码定义时确定
- 作用域链：当前作用域找不到变量，就向外层查找

**面试口语：**

作用域决定变量能在哪里被访问。JS 是词法作用域，作用域在代码写好时就确定。变量查找时会先从当前作用域找，找不到就沿着外层作用域继续找，这条链就是作用域链。

📌 重点记忆：闭包能成立，核心就是内部函数保留了对外层词法作用域的引用。

### 6. 🔥 函数

**简要总结：**

- 函数声明：`function fn() {}`
- 函数表达式：`const fn = function() {}`
- 箭头函数：`const fn = () => {}`
- 常见能力：默认参数、剩余参数、回调函数、高阶函数、IIFE、闭包

**面试口语：**

函数是 JS 的一等公民，可以作为参数传递，也可以作为返回值。普通函数和箭头函数的核心区别在于 `this`，箭头函数没有自己的 `this`，会继承外层作用域的 `this`。

⚠️ 注意：函数声明会整体提升，函数表达式只会提升变量声明。

### 7. 🔥 对象

**简要总结：**

- 创建对象：`{}`、`new Object()`
- 访问属性：`obj.name`、`obj['name']`
- 遍历对象：`for...in`、`Object.keys()`、`Object.values()`、`Object.entries()`
- 常见知识点：`this`、解构、展开、原型链、深浅拷贝

**面试口语：**

对象是 JS 中非常核心的数据结构，属性可以动态增删改查。对象属性查找时，如果自身没有，会沿着原型链继续查找。

💡 提示：遍历对象自身可枚举属性时，优先用 `Object.keys()`、`Object.entries()`，比 `for...in` 更可控。

### 8. 🔥 数组

**简要总结：**

- 增删：`push`、`pop`、`shift`、`unshift`、`splice`
- 查找：`find`、`findIndex`、`includes`、`indexOf`
- 遍历：`forEach`、`map`、`filter`、`reduce`
- 截取：`slice`
- 排序：`sort`
- 判断：`Array.isArray()`

**面试口语：**

数组常考方法是 `map`、`filter`、`reduce`、`slice` 和 `splice`。`map` 返回新数组，`filter` 返回过滤后的新数组，`reduce` 可以做累计计算。

⚠️ 注意：`slice` 不改变原数组，`splice` 会改变原数组。

### 9. ⭐ 字符串

**简要总结：**

- 查找：`includes`、`indexOf`
- 截取：`slice`、`substring`
- 替换：`replace`、`replaceAll`
- 分割：`split`
- 去空格：`trim`
- 拼接：`+`、模板字符串

**面试口语：**

字符串是不可变类型，调用字符串方法通常会返回新字符串，不会直接修改原字符串。开发中拼接变量时推荐使用模板字符串。

📌 重点记忆：模板字符串使用反引号，可以写变量插值：`` `Hello ${name}` ``。

## JavaScript 核心原理

### 1. ⭐ 执行上下文

**简要总结：**

- JS 代码运行时会创建执行上下文
- 分为全局执行上下文、函数执行上下文、`eval` 执行上下文
- 执行上下文中保存变量环境、作用域链、`this`
- 函数调用会创建新的执行上下文并压入调用栈

**面试口语：**

执行上下文就是 JS 代码运行时创建的环境，里面保存当前变量、作用域链和 `this`。每次函数调用都会创建新的函数执行上下文，然后压入调用栈执行。

### 2. ⭐ 作用域链

**简要总结：**

- 当前作用域找不到变量，就去外层作用域找
- 一层一层向外查找，直到全局作用域
- 本质由词法作用域决定

**面试口语：**

作用域链就是 JS 查找变量的规则。当前作用域找不到变量时，会去父级作用域继续找，一直找到全局作用域。如果还找不到，就会报错。

### 3. 🔥 闭包

**简要总结：**

- 内部函数访问外部函数的变量
- 外部函数执行结束后，相关变量不会马上释放
- 常用于数据私有化、保存状态、函数柯里化
- 使用不当可能导致内存占用过多

**面试口语：**

闭包就是一个函数可以访问它外层作用域里的变量，而且外层函数执行结束后，这些变量还能继续被内部函数使用。常见用途是保存状态和做数据私有化。

```js
function createCounter() {
  let count = 0

  return function () {
    count++
    return count
  }
}

const counter = createCounter()
counter() // 1
counter() // 2
```

⚠️ 注意：闭包不是一定会造成内存泄漏，只有长期持有不再需要的引用时才可能产生问题。

### 4. 🔥 this

**简要总结：**

- `this` 表示函数执行时的上下文对象
- 普通函数：看调用方式
- 对象方法：通常指向调用该方法的对象
- `call`、`apply`、`bind` 可以手动改变 `this`
- 箭头函数没有自己的 `this`，继承外层 `this`

**面试口语：**

`this` 的指向主要看函数怎么调用。普通函数一般是谁调用就指向谁，`call`、`apply`、`bind` 可以修改它的指向。箭头函数没有自己的 `this`，会直接使用外层作用域的 `this`。

📌 重点记忆：箭头函数的 `this` 在定义时由外层作用域决定，不是调用时决定。

### 5. 🔥 原型与原型链

**简要总结：**

- 每个对象都有原型
- 函数有 `prototype` 属性
- 对象找不到属性时，会去原型上找
- 原型再找不到，就继续向上找，直到 `null`

**面试口语：**

原型是 JS 实现继承的一种机制。对象访问属性时，如果自己没有，就会去原型对象上找，再找不到就继续往上找，直到 `null`，这个查找过程就是原型链。

### 6. ⭐ 继承

**简要总结：**

- JS 继承本质基于原型链
- 子对象可以复用父对象的属性和方法
- ES6 常用 `class` 和 `extends`
- `class` 本质仍然是原型机制的语法糖

**面试口语：**

JavaScript 的继承本质上是通过原型链实现的。ES6 之后一般用 `class` 和 `extends` 来写，但底层还是基于原型和原型链。

### 7. 🔥 new

**简要总结：**

- 创建一个新对象
- 将新对象的原型指向构造函数的 `prototype`
- 构造函数内部的 `this` 指向新对象
- 执行构造函数
- 如果构造函数返回对象，则返回该对象；否则返回新对象

**面试口语：**

`new` 的过程是先创建一个新对象，把它的原型指向构造函数的 `prototype`，然后让构造函数里的 `this` 指向这个新对象并执行，最后根据返回值决定返回结果。

### 8. 🔥 call / apply / bind

**简要总结：**

- 都可以改变函数的 `this`
- `call`：立即执行，参数一个个传
- `apply`：立即执行，参数用数组传
- `bind`：不立即执行，返回一个新函数

**面试口语：**

`call`、`apply`、`bind` 都是用来改变 `this` 指向的。`call` 和 `apply` 会立即执行，区别是传参方式不同；`bind` 不会马上执行，而是返回一个绑定好 `this` 的新函数。

### 9. 🔥 深拷贝 / 浅拷贝

**简要总结：**

- 浅拷贝：只复制第一层，嵌套对象仍然共享引用
- 深拷贝：嵌套对象也会复制，互不影响
- 浅拷贝常用：`Object.assign()`、展开运算符
- 深拷贝常用：`structuredClone()`、递归、第三方库

**面试口语：**

浅拷贝只复制第一层，里面如果还有对象，还是指向同一个地址；深拷贝会把嵌套对象也复制一份，所以修改新对象不会影响原对象。

```js
function deepClone(value, map = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value
  if (map.has(value)) return map.get(value)

  const result = Array.isArray(value) ? [] : {}
  map.set(value, result)

  Reflect.ownKeys(value).forEach((key) => {
    result[key] = deepClone(value[key], map)
  })

  return result
}
```

⚠️ 注意：`JSON.parse(JSON.stringify(obj))` 会丢失 `undefined`、函数、`Symbol`，也不能处理循环引用。

### 10. 🔥 Promise

**简要总结：**

- 用来处理异步操作
- 三种状态：`pending`、`fulfilled`、`rejected`
- 状态一旦改变就不能再变
- `then` 处理成功
- `catch` 处理失败
- `finally` 做收尾
- 支持链式调用

**面试口语：**

`Promise` 是 JS 处理异步的一种方式，有等待、成功、失败三种状态，而且状态一旦改变就不会再变。成功用 `then`，失败用 `catch`，它还支持链式调用，可以减少回调嵌套。

### 11. 🔥 async / await

**简要总结：**

- 是 `Promise` 的语法糖
- `async` 函数默认返回 `Promise`
- `await` 等待 `Promise` 的结果
- 写法更像同步代码
- 异常一般用 `try...catch`

**面试口语：**

`async/await` 本质上是 `Promise` 的语法糖，让异步代码写起来更像同步代码。`async` 函数会返回一个 `Promise`，`await` 用来等待它的结果，异常一般配合 `try...catch` 处理。

```js
async function getUser() {
  try {
    const response = await fetch('/api/user')
    const data = await response.json()
    console.log(data)
  } catch (error) {
    console.error('请求失败：', error)
  }
}
```

### 12. 🔥 Event Loop

**简要总结：**

- JS 是单线程
- 同步代码先进入调用栈执行
- 异步任务完成后进入任务队列
- 当前宏任务结束后，会先清空微任务队列
- 微任务清空后，再执行下一个宏任务

**面试口语：**

Event Loop 是 JavaScript 处理异步任务的机制。同步代码先执行，执行完以后会先清空微任务队列，再执行一个宏任务，然后不断重复这个过程。

📌 重点记忆：一次事件循环中，常见顺序是同步代码 → 微任务 → 下一个宏任务。

### 13. 🔥 宏任务 / 微任务

**简要总结：**

- 宏任务：`setTimeout`、`setInterval`、I/O、UI 渲染、事件回调
- 微任务：`Promise.then`、`catch`、`finally`、`queueMicrotask`、`MutationObserver`
- 同一轮事件循环里，微任务优先于下一个宏任务执行

**面试口语：**

宏任务和微任务都是异步任务队列。像 `setTimeout` 属于宏任务，`Promise.then` 属于微任务。当前同步代码执行完后，会先把微任务清空，再去执行下一个宏任务。

### 14. ⭐ 定时器

**简要总结：**

- `setTimeout`：延迟执行一次
- `setInterval`：按间隔重复执行
- `clearTimeout`：取消延迟任务
- `clearInterval`：取消循环任务
- 定时器回调属于宏任务

**面试口语：**

定时器到时间后不会立刻执行，而是进入宏任务队列，等调用栈清空并且微任务执行完后才有机会执行。所以设置的时间是最小延迟时间，不代表精确执行时间。

### 15. ⭐ 异步并发控制

**简要总结：**

- 控制同时执行的异步任务数量
- 避免一次性发起过多请求
- 常见实现：任务队列 + 固定数量 worker
- `Promise.all` 是全部并发，不限制数量

**面试口语：**

异步并发控制就是限制同一时间执行的异步任务数量。比如有 100 个请求，不一次全部发出去，而是限制同时只执行 5 个，完成一个再补一个。

```js
async function limitRequest(tasks, limit = 3) {
  const queue = [...tasks]

  async function worker() {
    while (queue.length) {
      const task = queue.shift()
      await task()
    }
  }

  const workers = Array.from({ length: limit }, () => worker())
  await Promise.all(workers)
}
```

### 16. ⭐ Promise 错误处理

**简要总结：**

- `catch()` 捕获错误
- `then` 第二个参数也能处理错误
- `finally()` 无论成功失败都会执行
- `async/await` 通常配合 `try...catch`

**面试口语：**

Promise 的错误一般用 `catch` 统一处理，`finally` 做一些收尾操作。如果用 `async/await`，通常配合 `try...catch` 来捕获异常。

```js
fetch('/api/user')
  .then((res) => res.json())
  .catch((err) => {
    console.error(err)
  })
  .finally(() => {
    console.log('请求结束')
  })
```

## ES6+

### 1. 🔥 let / const

**简要总结：**

- 都是块级作用域
- 都不能重复声明
- 都有暂时性死区
- `let` 可以重新赋值
- `const` 不能重新赋值

**面试口语：**

`let` 和 `const` 都是 ES6 新增的块级作用域变量声明。区别主要是 `let` 可以重新赋值，`const` 不可以。实际开发里一般优先用 `const`，需要重新赋值时再用 `let`。

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000)
}
// 0 1 2

for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 1000)
}
// 3 3 3
```

### 2. ⭐ 解构

**简要总结：**

- 从数组或对象中快速取值
- 数组按位置解构
- 对象按属性名解构
- 支持默认值、重命名、嵌套解构

**面试口语：**

解构就是从数组或对象里快速把值取出来。数组按位置取，对象按属性名取，还可以设置默认值和重命名。

```js
const [a, b] = [1, 2]
const { name, age: userAge = 18 } = user
```

### 3. ⭐ 展开运算符

**简要总结：**

- 展开数组或对象
- 常用于复制、合并
- 可以做函数传参
- 对对象和数组的复制属于浅拷贝

**面试口语：**

展开运算符就是把数组或对象展开。实际开发里常用来复制、合并数据，或者做函数传参。需要注意的是，用 `...` 复制对象或数组只是浅拷贝。

### 4. 🔥 箭头函数

**简要总结：**

- 写法更简洁
- 没有自己的 `this`
- 没有 `arguments`
- 不能作为构造函数，不能 `new`
- 不能作为生成器函数

**面试口语：**

箭头函数主要让函数写法更简洁。它和普通函数最大的区别是没有自己的 `this`，会继承外层作用域的 `this`，而且不能用 `new` 调用。

### 5. ⭐ 模板字符串

**简要总结：**

- 使用反引号定义字符串
- 支持变量插值：`${value}`
- 支持多行字符串
- 可读性比字符串拼接更好

**面试口语：**

模板字符串是 ES6 新增的字符串写法，可以直接在字符串中插入变量，也可以写多行字符串，实际开发中比 `+` 拼接更清晰。

```js
const name = 'Tom'
const str = `Hello ${name}`
```

### 6. ⭐ Symbol

**简要总结：**

- ES6 新增的基本数据类型
- 每个 `Symbol` 都是唯一的
- 常用来做对象的唯一属性名
- 可以避免属性名冲突

**面试口语：**

`Symbol` 是 ES6 新增的基本类型，特点是每个值都是唯一的。实际开发里常用它作为对象属性名，避免和其他属性发生命名冲突。

### 7. 🔥 Set / Map

**简要总结：**

- `Set`：存储唯一值，常用于数组去重
- `Map`：键值对结构，键可以是任意类型
- `WeakSet`：成员只能是对象，弱引用
- `WeakMap`：键只能是对象，弱引用

**面试口语：**

`Set` 主要用来存不重复的数据，常见场景是数组去重。`Map` 和对象类似，也是存键值对，但它的 key 可以是任意类型，比如对象也可以作为 key。

```js
const unique = [...new Set([1, 1, 2])]

const map = new Map()
map.set({ id: 1 }, 'user')
```

### 8. ⭐ Proxy / Reflect

**简要总结：**

- `Proxy`：代理对象，可以拦截读取、修改、删除等操作
- `Reflect`：提供对象操作的标准方法
- 二者经常配合使用
- Vue3 响应式底层基于 `Proxy`

**面试口语：**

`Proxy` 就是给对象加一层代理，可以拦截属性读取、修改、删除这些操作。`Reflect` 提供对应的标准对象操作方法，通常和 `Proxy` 一起用。

```js
const user = { name: 'Tom' }

const proxy = new Proxy(user, {
  get(target, key, receiver) {
    return Reflect.get(target, key, receiver)
  },
  set(target, key, value, receiver) {
    return Reflect.set(target, key, value, receiver)
  }
})
```

### 9. 💡 Generator

**简要总结：**

- 用 `function*` 定义
- 用 `yield` 暂停执行
- 用 `next()` 继续执行
- 每次 `next()` 返回 `{ value, done }`
- 常用于迭代器、异步流程控制

**面试口语：**

Generator 是一种可以暂停和继续执行的函数。用 `function*` 定义，`yield` 暂停，`next()` 继续执行。它常用来实现迭代器，早期也会用来处理异步流程。

### 10. 💡 Iterator

**简要总结：**

- Iterator 是迭代器
- 用来按顺序访问数据
- 核心方法是 `next()`
- `next()` 返回 `{ value, done }`
- `Array`、`Set`、`Map` 默认都支持迭代

**面试口语：**

Iterator 是一套遍历数据的标准机制，核心就是不断调用 `next()` 获取下一个值。像数组、Set、Map 都默认实现了 Iterator，所以可以直接用 `for...of` 遍历。

### 11. ⭐ ES Module

**简要总结：**

- ES6 官方模块化方案
- `export` 导出
- `import` 导入
- 支持默认导出和按需导出
- 一个文件可以看成一个独立模块

**面试口语：**

ES Module 是 ES6 官方的模块化规范，主要通过 `export` 导出、`import` 导入。它支持默认导出和按需导出，现在前端项目基本都使用这种模块化方式。

```js
// user.js
export const name = 'Tom'
export default function getUser() {}

// main.js
import getUser, { name } from './user.js'
```

## 浏览器中的 JavaScript

### 1. 🔥 DOM 操作

**简要总结：**

- 查找元素：`getElementById`、`querySelector`
- 修改内容：`innerHTML`、`textContent`
- 修改属性：`setAttribute`
- 修改样式：`style`、`classList`
- 创建元素：`createElement`
- 添加元素：`appendChild`
- 删除元素：`remove`
- 绑定事件：`addEventListener`

**面试口语：**

DOM 操作就是通过 JavaScript 查找、修改、创建、删除页面元素，也可以给元素绑定事件。实际开发里常用 `querySelector`、`classList` 和 `addEventListener`。

⚠️ 注意：频繁操作 DOM 可能影响性能，能批量处理时尽量减少多次读写布局。

### 2. ⭐ BOM

**简要总结：**

- BOM 是浏览器对象模型
- 核心对象是 `window`
- 常见对象：`location`、`history`、`navigator`、`screen`
- `setTimeout`、`setInterval` 也属于 `window`

**面试口语：**

BOM 主要用来操作浏览器本身，比如地址栏、历史记录、浏览器信息这些。核心对象是 `window`，像 `location`、`history`、`navigator` 都属于 BOM。

### 3. 🔥 事件机制

**简要总结：**

- 事件流程：捕获阶段 → 目标阶段 → 冒泡阶段
- 默认大多数事件处理发生在冒泡阶段
- `addEventListener(type, handler, true)` 可以在捕获阶段监听
- `stopPropagation()` 阻止传播
- `preventDefault()` 阻止默认行为

**面试口语：**

浏览器事件机制主要分为捕获、目标、冒泡三个阶段。实际开发里一般用 `addEventListener` 绑定事件，大多数情况下都是在冒泡阶段处理。

### 4. 🔥 事件冒泡 / 捕获

**简要总结：**

- 捕获：从外层元素向目标元素传递
- 冒泡：从目标元素向外层元素传递
- 默认更常用冒泡
- `stopPropagation()` 可以阻止事件继续传播

**面试口语：**

事件捕获是从父元素往目标元素传，事件冒泡正好相反，是从目标元素一层层往父元素传。实际开发里更常用冒泡。

### 5. 🔥 事件委托

**简要总结：**

- 利用事件冒泡
- 把多个子元素事件统一绑定到父元素
- 减少事件绑定数量
- 动态新增的子元素也能生效

**面试口语：**

事件委托就是利用事件冒泡，把多个子元素的事件统一绑定到父元素上。这样能减少事件监听数量，而且后面动态新增的子元素也不需要重新绑定事件。

```js
list.addEventListener('click', (event) => {
  if (event.target.matches('li')) {
    console.log(event.target.textContent)
  }
})
```

### 6. 🔥 localStorage / sessionStorage / Cookie

**简要总结：**

- `localStorage`：长期保存，除非手动删除
- `sessionStorage`：当前页面会话有效，关闭页面后清除
- `Cookie`：容量小，会随 HTTP 请求发送给服务器
- `localStorage` 和 `sessionStorage` 不会自动随请求发送

**面试口语：**

`localStorage` 适合长期保存数据，`sessionStorage` 只在当前会话里有效，关闭页面就没了。`Cookie` 容量比较小，但会自动跟着请求发给服务器，所以常用于登录态、服务端识别等场景。

⚠️ 注意：敏感信息不要直接放在 `localStorage`，容易受到 XSS 影响。

### 7. 🔥 Ajax / Fetch

**简要总结：**

- Ajax 是一种不刷新页面也能请求数据的技术思想
- 早期常用 `XMLHttpRequest`
- 现代项目更常用 `fetch` 或 `axios`
- `fetch` 默认只在网络错误时 reject，HTTP 404/500 不会自动 reject

**面试口语：**

Ajax 的核心是不刷新页面就和服务端交换数据。现在原生通常用 `fetch`，它返回 `Promise`，写法更简洁。不过要注意，`fetch` 遇到 404 或 500 时不会自动进入 `catch`，需要自己判断 `response.ok`。

```js
async function request() {
  const response = await fetch('/api/user')

  if (!response.ok) {
    throw new Error('请求失败')
  }

  return response.json()
}
```

### 8. 🔥 跨域 CORS

**简要总结：**

- 跨域是浏览器同源策略限制导致的
- 同源要求协议、域名、端口都相同
- CORS 是服务端通过响应头允许跨域
- 常见响应头：`Access-Control-Allow-Origin`
- 复杂请求会先发送预检请求 `OPTIONS`

**面试口语：**

跨域本质是浏览器同源策略的限制，不是服务器不能收到请求。常见解决方式是 CORS，由服务端返回允许跨域的响应头。复杂请求会先发一次 `OPTIONS` 预检请求。

📌 重点记忆：CORS 需要服务端配置，前端不能单方面彻底解决跨域。

### 9. 💡 JSONP

**简要总结：**

- 利用 `script` 标签不受同源策略限制
- 只支持 `GET` 请求
- 服务端返回一段函数调用代码
- 安全性和灵活性较差，现在较少使用

**面试口语：**

JSONP 是早期解决跨域的一种方式，利用 `script` 标签可以跨域加载资源的特点。它只能发 `GET` 请求，而且需要服务端配合返回函数调用，现在更多使用 CORS。

### 10. ⭐ 页面生命周期 / 页面加载过程

**简要总结：**

- 解析 HTML，构建 DOM 树
- 解析 CSS，构建 CSSOM 树
- DOM 和 CSSOM 合成渲染树
- 布局：计算元素位置和大小
- 绘制：把元素画到页面上
- 执行 JS 可能阻塞 DOM 解析

**面试口语：**

页面加载时，浏览器会先解析 HTML 生成 DOM，同时解析 CSS 生成 CSSOM，然后合成渲染树，经过布局和绘制显示出来。JS 如果没有异步加载，可能会阻塞 DOM 解析。

💡 提示：`DOMContentLoaded` 表示 DOM 解析完成，`load` 表示页面资源基本加载完成。

### 11. 💡 Web Worker

**简要总结：**

- 可以在后台线程执行 JS
- 不会阻塞主线程 UI
- 通过 `postMessage` 和主线程通信
- 不能直接操作 DOM
- 适合大计算、文件处理等场景

**面试口语：**

Web Worker 可以把耗时任务放到后台线程执行，避免阻塞页面渲染。它和主线程之间通过消息通信，但不能直接操作 DOM。

### 12. 🔥 浏览器缓存

**简要总结：**

- 强缓存：不向服务器发请求，直接用本地缓存
- 协商缓存：向服务器确认资源是否变化
- 强缓存相关头：`Cache-Control`、`Expires`
- 协商缓存相关头：`ETag`、`Last-Modified`

**面试口语：**

浏览器缓存分为强缓存和协商缓存。强缓存命中时不会请求服务器；强缓存失效后会走协商缓存，由服务器判断资源是否变化，没变化就返回 `304`。

📌 重点记忆：`Cache-Control` 优先级高于 `Expires`，`ETag` 精度通常高于 `Last-Modified`。

### 13. 🔥 重绘 / 回流

**简要总结：**

- 回流：元素尺寸、位置、布局变化，需要重新计算布局
- 重绘：颜色、背景等视觉变化，不影响布局
- 回流一定会触发重绘
- 重绘不一定触发回流

**面试口语：**

回流是布局发生变化，需要重新计算元素位置和大小；重绘是样式外观变化但布局不变。回流成本通常更高，所以要尽量减少频繁修改布局。

💡 提示：批量修改 class、使用 `transform` 做动画，通常比频繁修改 `top`、`left` 更好。

### 14. 🔥 防抖 / 节流

**简要总结：**

- 防抖：连续触发时，只在最后一次触发后执行
- 节流：一段时间内最多执行一次
- 防抖适合搜索输入、窗口 resize 结束后处理
- 节流适合滚动监听、拖拽、按钮连续点击限制

**面试口语：**

防抖是等用户停止触发一段时间后再执行，节流是固定时间内最多执行一次。简单说，防抖重在最后一次，节流重在固定频率。

## TypeScript 基础与高级类型

### 1. 🔥 基础类型

**简要总结：**

- 原始类型：`string`、`number`、`boolean`、`null`、`undefined`、`symbol`、`bigint`
- 数组：`number[]`、`Array<number>`
- 元组：`[string, number]`
- 任意类型：`any`
- 未知类型：`unknown`
- 空值：`void`
- 永不存在：`never`

**面试口语：**

TypeScript 是给 JavaScript 加类型系统。基础类型和 JS 类型基本对应，常见还包括数组、元组、`any`、`unknown`、`void`、`never`。实际开发中尽量少用 `any`，不确定类型优先用 `unknown`。

⚠️ 注意：`any` 会绕过类型检查，`unknown` 使用前必须先做类型收窄。

### 2. 🔥 interface

**简要总结：**

- 常用于描述对象结构
- 可以被 `extends` 继承
- 可以重复声明并自动合并
- 适合定义对象、类、组件 props

**面试口语：**

`interface` 主要用来描述对象结构，支持继承和声明合并。项目里定义对象形状、接口返回值、组件 props 时很常用。

```ts
interface User {
  id: number
  name: string
}
```

### 3. 🔥 type

**简要总结：**

- 可以给任意类型起别名
- 可以定义联合类型、交叉类型、函数类型
- 不能重复声明同名类型
- 表达能力更灵活

**面试口语：**

`type` 是类型别名，可以给对象、联合类型、函数类型等起名字。相比 `interface`，它表达能力更灵活，但不能像 `interface` 那样重复声明合并。

```ts
type Status = 'pending' | 'success' | 'error'
type Handler = (value: string) => void
```

### 4. 🔥 泛型

**简要总结：**

- 泛型可以让类型像参数一样传入
- 在保证类型安全的同时提高复用性
- 常用于函数、接口、组件、API 返回值

**面试口语：**

泛型就是把类型当成参数传进去。它可以让函数或组件在复用的同时保留准确类型，不需要写死某一种类型。

```ts
function identity<T>(value: T): T {
  return value
}
```

📌 重点记忆：泛型解决的是“复用逻辑，但保留类型信息”的问题。

### 5. ⭐ 联合类型

**简要总结：**

- 使用 `|` 表示多个类型中的一个
- 常用于状态、枚举值、接口差异字段
- 使用前通常需要类型收窄

**面试口语：**

联合类型表示一个值可以是多种类型之一，比如状态只能是几个字符串之一。使用联合类型时，通常需要通过判断来缩小具体类型。

```ts
type ID = string | number
```

### 6. ⭐ 交叉类型

**简要总结：**

- 使用 `&` 合并多个类型
- 最终类型需要同时满足多个类型
- 常用于组合对象能力

**面试口语：**

交叉类型表示同时拥有多个类型的能力，经常用来把多个对象类型组合成一个新类型。

```ts
type UserWithRole = User & { role: string }
```

### 7. ⭐ 类型断言

**简要总结：**

- 告诉 TS “我知道这个值是什么类型”
- 常用写法：`value as Type`
- 只是编译期提示，不会改变运行时数据

**面试口语：**

类型断言是开发者告诉 TypeScript 某个值的具体类型。它不会做运行时转换，只是影响编译期类型检查，所以不能滥用。

⚠️ 注意：类型断言不是类型转换。

### 8. 🔥 keyof

**简要总结：**

- 获取对象类型所有 key 的联合类型
- 常和泛型一起使用
- 可以约束访问对象属性时的 key 必须合法

**面试口语：**

`keyof` 可以拿到对象类型所有属性名组成的联合类型，常和泛型配合，用来保证访问对象属性时 key 是存在的。

```ts
function getValue<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key]
}
```

### 9. ⭐ typeof

**简要总结：**

- JS 中 `typeof` 用于运行时类型判断
- TS 中 `typeof` 可以基于变量反推出类型
- 常用于从配置对象、常量对象中提取类型

**面试口语：**

TypeScript 里的 `typeof` 可以根据已有变量推导出它的类型，常用于根据常量对象生成类型，避免重复写一份类型定义。

```ts
const config = { theme: 'dark', size: 12 }
type Config = typeof config
```

### 10. ⭐ in

**简要总结：**

- JS 中 `in` 判断属性是否存在
- TS 中 `in` 常用于映射类型
- 可以遍历联合类型中的每一项

**面试口语：**

`in` 在 TS 类型里常用于映射类型，相当于遍历一组 key，然后生成新的对象类型。

```ts
type ReadonlyUser = {
  readonly [K in keyof User]: User[K]
}
```

### 11. 💡 infer

**简要总结：**

- `infer` 用于条件类型中推断类型
- 常用于提取函数返回值、Promise 内部类型、数组元素类型
- 必须配合 `extends` 使用

**面试口语：**

`infer` 可以在条件类型里临时声明一个要推断的类型变量。比如从函数类型中推断返回值，或从 `Promise<T>` 中推断出 `T`。

```ts
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never
```

### 12. ⭐ extends

**简要总结：**

- 在接口中表示继承
- 在泛型中表示约束
- 在条件类型中表示类型判断

**面试口语：**

`extends` 在 TS 里有几种常见用法：接口继承、泛型约束、条件类型判断。比如 `K extends keyof T` 就是约束 `K` 必须是 `T` 的 key。

### 13. 💡 条件类型

**简要总结：**

- 语法：`T extends U ? X : Y`
- 根据类型关系返回不同类型
- 常和泛型、`infer` 配合使用

**面试口语：**

条件类型就像类型系统里的三元表达式，根据一个类型是否满足另一个类型来返回不同结果。

### 14. 💡 映射类型

**简要总结：**

- 基于已有类型生成新类型
- 常和 `keyof`、`in` 配合
- 可以批量添加 `readonly`、`?` 等修饰符

**面试口语：**

映射类型可以遍历一个对象类型的 key，然后生成新类型。TS 内置的 `Partial`、`Readonly` 这些工具类型底层都用到了映射类型。

### 15. 🔥 工具类型

**简要总结：**

- `Partial<T>`：所有属性变可选
- `Required<T>`：所有属性变必选
- `Readonly<T>`：所有属性只读
- `Pick<T, K>`：挑选部分属性
- `Omit<T, K>`：排除部分属性
- `Record<K, T>`：构造键值对象类型
- `ReturnType<T>`：获取函数返回值类型
- `Parameters<T>`：获取函数参数类型

**面试口语：**

工具类型是 TS 内置的一些类型处理工具，可以基于已有类型快速生成新类型。实际开发中 `Partial`、`Pick`、`Omit`、`Record` 非常常用。

## TypeScript 工程实践

### 1. 🔥 interface 和 type 选择

**简要总结：**

- 定义对象结构，优先考虑 `interface`
- 定义联合类型、函数类型、工具组合，优先用 `type`
- 需要声明合并时用 `interface`
- 两者都能满足时，团队统一规范更重要

**面试口语：**

我一般会用 `interface` 描述对象结构，比如接口返回值和组件 props；用 `type` 描述联合类型、函数类型和复杂类型组合。真实项目里更重要的是团队保持统一风格。

### 2. ⭐ enum

**简要总结：**

- `enum` 用来定义枚举值
- 数字枚举会产生反向映射
- 字符串枚举可读性更好
- 也可以用字面量联合类型替代

**面试口语：**

`enum` 可以定义一组固定值，比如状态码或角色。现在很多项目也会用字面量联合类型替代枚举，因为它更轻量，编译后不会额外生成对象。

```ts
type Status = 'pending' | 'success' | 'error'
```

### 3. ⭐ tsconfig

**简要总结：**

- `tsconfig.json` 是 TypeScript 项目配置文件
- `strict` 开启严格类型检查
- `target` 指定编译后的 JS 版本
- `module` 指定模块规范
- `paths` 配置路径别名

**面试口语：**

`tsconfig` 用来配置 TS 编译规则。比较重要的是 `strict`、`target`、`module`、`baseUrl`、`paths`。实际项目建议开启 `strict`，类型安全更好。

### 4. ⭐ 声明文件

**简要总结：**

- 声明文件后缀是 `.d.ts`
- 用来描述已有 JS 代码的类型
- 可以声明全局变量、模块、第三方库类型
- 不包含具体实现

**面试口语：**

声明文件就是给没有类型的 JS 代码补类型说明。比如第三方库没有类型定义时，可以写 `.d.ts` 告诉 TS 这个模块有哪些 API。

### 5. ⭐ 第三方库类型

**简要总结：**

- 优先使用库自带类型
- 没有自带类型时查找 `@types/xxx`
- 仍然没有时可以自己写 `.d.ts`
- 不建议长期用 `any` 顶掉

**面试口语：**

接入第三方库时，我会先看库是否自带类型；如果没有，再安装 `@types` 包；如果还没有，就自己补声明文件，尽量不要用 `any` 把类型检查绕开。

### 6. 💡 类型体操

**简要总结：**

- 利用条件类型、映射类型、递归类型等做类型计算
- 常见题：实现 `Pick`、`Omit`、`Readonly`、`Awaited`
- 能提升类型理解，但业务项目里要控制复杂度

**面试口语：**

类型体操就是在 TS 类型系统里做类型计算。它能帮助我们写出更准确的工具类型，但真实业务里要避免过度复杂，否则维护成本会很高。

### 7. ⭐ React / Vue 中的 TS

**简要总结：**

- React 常见：组件 props、事件类型、hooks 返回值
- Vue 常见：`defineProps`、`defineEmits`、`ref`、`computed`
- API 数据类型要提前定义
- 组件对外暴露的 props 和 emits 要明确

**面试口语：**

在 React 或 Vue 中用 TS，重点是把组件 props、事件、状态、接口返回值这些边界定义清楚。这样组件使用方能得到更好的提示，也能减少字段拼错和类型不匹配的问题。

### 8. 🔥 API 类型设计

**简要总结：**

- 请求参数和响应数据都要定义类型
- 列表接口通常包含 `list`、`total`、分页参数

**面试口语：**

API 类型设计时，我会把请求参数、响应数据和公共响应结构分开定义。比如 `ApiResponse<T>` 表示通用响应，具体接口只需要传入自己的数据类型。

```ts
interface ApiResponse<T> {
```

### 9. ⭐ 泛型组件

**简要总结：**

**面试口语：**

泛型组件适合数据结构不固定但逻辑可复用的场景，比如表格组件。通过泛型把每一行的数据类型传进去，组件内部访问字段时就能保持类型安全。

### 10. 🔥 类型安全

**简要总结：**

**面试口语：**

类型安全不是把所有地方都写得很复杂，而是在关键边界把类型定义清楚，比如 API、组件 props、状态数据。这样能提前发现很多运行时问题。

## 手写与场景题

### 1. 🔥 手写 Promise

**考点总结：**

- 三种状态：`pending`、`fulfilled`、`rejected`
- 状态只能改变一次
- `then` 支持异步回调
- 支持链式调用

**面试口语：**

手写 Promise 的核心是维护状态和值，`resolve` 时执行成功回调，`reject` 时执行失败回调。更完整的实现还要处理链式调用和 thenable。

📌 重点记忆：面试中先讲清状态机，再写简化版实现，不要一上来硬背完整规范。

```js
const PENDING = 'pending'
const FULFILLED = 'fulfilled'
const REJECTED = 'rejected'

class MyPromise {
  constructor(executor) {
    this.status = PENDING
    this.value = null
    this.reason = null
    this.onFulfilledCallbacks = []
    this.onRejectedCallbacks = []

    const resolve = (value) => {
      if (this.status !== PENDING) return

      this.status = FULFILLED
      this.value = value
      this.onFulfilledCallbacks.forEach((fn) => fn())
    }

    const reject = (reason) => {
      if (this.status !== PENDING) return

      this.status = REJECTED
      this.reason = reason
      this.onRejectedCallbacks.forEach((fn) => fn())
    }

    try {
      executor(resolve, reject)
    } catch (error) {
      reject(error)
    }
  }

  then(onFulfilled, onRejected) {
    onFulfilled = typeof onFulfilled === 'function' ? onFulfilled : (value) => value
    onRejected = typeof onRejected === 'function' ? onRejected : (reason) => { throw reason }

    return new MyPromise((resolve, reject) => {
      if (this.status === FULFILLED) {
        queueMicrotask(() => {
          try {
            resolve(onFulfilled(this.value))
          } catch (error) {
            reject(error)
          }
        })
      } else if (this.status === REJECTED) {
        queueMicrotask(() => {
          try {
            resolve(onRejected(this.reason))
          } catch (error) {
            reject(error)
          }
        })
      } else {
        this.onFulfilledCallbacks.push(() => {
          queueMicrotask(() => {
            try {
              resolve(onFulfilled(this.value))
            } catch (error) {
              reject(error)
            }
          })
        })

        this.onRejectedCallbacks.push(() => {
          queueMicrotask(() => {
            try {
              resolve(onRejected(this.reason))
            } catch (error) {
              reject(error)
            }
          })
        })
      }
    })
  }

  catch(onRejected) {
    return this.then(null, onRejected)
  }
}
```

⚠️ 注意：这是面试简版，重点展示状态流转、回调收集、异步执行和基础链式调用；完整 Promise/A+ 规范还需要处理 thenable 解析、循环引用等更多细节。

### 2. 🔥 手写 debounce / throttle

**debounce：**

```js
function debounce(fn, delay) {
  let timer = null

  return function (...args) {
    clearTimeout(timer)
    timer = setTimeout(() => {
      fn.apply(this, args)
    }, delay)
  }
}
```

**throttle：**

```js
function throttle(fn, delay) {
  let lastTime = 0

  return function (...args) {
    const now = Date.now()

    if (now - lastTime >= delay) {
      lastTime = now
      fn.apply(this, args)
    }
  }
}
```

### 3. 🔥 手写 deepClone

**考点总结：**

- 递归复制嵌套对象
- 处理数组和对象
- 用 `WeakMap` 解决循环引用
- 真实项目优先考虑 `structuredClone`

```js
function deepClone(value, map = new WeakMap()) {
  if (value === null || typeof value !== 'object') return value
  if (map.has(value)) return map.get(value)

  const result = Array.isArray(value) ? [] : {}
  map.set(value, result)

  Reflect.ownKeys(value).forEach((key) => {
    result[key] = deepClone(value[key], map)
  })

  return result
}
```

```js
Function.prototype.myBind = function (context, ...presetArgs) {
```

### 5. 🔥 手写 new

**考点总结：**

- 创建新对象
- 关联原型
- 绑定 `this` 执行构造函数
- 根据构造函数返回值决定最终结果

```js
function myNew(Constructor, ...args) {
  const obj = Object.create(Constructor.prototype)

  return result !== null && typeof result === 'object' ? result : obj
}
```

### 7. 🔥 并发请求控制

**考点总结：**

- 维护任务队列
- 固定并发数量
- 完成一个任务后补下一个
- 最后等待所有 worker 完成

```js
async function limitRequest(tasks, limit) {
  const queue = [...tasks]

  async function worker() {
    while (queue.length) {
      const task = queue.shift()
      await task()
    }
  }

  await Promise.all(Array.from({ length: limit }, worker))
}
```

### 8. ⭐ 实现 EventEmitter

**考点总结：**

- `on`：订阅事件
- `emit`：触发事件
- `off`：取消订阅
- `once`：只执行一次

```js
class EventEmitter {
  constructor() {
    this.events = new Map()
  }

  on(type, handler) {
    const handlers = this.events.get(type) || []
    handlers.push(handler)
    this.events.set(type, handlers)
  }

  off(type, handler) {
    const handlers = this.events.get(type) || []
    this.events.set(
      type,
      handlers.filter((item) => item !== handler)
    )
  }

  emit(type, ...args) {
    const handlers = this.events.get(type) || []
    handlers.forEach((handler) => handler(...args))
  }

  once(type, handler) {
    const onceHandler = (...args) => {
      handler(...args)
      this.off(type, onceHandler)
    }

    this.on(type, onceHandler)
  }
}
```
