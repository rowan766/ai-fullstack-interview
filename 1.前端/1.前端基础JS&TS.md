3. 运算符

   - 算术：`+ - * / % ** ++ --`
   - 赋值：`= += -= *= /=`
   - 比较：`== === != !== > < >= <=`
   - 逻辑：`&& || ! ??`
   - 三元：`条件 ? A : B`

   - 其他：`typeof`、`delete`、`in`、`instanceof`

   ⭐ 面试重点：`var` 是函数作用域，`let/const` 是块级作用域、作用域链、闭包。

## JavaScript 核心原理
1. 执行上下文

   - JS 代码执行时的运行环境，分为全局、函数、`eval`，里面主要保存变量、作用域链、`this`，函数调用时会创建新的执行上下文并压入调用栈
   - 口语版：执行上下文就是 JS 代码运行时创建的一个环境，里面会保存当前的变量、作用域链和 `this`。比如函数每调用一次，就会创建一个新的函数执行上下文，然后压入调用栈执行。

2. 作用域链

   **简要总结：**

   - 当前作用域找不到变量，就去外层作用域找
   - 一层一层往外查找，形成作用域链
   - 最后会查到全局作用域
   - 本质上由词法作用域决定

   **面试口语：**
    作用域链就是 JS 查找变量的规则。当前作用域找不到，就会去父级作用域继续找，一直找到全局作用域。如果还找不到，就会报错。

3. 🔥闭包

   **简要总结：**

   - 内部函数访问外部函数的变量
   - 外部函数执行结束后，这些变量不会马上被释放
   - 常用于数据私有化、保存状态
   - 使用不当可能造成内存占用过多

   **面试口语：**
    闭包就是一个函数可以访问它外层作用域里的变量，而且外层函数执行结束后，这些变量还能继续被内部函数使用。常见用途是保存状态和做数据私有化。

4. 🔥this

   **简要总结：**

   - `this` 表示当前函数执行时的上下文对象
   - 普通函数：看**谁调用它**
   - 对象方法：一般指向调用该方法的对象
   - `call / apply / bind`：可以手动修改 `this`
   - 箭头函数：**没有自己的 `this`**，继承外层 `this`

   **面试口语：**
    `this` 的指向主要看函数怎么调用。普通函数一般是谁调用就指向谁，`call、apply、bind` 可以修改它的指向。箭头函数比较特殊，它没有自己的 `this`，会直接使用外层作用域的 `this`。

5. 🔥原型与原型链

   **简要总结：**

   - 每个对象都可以通过原型继承属性和方法
   - 对象找不到属性时，会去它的原型上找
   - 原型再找不到，就继续往上找
   - 这一整条查找链就是原型链

   **面试口语：**
    原型就是 JS 实现继承的一种机制。对象访问一个属性时，如果自己没有，就会去原型对象上找，再找不到就继续往上找，直到 `null`，这个查找过程就是原型链。

6. 继承

   **简要总结：**

   - JS 继承本质上基于原型链
   - 子对象可以复用父对象的属性和方法
   - ES6 常用 `class` + `extends`
   - `class` 底层本质还是原型机制

   **面试口语：**
    JavaScript 的继承本质上是通过原型链实现的。ES6 之后一般用 `class` 和 `extends` 来写，但底层其实还是基于原型和原型链。

7. new

   **简要总结：**

   - 创建一个新对象
   - 新对象关联构造函数的 `prototype`
   - 构造函数里的 `this` 指向新对象
   - 执行构造函数
   - 返回这个新对象

   **面试口语：**
    `new` 的过程就是先创建一个新对象，把它的原型指向构造函数的 `prototype`，然后让构造函数里的 `this` 指向这个新对象并执行，最后返回这个对象

8. call / apply / bind

   **简要总结：**

   - 都可以修改函数的 `this`
   - `call`：立即执行，参数一个个传
   - `apply`：立即执行，参数用数组传
   - `bind`：不立即执行，返回一个新函数

   **面试口语：**
    `call、apply、bind` 都是用来改变 `this` 指向的。`call` 和 `apply` 会立即执行，区别是传参方式不同；`bind` 不会马上执行，而是返回一个绑定好 `this` 的新函数。




9. 深拷贝 / 浅拷贝

   1. **简要总结：**

      - 浅拷贝：只复制第一层，嵌套对象还是共用引用
      - 深拷贝：嵌套对象也会复制，互不影响
      - 浅拷贝常用：`Object.assign()`、`...`
      - 深拷贝常用：`structuredClone()`

      **面试口语：**
       浅拷贝只复制第一层，里面如果还有对象，还是指向同一个地址；深拷贝会把嵌套对象也复制一份，所以修改新对象不会影响原对象。

      ```js
         function deepClone(obj) {
            if (obj === null || typeof obj !== 'object') {
               return obj
            }
      
            const result = Array.isArray(obj) ? [] : {}
      
            for (const key in obj) {
               if (Object.prototype.hasOwnProperty.call(obj, key)) {
                  result[key] = deepClone(obj[key])
               }
            }
      
            return result
            }
      ```

       

10. 异步与事件循环

    **简要总结：**

    - JS 是单线程的
    - 同步任务直接进调用栈执行
    - 异步任务完成后进入任务队列
    - 调用栈清空后，事件循环把任务取出来执行
    - 微任务优先于宏任务

    **常见微任务：**

    - `Promise.then`
    - `queueMicrotask`

    **常见宏任务：**

    - `setTimeout`
    - `setInterval`
    - I/O

    **面试口语：**
     JavaScript 是单线程的，遇到异步任务时不会一直等，而是先执行后面的同步代码。异步任务完成后会进入任务队列，等调用栈清空后，事件循环再把任务拿出来执行。执行顺序上，一般是先执行微任务，再执行宏任务。

11. 🔥Promise

    **简要总结：**

    - 用来处理异步操作
    - 三种状态：`pending`、`fulfilled`、`rejected`
    - 状态一旦改变就不能再变
    - `then` 处理成功
    - `catch` 处理失败
    - `finally` 无论成功失败都会执行
    - 支持链式调用

    **面试口语：**
     `Promise` 是 JS 处理异步的一种方式，有等待、成功、失败三种状态，而且状态一旦改变就不会再变。成功用 `then`，失败用 `catch`，它还支持链式调用，可以避免传统回调写得太乱。

12. 🔥async / await

    **简要总结：**

    - 是 `Promise` 的语法糖
    - `async` 函数默认返回 `Promise`
    - `await` 等待 `Promise` 执行结果
    - 写法更像同步代码
    - 异常一般用 `try...catch`

    **面试口语：**
     `async/await` 本质上是 `Promise` 的语法糖，让异步代码写起来更像同步代码。`async` 函数会返回一个 `Promise`，`await` 用来等待它的结果，异常一般配合 `try...catch` 处理。
    
    ```javascript
    async function getUser() {
      try {
        const response = await fetch('/api/user')
    
        const data = await response.json()
    
        console.log(data)
      } catch (error) {
        console.error('请求失败：', error)
      }
    }
    ```
    
    

13. 🔥Event Loop

    **简要总结：**

    - JS 是单线程
    - 同步代码先执行
    - 异步任务进入任务队列
    - 调用栈清空后执行队列任务
    - **先执行微任务，再执行宏任务**

    **微任务：**

    - `Promise.then`
    - `queueMicrotask`

    **宏任务：**

    - `setTimeout`
    - `setInterval`
    - I/O

    **面试口语：**
     Event Loop 就是 JavaScript 处理异步任务的机制。同步代码先执行，执行完以后会先清空微任务队列，再执行一个宏任务，然后不断重复这个过程。

14. 宏任务 / 微任务

    **简要总结：**

    - 宏任务：`setTimeout`、`setInterval`、I/O
    - 微任务：`Promise.then`、`queueMicrotask`
    - 同一轮事件循环里，**微任务先于宏任务执行**

    **面试口语：**
     宏任务和微任务都是异步任务队列。像 `setTimeout` 属于宏任务，`Promise.then` 属于微任务。当前同步代码执行完后，会先把微任务清空，再去执行下一个宏任务。

15. 定时器

    **简要总结：**

    - `setTimeout`：延迟执行一次
    - `setInterval`：循环执行
    - `clearTimeout`：取消延时任务
    - `clearInterval`：取消循环任务
    - 定时器属于宏任务
    - 到时间后不一定立刻执行

    **面试口语：**
     JavaScript 定时器主要是 `setTimeout` 和 `setInterval`。它们到时间后会进入宏任务队列，等主线程空闲后再执行，所以设置的时间只是最小延迟时间，不代表一定准时执行。

16. 异步并发控制

    **简要总结：**

    - 控制同时执行的异步任务数量
    - 避免一次发太多请求
    - 常见方式：任务队列 + 并发数限制
    - `Promise.all` 是全部并发，不限制数量

    **面试口语：**
     异步并发控制就是限制同一时间执行的异步任务数量。比如有 100 个请求，我不会一次全部发出去，而是限制同时只执行 5 个，完成一个再补一个，这样可以避免把浏览器或服务端压力打满。

    **使用场景：**

    比如批量上传图片或者批量请求接口时，我会做并发控制。假设有 100 个任务，我可以限制同时只执行 3 个，一个完成后再补下一个，核心就是用任务队列加固定数量的 worker

    ```js
    async function limitRequest(tasks, limit = 3) {
      const queue = [...tasks]
    
      async function worker() {
        while (queue.length) {
          const task = queue.shift()
          await task()
        }
      }
    
        const workers = []
        for (let i = 0; i < limit; i++) {
          workers.push(worker())
        }
    
      await Promise.all(workers)
    }
    ```

    ```js
    const tasks = urls.map(url => {
      return () => fetch(url)
    })
    
    await limitRequest(tasks, 3)
    ```

    

17. Promise 错误处理

    **简要总结：**

    - `catch()` 捕获错误
    - `then` 第二个参数也能处理错误
    - `finally()` 无论成功失败都会执行
    - `async/await` 一般配合 `try...catch`

    ```js
    fetch('/api/user')
      .then(res => res.json())
      .catch(err => {
        console.error(err)
      })
      .finally(() => {
        console.log('请求结束')
      })
    ```

    **面试口语：**
     Promise 的错误一般用 `catch` 统一处理，`finally` 做一些收尾操作。如果用 `async/await`，通常会配合 `try...catch` 来捕获异常。
