# 镜像

## 镜像基础

### 1. 🔥 镜像是什么

**简要总结：**

- 镜像是容器运行模板
- 包含文件系统、依赖、运行时、配置
- 镜像是只读分层结构
- 容器基于镜像启动

**面试口语：**

镜像可以理解成打包好的应用运行环境。只要镜像构建稳定，在不同机器上启动出来的容器环境就基本一致。

**底层原理 / 背后逻辑：**

镜像使用分层文件系统。每一层只保存相对上一层的变化。多个镜像可以共享相同基础层，所以节省空间，也加快拉取和构建。

### 2. 🔥 镜像分层

**简要总结：**

- Dockerfile 指令会生成层
- 层是只读的
- 容器运行时增加可写层
- 相同层可以复用
- 删除上层文件不一定减少最终历史层体积

**面试口语：**

镜像分层让构建可以复用缓存，也让多个镜像共享基础层。但如果前一层复制了大文件，后一层删除它，历史层里仍然存在，所以镜像体积不一定变小。

**底层原理 / 背后逻辑：**

联合文件系统把多层文件合并成一个视图。下层文件只读，上层可以覆盖或标记删除。这个设计换来了复用和缓存，但也要求 Dockerfile 写法注意层的顺序和内容。

## 镜像仓库

### 1. ⭐ Registry 和 tag

**简要总结：**

- Registry 是镜像仓库
- Repository 是镜像集合
- Tag 是镜像版本标签
- `latest` 不是可靠版本号
- 生产部署应使用明确版本或 digest

**面试口语：**

镜像 tag 用来区分版本，但 `latest` 只是一个普通标签，不代表最新也不稳定。生产环境最好用明确版本号，关键场景可以用 digest 保证镜像不可变。

**底层原理 / 背后逻辑：**

tag 是可移动引用，同一个 tag 可以被重新推送到不同镜像。digest 是内容哈希，内容变 digest 就变。部署要可回滚、可追踪，就不能只依赖 `latest`。

### 2. ⭐ 镜像体积优化

**简要总结：**

- 选择更小基础镜像
- 清理构建缓存
- 使用多阶段构建
- 不复制无关文件
- 使用 `.dockerignore`

**面试口语：**

镜像越大，拉取越慢，部署越慢，安全扫描面也越大。优化时会选合适基础镜像、减少无用文件、用多阶段构建只保留运行时需要的东西。

**底层原理 / 背后逻辑：**

镜像体积来自所有层的叠加。构建工具、源码缓存、临时文件如果留在最终镜像里，会增加传输、存储和安全风险。多阶段构建可以把编译环境和运行环境分离。
