## Docker 核心概念

### 1. 🔥 Docker 是什么

**简要总结：**

- Docker 是容器化平台
- 用镜像打包应用和运行环境
- 用容器运行镜像实例
- 解决环境不一致、部署复杂、隔离运行问题
- 常用于后端服务、数据库、中间件、本地开发环境

**面试口语：**

Docker 可以把应用代码、依赖、运行时和启动命令打包成镜像，然后在不同机器上用相同方式启动容器。它解决的核心问题是环境一致性和部署标准化。

**底层原理 / 背后逻辑：**

Docker 不是虚拟机。它本质上还是宿主机上的进程，只是通过 Linux namespace 做资源视图隔离，通过 cgroups 做资源限制，通过联合文件系统做镜像分层。容器轻量，是因为它共享宿主机内核，不需要每个应用启动一个完整操作系统。

### 2. 🔥 镜像和容器区别

**简要总结：**

- 镜像是静态模板
- 容器是镜像运行后的实例
- 一个镜像可以启动多个容器
- 容器有自己的可写层
- 删除容器不等于删除镜像

**面试口语：**

镜像可以理解成应用的安装包或模板，容器是这个模板运行起来后的进程环境。一个镜像可以启动很多个容器，每个容器有自己的运行状态。

**底层原理 / 背后逻辑：**

镜像由多层只读文件系统组成，容器启动时会在镜像之上加一层可写层。应用运行时写入的临时文件默认进容器可写层，所以容器删除后这些数据也会丢，持久数据要放 Volume。

### 3. ⭐ Docker 和虚拟机区别

**简要总结：**

- 虚拟机虚拟硬件和完整操作系统
- Docker 容器共享宿主机内核
- 容器启动更快、资源占用更少
- 虚拟机隔离更重
- 容器更适合应用级部署

**面试口语：**

虚拟机像是在一台机器里再跑一台完整机器，容器更像是在同一个 Linux 内核上隔离运行多个进程。Docker 更轻量，启动更快，更适合微服务和应用部署。

**底层原理 / 背后逻辑：**

虚拟机通过 Hypervisor 虚拟 CPU、内存、磁盘和网卡，每个虚拟机有自己的内核。容器共享宿主机内核，只隔离进程、网络、文件系统等视图，所以性能损耗更小，但内核隔离边界没有虚拟机那么厚。

## 常用命令

### 1. 🔥 Docker 常用命令

**简要总结：**

- `docker images`：查看镜像
- `docker ps`：查看运行中容器
- `docker ps -a`：查看所有容器
- `docker run`：启动容器
- `docker stop`：停止容器
- `docker logs`：查看日志
- `docker exec`：进入容器执行命令

**面试口语：**

Docker 排查常用命令主要是看容器是否运行、看日志、进容器确认环境。比如服务启动失败，我会先 `docker ps -a` 看状态，再 `docker logs` 看错误。

**底层原理 / 背后逻辑：**

Docker CLI 是和 Docker Daemon 通信。真正创建容器、挂载文件系统、配置网络、限制资源的是守护进程。命令只是观察和控制容器生命周期的入口。
