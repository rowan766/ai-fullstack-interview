# 镜像优化

> 图标说明：⭐ 重点｜🔥 高频｜⚠️ 注意｜💡 提示｜📌 重点记忆

## 构建优化

### 1. 🔥 如何减小镜像体积

**简要总结：**

- 选择合适基础镜像
- 使用 `.dockerignore`
- 清理包管理器缓存
- 多阶段构建
- 只保留运行时需要的文件
- 不把日志、缓存、测试数据打进镜像

**面试口语：**

减小镜像体积主要是减少无用文件和构建依赖。比如前端构建后只保留 dist，后端只保留运行依赖，不把源码缓存、测试文件、包管理缓存都塞进最终镜像。

**底层原理 / 背后逻辑：**

镜像越大，拉取、存储、扫描、部署都越慢。镜像体积来自每一层内容，构建时加入的大文件即使后面删除，也可能仍留在历史层里，所以要在同一层清理或使用多阶段构建。

### 2. 🔥 多阶段构建

**简要总结：**

- build 阶段安装编译工具和构建依赖
- runtime 阶段只复制产物
- 减少最终镜像体积
- 降低攻击面

**面试口语：**

多阶段构建就是把编译环境和运行环境分开。第一阶段负责构建，第二阶段只复制构建产物和运行依赖，这样最终镜像更小、更干净。

**底层原理 / 背后逻辑：**

很多构建工具只在构建期需要，运行时不需要。把它们留在最终镜像里会增加体积和安全风险。多阶段构建利用多个 FROM，把中间阶段当临时环境。

## 缓存优化

### 1. ⭐ 利用构建缓存

**简要总结：**

- 变化少的层放前面
- 变化频繁的代码放后面
- 先复制依赖文件并安装依赖
- 再复制业务代码
- 避免无关文件导致缓存失效

**面试口语：**

构建缓存优化常见做法是先复制依赖配置，安装依赖，然后再复制业务代码。这样代码改动不会让依赖层每次都重新构建。

**底层原理 / 背后逻辑：**

Docker 构建缓存按层判断输入是否变化。一层变化，它后面的层都要重新执行。把稳定层放前面，就能最大化缓存命中。

### 2. ⭐ 安全优化

**简要总结：**

- 不在镜像里写死密钥
- 使用非 root 用户运行
- 减少不必要工具
- 固定基础镜像版本
- 做镜像漏洞扫描

**面试口语：**

镜像优化不只是体积，还包括安全。生产镜像不要内置密钥，不要默认 root 跑服务，基础镜像要固定版本并定期扫描漏洞。

**底层原理 / 背后逻辑：**

镜像里包含的每个工具和库都可能成为攻击面。权限越高、组件越多、版本越不可控，风险越大。小镜像不仅部署快，也更容易做安全治理。
