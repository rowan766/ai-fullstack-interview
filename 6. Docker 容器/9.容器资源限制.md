# 容器资源限制

> 图标说明：⭐ 重点｜🔥 高频｜⚠️ 注意｜💡 提示｜📌 重点记忆

## cgroups

### 1. 🔥 为什么要限制容器资源

**简要总结：**

- 防止单个容器抢占宿主机资源
- 限制 CPU、内存、进程数、IO
- 提升多服务稳定性
- 避免一个服务拖垮整台机器

**面试口语：**

一台机器上可能跑多个容器，如果不限制资源，一个异常服务可能把 CPU 或内存吃满，影响其他服务。所以生产环境要设置合理的资源限制。

**底层原理 / 背后逻辑：**

Docker 通过 cgroups 限制容器能使用的资源。容器本质是宿主机进程，如果没有 cgroups，它和普通进程一样可能消耗整台机器资源。资源限制就是给每组进程划边界。

### 2. 🔥 内存限制和 OOM

**简要总结：**

- `--memory` 设置内存上限
- 超过限制可能触发 OOM kill
- 容器退出码可能是 137
- Java、Node、Python 都要注意内存峰值

**面试口语：**

容器内存超过限制时，可能被 OOM kill。排查时我会看容器状态、退出码、Docker 事件和应用内存曲线，判断是内存泄漏、数据量过大还是限制太小。

**底层原理 / 背后逻辑：**

内核会统计 cgroup 内进程的内存使用。当超过限制且无法回收时，会杀掉进程释放内存。容器里看到的可用内存和宿主机不完全等价，应用运行时最好能感知容器限制。

## CPU 限制

### 1. 🔥 CPU 限制

**简要总结：**

- `--cpus` 限制可用 CPU
- CPU 限制通常表现为变慢
- 不一定会杀进程
- CPU 密集型服务要合理分配

**面试口语：**

CPU 超限一般不是直接杀掉容器，而是被调度限速，所以表现为接口变慢、任务执行变久。CPU 密集型任务和在线接口最好隔离部署。

**底层原理 / 背后逻辑：**

cgroups 可以限制进程在一个周期内使用 CPU 的时间片。超过配额后进程要等待下个周期。这个机制保护宿主机整体资源，但容器内应用会感受到延迟增加。

### 2. ⭐ 资源限制怎么设置

**简要总结：**

- 根据压测和历史监控设置
- 区分 requests 和 limits 思路
- 在线服务预留余量
- 批处理任务避免影响接口服务
- 配合监控告警

**面试口语：**

资源限制不是随便写一个值，要结合压测、线上监控和业务峰值。在线服务要留余量，批处理任务要限制资源，避免影响核心接口。

**底层原理 / 背后逻辑：**

资源限制太小会导致频繁 OOM 或限速，太大又失去隔离意义。设置资源的本质是容量规划：明确每个服务的资源边界和故障影响范围。
