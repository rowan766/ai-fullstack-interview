# Docker 部署与故障排查

## 部署流程

### 1. 🔥 Docker 部署后端服务流程

**简要总结：**

- 编写 Dockerfile
- 构建镜像
- 推送镜像仓库
- 服务器拉取镜像
- 配置环境变量、端口、Volume
- 启动容器并查看日志
- 配置 Nginx 反向代理

**面试口语：**

Docker 部署一般是先把应用构建成镜像，推到镜像仓库，然后服务器拉取指定版本镜像，带上环境变量、端口和数据卷启动容器，最后通过日志和健康检查确认服务正常。

**底层原理 / 背后逻辑：**

Docker 部署强调镜像不可变和环境外部化。代码和依赖进入镜像，环境差异通过环境变量、配置文件和挂载注入。这样同一个镜像可以在测试和生产用相同方式运行，减少环境不一致。

### 2. 🔥 容器启动失败怎么排查

**简要总结：**

- `docker ps -a` 看状态和退出码
- `docker logs 容器名` 看错误
- 检查启动命令
- 检查环境变量
- 检查端口占用
- 检查挂载路径和权限
- 检查依赖服务是否可用

**面试口语：**

容器启动失败我会先看状态和日志。常见原因是启动命令错、环境变量缺失、端口被占、挂载目录权限不对，或者数据库、Redis 这些依赖还没准备好。

**底层原理 / 背后逻辑：**

容器启动后只要主进程退出，容器就退出。排查时要围绕主进程为什么没有持续运行来找原因。日志、退出码、环境变量和挂载配置通常能定位大部分问题。

## 常见问题

### 1. 🔥 容器能启动但访问不了

**简要总结：**

- 应用是否在容器内监听
- 监听地址是否是 `0.0.0.0`
- 端口映射是否正确
- 防火墙或安全组是否放行
- Nginx upstream 是否配置正确

**面试口语：**

容器运行中但访问不了，我会先进容器或看日志确认应用监听端口，再看 `docker ps` 端口映射，然后看宿主机防火墙、安全组和 Nginx 配置。

**底层原理 / 背后逻辑：**

外部访问容器要经过外部网络、宿主机端口、Docker 转发、容器网络、应用监听。任意一层错都会访问失败。特别常见的是应用只监听 `127.0.0.1`，导致容器外无法访问。

### 2. 🔥 容器反复重启

**简要总结：**

- 主进程异常退出
- restart policy 自动拉起
- 配置错误导致重复失败
- 依赖服务不可用
- OOM kill

**面试口语：**

容器反复重启通常是主进程不断退出，而 restart 策略又把它拉起来。我会看 logs、退出码和资源使用，判断是程序报错、配置缺失、依赖连接失败还是 OOM。

**底层原理 / 背后逻辑：**

restart policy 只能保证进程退出后尝试重启，不能解决根因。如果配置永远错，容器就会进入 crash loop。排查要找第一次退出的错误，而不是只看它重启了多少次。

### 3. ⭐ 镜像版本和回滚

**简要总结：**

- 生产不要依赖 latest
- 每次发布使用明确 tag
- 保留上一版本镜像
- 回滚就是重新启动旧版本镜像
- 数据库变更要单独考虑兼容性

**面试口语：**

Docker 回滚应用代码相对简单，只要保留旧镜像，用旧 tag 重新启动即可。但如果涉及数据库结构变更，就要提前设计兼容和回滚方案。

**底层原理 / 背后逻辑：**

镜像不可变让应用发布可追踪、可回滚。真正复杂的是外部状态，比如数据库数据、文件、缓存和消息。应用镜像能回滚，不代表数据也能自动回滚。
