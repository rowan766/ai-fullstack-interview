## Dockerfile 基础

### 1. 🔥 Dockerfile 是什么

**简要总结：**

- Dockerfile 是镜像构建说明书
- 每条指令通常会形成镜像层
- 描述基础镜像、依赖安装、文件复制、启动命令
- 构建结果是镜像

**面试口语：**

Dockerfile 用来声明镜像怎么构建。比如从哪个基础镜像开始，安装哪些依赖，复制哪些代码，暴露什么端口，容器启动时执行什么命令。

**底层原理 / 背后逻辑：**

镜像构建是分层的。Docker 按 Dockerfile 指令逐步执行，每一步生成一层缓存。上层依赖下层，如果前面的层没有变化，后面构建可以复用缓存，这也是为什么依赖安装和代码复制顺序会影响构建速度。

### 2. 🔥 常见指令

**简要总结：**

- `FROM`：基础镜像
- `WORKDIR`：工作目录
- `COPY`：复制文件
- `RUN`：构建阶段执行命令
- `ENV`：环境变量
- `EXPOSE`：声明端口
- `CMD`：默认启动命令
- `ENTRYPOINT`：入口命令

**面试口语：**

`RUN` 是构建镜像时执行，`CMD` 和 `ENTRYPOINT` 是容器启动时执行。`COPY` 负责把项目文件放进镜像，`WORKDIR` 用来设置后续命令的工作目录。

**底层原理 / 背后逻辑：**

构建阶段和运行阶段要分清。依赖安装、编译构建应该放在镜像构建期；启动服务才是容器运行期。把运行时才需要的事情放进启动命令，会让容器启动慢且不稳定。

## CMD 和 ENTRYPOINT

### 1. 🔥 CMD 和 ENTRYPOINT 区别

**简要总结：**

- `CMD` 提供默认参数或默认命令
- `ENTRYPOINT` 定义固定入口
- `docker run` 后面的参数容易覆盖 CMD
- 两者可以配合使用

**面试口语：**

CMD 更像默认启动命令，运行时可以被覆盖；ENTRYPOINT 更像固定入口，适合容器始终执行某个程序，再把 CMD 当默认参数。

**底层原理 / 背后逻辑：**

容器启动后本质上会运行一个前台主进程。Docker 需要知道这个主进程是什么。CMD 和 ENTRYPOINT 最终都会参与生成容器主进程命令，区别在于覆盖规则和表达意图不同。

### 2. ⭐ Dockerfile 优化

**简要总结：**

- 先复制依赖描述文件，再安装依赖
- 再复制业务代码
- 合并 RUN 减少层数
- 使用 `.dockerignore`
- 多阶段构建减少最终镜像体积

**面试口语：**

Dockerfile 优化主要看缓存和镜像大小。比如 Python 项目先复制 requirements，再安装依赖，最后复制代码，这样代码改动不会导致依赖层每次重装。

**底层原理 / 背后逻辑：**

Docker 构建缓存按层复用。只要某层输入变化，它之后的层都要重新构建。把变化少的依赖层放前面、变化频繁的业务代码放后面，可以显著提升构建速度。
