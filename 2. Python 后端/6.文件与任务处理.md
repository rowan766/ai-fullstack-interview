## 文件处理

### 1. 🔥 文件读写

**简要总结：**

- 使用 `with open()` 自动关闭文件
- 文本文件注意编码
- 大文件不要一次性读入内存
- 二进制文件使用 `rb` / `wb`

**面试口语：**

Python 文件处理常用 `with open()`，它能保证异常情况下也关闭文件。读大文件时不要 `read()` 一次全部加载，应该逐行或分块读取。

```python
with open("data.txt", "r", encoding="utf-8") as file:
    for line in file:
        handle(line.strip())
```

**底层原理 / 背后逻辑：**

文件是操作系统资源，不关闭会占用文件描述符。`with` 依赖上下文管理器，进入时打开资源，退出时调用 `__exit__` 释放资源。大文件一次性读入会占用大量内存，流式读取可以把内存占用控制在很小范围内。

### 2. 🔥 文件上传

**简要总结：**

- 校验文件大小、类型、扩展名
- 文件名要重新生成，避免路径穿越和覆盖
- 大文件分块保存
- 上传后可异步处理

**面试口语：**

文件上传不能只相信前端限制，后端要校验大小、类型和权限。保存时不要直接使用用户传来的文件名，避免覆盖文件或路径穿越。

```python
from pathlib import Path
from uuid import uuid4

def save_upload(filename: str, content: bytes):
    suffix = Path(filename).suffix
    safe_name = f"{uuid4().hex}{suffix}"
    path = Path("uploads") / safe_name
    path.write_bytes(content)
    return path
```

### 3. ⭐ pathlib

**简要总结：**

- 面向对象的路径处理库
- 比字符串拼路径更安全清晰
- 跨平台处理路径分隔符
- 支持读取、写入、遍历、判断文件类型

**面试口语：**

`pathlib` 比手动拼字符串更推荐，尤其是跨平台路径处理。它把路径当对象操作，可读性更好。

```python
from pathlib import Path

base = Path("logs")
for path in base.glob("*.log"):
    print(path.name, path.stat().st_size)
```

## 任务处理

### 1. 🔥 后台任务

**简要总结：**

- 请求内只做必要操作
- 耗时任务放后台执行
- 常见场景：发邮件、生成报表、图片处理、消息推送
- 简单任务可用 FastAPI BackgroundTasks
- 复杂任务用 Celery / RQ / Dramatiq

**面试口语：**

后台任务是为了缩短接口响应时间。比如用户提交后立即返回成功，发邮件、生成报表这类耗时操作放到后台处理。

```python
from fastapi import BackgroundTasks

def send_email(email: str):
    ...

@app.post("/register")
def register(email: str, tasks: BackgroundTasks):
    tasks.add_task(send_email, email)
    return {"message": "注册成功"}
```

**底层原理 / 背后逻辑：**

简单后台任务通常仍在当前应用进程里执行，进程重启可能丢任务，不适合重要任务。可靠任务系统会把任务写入消息队列，由 worker 消费，任务状态和重试策略可追踪。

### 2. 🔥 Celery

**简要总结：**

- 分布式任务队列
- Broker 负责传递任务，如 Redis、RabbitMQ
- Worker 负责执行任务
- Result backend 保存执行结果
- 支持重试、定时任务、并发 worker

**面试口语：**

Celery 适合异步任务和定时任务。Web 服务把任务发到 broker，worker 从 broker 取任务执行，执行结果可以保存到 result backend。

```python
from celery import Celery

celery_app = Celery("tasks", broker="redis://localhost:6379/0")

@celery_app.task(bind=True, max_retries=3)
def send_email(self, email: str):
    try:
        do_send(email)
    except Exception as exc:
        raise self.retry(exc=exc, countdown=5)
```

**底层原理 / 背后逻辑：**

Celery 本质是生产者消费者模型。Web 应用是生产者，把任务消息放进 broker；worker 是消费者，取出消息执行。可靠性来自消息确认、重试、超时、幂等设计。面试常追问：任务可能重复执行，所以任务逻辑要尽量幂等。

### 3. ⭐ 定时任务

**简要总结：**

- Linux 可用 cron
- Python 可用 APScheduler
- Celery 可用 celery beat
- 分布式环境要避免多实例重复执行

**面试口语：**

定时任务要注意单机和多机区别。单机用 cron 或 APScheduler 很简单，多实例部署时要避免每个实例都跑一遍，可以用分布式锁或统一调度器。

### 4. 🔥 任务幂等和重试

**简要总结：**

- 任务失败后可能重试
- 网络超时不代表下游没有成功
- 幂等 key 可以防止重复处理
- 数据库唯一约束可兜底

**面试口语：**

异步任务一定要考虑重复执行。比如扣库存、发优惠券、转账这类任务，如果重试后重复执行会出事故。可以用业务唯一键、状态机或数据库唯一约束保证幂等。

```python
def grant_coupon(user_id: int, coupon_id: int):
    key = f"{user_id}:{coupon_id}"
    if has_processed(key):
        return
    create_coupon_record(user_id, coupon_id, idempotent_key=key)
```
