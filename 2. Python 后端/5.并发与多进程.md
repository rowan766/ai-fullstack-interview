# 并发与多进程

## 并发基础

### 1. 🔥 线程、进程、协程区别

**简要总结：**

- 进程：资源分配单位，内存隔离
- 线程：CPU 调度单位，共享进程内存
- 协程：用户态调度，遇到 await 主动让出执行权
- CPU 密集型适合多进程
- IO 密集型适合多线程或异步

**面试口语：**

进程隔离性强，可以利用多核，但创建和通信成本高；线程共享内存，适合 IO 密集型，但要注意锁和线程安全；协程更轻量，适合高并发 IO，但不能执行阻塞代码。

**底层原理 / 背后逻辑：**

选择并发模型要看瓶颈在哪里。CPU 密集型任务需要真正使用多个 CPU 核，CPython 多线程受 GIL 限制，所以更适合多进程。IO 密集型任务大部分时间在等待外部资源，多线程和协程都能在等待时切换任务，提高吞吐。

### 2. 🔥 GIL

**简要总结：**

- GIL 是 CPython 的全局解释器锁
- 同一时刻只有一个线程执行 Python 字节码
- 简化引用计数和 C 扩展线程安全
- 限制 CPU 密集型多线程性能
- IO 等待时线程可能释放 GIL

**面试口语：**

GIL 限制的是 CPython 多线程执行 Python 字节码，不代表 Python 不能并发。IO 密集型多线程仍然有意义，因为线程等待 IO 时会释放 GIL；CPU 密集型更适合多进程。

**底层原理 / 背后逻辑：**

CPython 的内存管理大量依赖引用计数，如果多个线程同时修改对象引用计数，需要复杂锁保护。GIL 用一把大锁保护解释器内部状态，降低实现复杂度。但代价是多个线程不能同时执行 Python 字节码，因此 CPU 计算无法靠多线程充分利用多核。

### 3. 🔥 ThreadPoolExecutor

**简要总结：**

- 线程池复用线程
- 适合网络请求、文件 IO、数据库访问
- 减少频繁创建销毁线程开销
- 仍需注意共享数据线程安全

**面试口语：**

线程池适合大量 IO 任务，比如批量请求接口。线程在等待 IO 时让出 CPU，其他线程可以继续执行，因此整体吞吐会提升。

```python
from concurrent.futures import ThreadPoolExecutor

def download(url: str) -> str:
    return requests.get(url, timeout=3).text

with ThreadPoolExecutor(max_workers=10) as pool:
    results = list(pool.map(download, urls))
```

### 4. 🔥 ProcessPoolExecutor

**简要总结：**

- 进程池复用子进程
- 适合 CPU 密集型任务
- 可以利用多核
- 参数和返回值需要序列化
- 进程间通信成本高

**面试口语：**

进程池适合图片处理、压缩、复杂计算这类 CPU 密集型任务。每个进程有自己的解释器和 GIL，所以可以利用多核，但进程通信和数据序列化成本更高。

```python
from concurrent.futures import ProcessPoolExecutor

def fib(n: int) -> int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

with ProcessPoolExecutor() as pool:
    results = list(pool.map(fib, [30, 31, 32]))
```

### 5. 🔥 线程安全和锁

**简要总结：**

- 多线程共享数据会产生竞态条件
- `Lock` 保护临界区
- `RLock` 支持同一线程重复获取
- `Semaphore` 控制并发数量
- 锁粒度太大会降低并发性能

**面试口语：**

线程安全问题通常是多个线程同时读写共享变量。解决方法是用锁保护临界区，但锁不能乱加，粒度太大会让程序退化成串行，多个锁顺序不一致还可能死锁。

```python
import threading

lock = threading.Lock()
count = 0

def increment():
    global count
    with lock:
        count += 1
```

### 6. ⭐ 队列和生产者消费者

**简要总结：**

- Queue 是线程安全队列
- 生产者负责放任务
- 消费者负责取任务处理
- 可用于削峰、解耦和后台任务

**面试口语：**

生产者消费者模型适合任务处理场景。请求线程只负责把任务放进队列，后台 worker 慢慢消费，可以解耦请求和耗时处理。

```python
from queue import Queue
from threading import Thread

queue = Queue()

def worker():
    while True:
        item = queue.get()
        try:
            handle(item)
        finally:
            queue.task_done()

Thread(target=worker, daemon=True).start()
```

### 7. ⭐ 多进程通信

**简要总结：**

- Queue：进程间传递消息
- Pipe：两个进程之间通信
- Manager：共享代理对象
- SharedMemory：共享内存
- 真实项目更多用 Redis、MQ、数据库协调

**面试口语：**

进程之间内存隔离，不能像线程一样直接共享变量。需要通过 Queue、Pipe、共享内存或外部中间件通信。Web 项目里多 worker 通常会用 Redis 或消息队列协调状态。
