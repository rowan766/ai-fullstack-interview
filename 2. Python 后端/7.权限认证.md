# 权限认证

## 认证与授权

### 1. 🔥 认证和授权区别

**简要总结：**

- 认证 Authentication：确认你是谁
- 授权 Authorization：确认你能做什么
- 登录、token 校验属于认证
- 角色、权限、资源访问控制属于授权

**面试口语：**

认证解决身份问题，授权解决权限问题。比如用户登录成功只是证明他是谁，不代表他能删除订单；删除订单还要判断他有没有对应权限。

**底层原理 / 背后逻辑：**

后端安全链路通常先认证再授权。认证失败返回 401，授权失败返回 403。认证信息可以来自 Session、JWT、API Key、OAuth2；授权模型可以是 RBAC、ABAC 或资源级权限。

### 2. 🔥 Session 和 Cookie

**简要总结：**

- Session 状态通常保存在服务端
- Cookie 保存 session id
- 浏览器会自动携带 Cookie
- 服务端根据 session id 找登录态
- 需要防 CSRF

**面试口语：**

Session 方案是服务端保存登录状态，客户端只保存一个 session id。浏览器每次请求自动带 Cookie，服务端根据这个 id 查用户信息。

**底层原理 / 背后逻辑：**

HTTP 是无状态协议，每次请求之间天然没有关联。Session 的作用是在服务端建立一份状态，再用 Cookie 中的 session id 把多次请求关联起来。它的优点是服务端可控，缺点是需要存储和共享 Session，多实例部署时通常要放 Redis。

### 3. 🔥 JWT

**简要总结：**

- JWT 是自包含 token
- 由 header、payload、signature 三部分组成
- 服务端通过签名验证 token 是否被篡改
- payload 不是加密，只是 Base64URL 编码
- 适合无状态认证

**面试口语：**

JWT 的特点是自包含，token 里可以带用户 id、过期时间等声明。服务端不用查 Session，只要校验签名和过期时间即可。但 JWT 一旦签发，在过期前不容易主动失效。

```python
import jwt

token = jwt.encode({"sub": "1"}, "secret", algorithm="HS256")
payload = jwt.decode(token, "secret", algorithms=["HS256"])
```

**底层原理 / 背后逻辑：**

JWT 的签名用于防篡改，不负责保密。客户端可以解码 payload，所以不能放密码、密钥等敏感信息。服务端用相同密钥或公钥验签，确认 token 是可信签发方生成且未被修改。

📌 重点记忆：JWT 可验证，不等于加密。

### 4. 🔥 RBAC 权限模型

**简要总结：**

- User 用户
- Role 角色
- Permission 权限
- 用户绑定角色
- 角色绑定权限
- 适合后台管理系统

**面试口语：**

RBAC 是最常见的后台权限模型。用户不直接绑定大量权限，而是绑定角色，角色再绑定权限。这样权限变化时只需要调整角色，不用逐个改用户。

```txt
User -> Role -> Permission
Tom  -> Admin -> order:delete
```

**底层原理 / 背后逻辑：**

权限系统的核心是把“主体、资源、动作”建模清楚。比如用户 Tom 对订单资源是否有 delete 动作权限。RBAC 用角色作为中间层降低管理复杂度，但如果权限和具体数据强相关，比如只能看自己部门订单，就需要加入数据权限或 ABAC。

### 5. ⭐ OAuth2

**简要总结：**

- OAuth2 是授权框架
- 常用于第三方登录和开放平台授权
- 用户授权后，客户端拿到 access token
- 常见流程：授权码模式

**面试口语：**

OAuth2 解决的是第三方应用如何在用户授权后访问资源。比如用 GitHub 登录，应用不会拿到用户 GitHub 密码，而是通过授权码换 access token。

**底层原理 / 背后逻辑：**

授权码模式把用户登录放在授权服务器完成，客户端只拿到临时 code，再由后端用 code 换 token。这样 access token 不直接暴露在浏览器跳转地址里，更安全。OAuth2 关注授权，OIDC 在 OAuth2 之上补充身份认证。

### 6. 🔥 密码安全

**简要总结：**

- 密码不能明文存储
- 使用哈希加盐
- 推荐 bcrypt、argon2、pbkdf2
- 登录时比较哈希结果
- 防止暴力破解要加限流和锁定策略

**面试口语：**

密码必须做不可逆哈希并加盐，不能用 MD5 简单存。bcrypt、argon2 这类算法故意设计得比较慢，可以增加暴力破解成本。

```python
from passlib.context import CryptContext

pwd_context = CryptContext(schemes=["bcrypt"], deprecated="auto")

hashed = pwd_context.hash("password")
is_valid = pwd_context.verify("password", hashed)
```

### 7. ⭐ 接口鉴权实现

**简要总结：**

- 从请求头或 Cookie 获取凭证
- 验证 token / session
- 查询用户状态
- 判断权限
- 无身份返回 401，无权限返回 403

**面试口语：**

接口鉴权通常会封装成中间件或依赖函数。先解析当前用户，再判断用户是否有访问当前资源的权限。FastAPI 里可以用 Depends，Django 里可以用 middleware 或 permission class。

```python
from fastapi import Depends, HTTPException

def require_admin(user=Depends(get_current_user)):
    if "admin" not in user["roles"]:
        raise HTTPException(status_code=403, detail="无权限")
    return user
```
