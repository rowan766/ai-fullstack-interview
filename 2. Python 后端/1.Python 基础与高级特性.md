## Python 基础

### 1. 🔥 常用数据类型

**简要总结：**

- 数字：`int`、`float`、`bool`、`complex`
- 字符串：`str`
- 容器：`list`、`tuple`、`set`、`dict`
- 特殊值：`None`
- 不可变类型：`int`、`float`、`bool`、`str`、`tuple`
- 可变类型：`list`、`set`、`dict`

**面试口语：**

Python 常用数据类型包括数字、字符串、列表、元组、集合和字典。它们最重要的区别是是否可变，不可变对象创建后值不能原地修改，可变对象可以在原地址上修改内容。

📌 重点记忆：`tuple` 本身不可变，但如果里面放了 `list`，这个 `list` 的内容仍然可以改。

### 2. 🔥 可变对象和不可变对象

**简要总结：**

- 可变对象：对象内容可以原地修改，`id` 通常不变
- 不可变对象：修改时会创建新对象
- 可变对象常见：`list`、`dict`、`set`
- 不可变对象常见：`int`、`str`、`tuple`

**面试口语：**

可变对象是内容可以被原地修改的对象，比如列表追加元素后还是同一个对象；不可变对象修改时会产生新对象，比如字符串拼接后会得到一个新的字符串。

```python
nums = [1, 2]
print(id(nums))
nums.append(3)
print(id(nums))  # id 通常不变
```

### 3. 🔥 list / tuple / set / dict 区别

**简要总结：**

- `list`：有序、可重复、可变
- `tuple`：有序、可重复、不可变
- `set`：无序、唯一、可变
- `dict`：键值对、key 唯一、按插入顺序保留

**面试口语：**

列表适合存一组可变序列，元组适合存固定结构的数据，集合适合去重和集合运算，字典适合通过 key 快速查找 value。

⚠️ 注意：Python 3.7+ 中 `dict` 语言层面保证按插入顺序保存。

### 4. 🔥 is 和 ==

**简要总结：**

- `==` 比较值是否相等
- `is` 比较两个变量是否引用同一个对象
- `is` 常用于判断 `None`
- 小整数缓存、字符串驻留可能让 `is` 的结果看起来“相等”

**面试口语：**

`==` 比较的是值，`is` 比较的是对象身份，也就是内存中的同一个对象。判断普通值是否相等用 `==`，判断是不是 `None` 用 `is None`。

```python
a = [1, 2]
b = [1, 2]

print(a == b)  # True
print(a is b)  # False
```

### 5. 🔥 浅拷贝和深拷贝

**简要总结：**

- 浅拷贝只复制第一层对象
- 深拷贝会递归复制嵌套对象
- `copy.copy()` 是浅拷贝
- `copy.deepcopy()` 是深拷贝

**面试口语：**

浅拷贝会创建一个新的外层对象，但里面嵌套的对象仍然共享引用；深拷贝会把嵌套对象也复制一份，修改新对象不会影响原对象。

```python
import copy

a = [[1], [2]]
b = copy.copy(a)
c = copy.deepcopy(a)

a[0].append(100)
print(b)  # [[1, 100], [2]]
print(c)  # [[1], [2]]
```

### 6. 🔥 参数传递机制

**简要总结：**

- Python 参数传递本质是对象引用传递
- 函数形参是外部对象引用的一个新名字
- 修改可变对象内部内容，会影响外部对象
- 给形参重新赋值，不会改变外部变量绑定

**面试口语：**

Python 不是传统意义上的值传递或引用传递，更准确说是对象引用传递。函数接收到的是对象引用，修改可变对象内容会影响外部；但如果给形参重新赋值，只是让形参指向新对象。

📌 重点记忆：变量不是盒子，变量是对象的名字。

### 7. 🔥 作用域和 LEGB

**简要总结：**

- `L`：Local，本地作用域
- `E`：Enclosing，外层函数作用域
- `G`：Global，模块全局作用域
- `B`：Built-in，内置作用域
- 查找变量时按 LEGB 顺序查找

**面试口语：**

LEGB 是 Python 查找变量的顺序：先在当前函数里找，再去外层函数找，然后去模块全局找，最后去内置作用域找。

### 8. ⭐ global 和 nonlocal

**简要总结：**

- `global` 声明变量来自模块全局作用域
- `nonlocal` 声明变量来自外层函数作用域
- 两者都是改变变量绑定位置
- 不建议大量使用，会降低代码可读性

**面试口语：**

`global` 用来修改全局变量，`nonlocal` 用来修改外层函数里的变量。闭包里如果需要修改外层函数变量，一般用 `nonlocal`。

### 9. 🔥 闭包和 late binding

**简要总结：**

- 闭包是内部函数引用外部函数变量
- 外部函数执行完后，变量仍然被内部函数持有
- Python 闭包中容易出现 late binding
- late binding 是变量在函数调用时才取值

**面试口语：**

闭包就是内部函数能记住外层函数的变量。Python 里要注意 late binding，比如循环里创建函数，函数真正执行时拿到的可能是循环结束后的变量值。

```python
funcs = []

for i in range(3):
    funcs.append(lambda i=i: i)

print([fn() for fn in funcs])  # [0, 1, 2]
```

⚠️ 注意：用默认参数 `i=i` 可以把当前循环值提前绑定住。

### 10. 🔥 函数参数

**简要总结：**

- 位置参数
- 默认参数
- 可变位置参数：`*args`
- 可变关键字参数：`**kwargs`
- 仅限关键字参数

**面试口语：**

`*args` 用来接收多个位置参数，结果是元组；`**kwargs` 用来接收多个关键字参数，结果是字典。它们常用于封装装饰器、转发参数或写通用接口。

### 11. 🔥 默认参数为什么不要用可变对象

**简要总结：**

- 默认参数在函数定义时创建
- 多次调用会复用同一个默认对象
- 可变默认参数可能导致数据串在一起
- 通常用 `None` 作为默认值，再在函数内部创建对象

**面试口语：**

Python 默认参数是在函数定义时创建的，不是每次调用都创建。如果默认参数是列表，多次调用会共享同一个列表，所以一般用 `None` 做默认值。

```python
def add_item(item, items=None):
    if items is None:
        items = []

    items.append(item)
    return items
```

### 12. ⭐ lambda / map / filter / reduce

**简要总结：**

- `lambda`：匿名函数，适合简单表达式
- `map`：对每个元素做映射
- `filter`：筛选满足条件的元素
- `reduce`：把序列累计成一个结果

**面试口语：**

`lambda` 适合写很短的匿名函数。`map` 是映射，`filter` 是过滤，`reduce` 是累计。Python 中很多场景也可以用列表推导式替代，可读性更好。

💡 提示：业务代码里不要为了函数式写法牺牲可读性。

### 13. ⭐ 推导式和切片

**简要总结：**

- 列表推导式：生成列表
- 集合推导式：生成集合并去重
- 字典推导式：生成键值对
- 切片语法：`seq[start:end:step]`
- 切片通常会返回新对象

**面试口语：**

推导式适合把简单循环转换成更简洁的表达式。切片可以快速截取序列，支持开始位置、结束位置和步长，常用来复制列表、反转字符串等。

```python
nums = [1, 2, 3, 4]
print(nums[1:3])   # [2, 3]
print(nums[::-1])  # [4, 3, 2, 1]
```

### 14. 🔥 哈希 / dict / set 底层

**简要总结：**

- 哈希是把对象映射成整数散列值
- 可哈希对象才能作为 `dict` 的 key
- 可哈希对象通常要求不可变，且实现稳定的 `__hash__`
- `dict` 和 `set` 底层都基于哈希表
- 平均查找复杂度通常是 `O(1)`

**面试口语：**

字典和集合底层主要依赖哈希表。查找 key 时先计算 hash，再定位到对应位置，所以平均查找效率很高。列表不能作为字典 key，是因为列表可变，hash 不稳定。

⚠️ 注意：哈希冲突时，底层会通过冲突解决策略继续查找，并不代表 key 一定丢失。

### 15. 🔥 异常处理

**简要总结：**

- `try`：可能出错的代码
- `except`：捕获异常
- `else`：没有异常时执行
- `finally`：无论是否异常都会执行
- `raise`：主动抛出异常
- `assert`：用于调试断言，不适合业务校验

**面试口语：**

异常处理流程是先执行 `try`，如果出错进入对应的 `except`，没有出错会执行 `else`，最后无论是否异常都会执行 `finally`。业务中自定义异常通常继承 `Exception`。

### 16. 🔥 with 和上下文管理器

**简要总结：**

- `with` 用来管理资源申请和释放
- 常用于文件、锁、数据库连接
- 进入时调用 `__enter__`
- 退出时调用 `__exit__`
- 即使发生异常，也会执行退出逻辑

**面试口语：**

上下文管理器主要解决资源自动释放问题。比如打开文件后，不管中间是否报错，`with` 都能保证退出时执行清理逻辑。

```python
with open('demo.txt', 'r', encoding='utf-8') as file:
    content = file.read()
```

## 面向对象

### 1. 🔥 面向对象核心特性

**简要总结：**

- 封装：把数据和行为组织在类中
- 继承：复用和扩展已有类
- 多态：不同对象对同一操作有不同行为
- Python 更强调鸭子类型

**面试口语：**

Python 支持封装、继承和多态。它的多态很多时候不是靠严格接口实现，而是看对象有没有需要的方法，也就是鸭子类型。

### 2. 🔥 类属性、实例属性和 self

**简要总结：**

- 类属性属于类，所有实例共享
- 实例属性属于具体实例
- `self` 是当前实例对象
- 方法调用时，实例会自动作为第一个参数传入

**面试口语：**

`self` 本质就是当前实例。实例方法定义时第一个参数写 `self`，调用时 Python 会自动把实例传进去。类属性是共享的，实例属性是每个对象自己的。

### 3. ⭐ 实例方法 / classmethod / staticmethod

**简要总结：**

- 实例方法：第一个参数是 `self`
- 类方法：第一个参数是 `cls`
- 静态方法：不自动传 `self` 或 `cls`
- 类方法常用于工厂方法
- 静态方法常用于和类相关的工具函数

**面试口语：**

实例方法操作实例状态，类方法操作类本身，静态方法只是放在类命名空间下的普通函数。需要访问实例用实例方法，需要访问类用类方法，都不需要就用静态方法。

### 4. ⭐ property

**简要总结：**

- `@property` 可以把方法当属性访问
- 可以配合 setter 做赋值校验
- 底层基于描述符协议
- 常用于封装内部字段

**面试口语：**

`property` 让方法使用起来像属性一样，可以在不改变调用方式的情况下增加校验或计算逻辑。它底层其实是描述符。

### 5. 🔥 继承、MRO 和 super

**简要总结：**

- Python 支持单继承和多继承
- MRO 是方法解析顺序
- Python 使用 C3 线性化算法计算 MRO
- `super()` 按 MRO 查找下一个类
- `super()` 不一定等于“直接父类”

**面试口语：**

多继承时，Python 需要确定方法查找顺序，这就是 MRO。`super()` 会根据 MRO 找下一个类，不是简单调用父类。C3 线性化主要是保证继承顺序一致且避免菱形继承混乱。

📌 重点记忆：看 MRO 可以用 `ClassName.__mro__`。

### 6. ⭐ 鸭子类型和多态

**简要总结：**

- 鸭子类型关注对象行为，不关注具体类型
- 只要对象有需要的方法，就可以被使用
- Python 多态经常通过鸭子类型体现

**面试口语：**

鸭子类型就是“像鸭子一样走路和叫，那就可以当鸭子用”。在 Python 里，函数通常不关心对象具体属于哪个类，只关心它有没有需要的方法。

### 7. ⭐ 封装和名称改写

**简要总结：**

- `_name`：约定为内部使用
- `__name`：触发名称改写 Name Mangling
- `__name` 会被改成 `_ClassName__name`
- Python 的私有更多是约定，不是绝对限制

**面试口语：**

Python 里单下划线表示约定上的内部属性，双下划线会触发名称改写，主要用于避免子类属性覆盖父类属性，并不是真正无法访问。

### 8. ⭐ 抽象类和接口

**简要总结：**

- `abc` 模块可以定义抽象基类
- `@abstractmethod` 定义抽象方法
- 子类必须实现抽象方法才能实例化
- Python 中接口也常用 Protocol 或鸭子类型表达

**面试口语：**

抽象类用于规定子类必须实现哪些方法。Python 也可以通过鸭子类型或 `Protocol` 表达接口，实际项目里看是否需要强约束。

### 9. ⭐ dataclass

**简要总结：**

- `dataclass` 用来简化数据类
- 自动生成 `__init__`、`__repr__`、`__eq__` 等方法
- 适合只承载数据的类
- 支持默认值、不可变配置、排序等

**面试口语：**

`dataclass` 适合定义数据结构，能自动生成初始化、打印和比较等方法，比普通 class 少写很多样板代码。

```python
from dataclasses import dataclass

@dataclass
class User:
    id: int
    name: str
```

### 10. 💡 __slots__

**简要总结：**

- 限制实例可以拥有的属性
- 避免每个实例创建 `__dict__`
- 大量实例场景下可以减少内存
- 灵活性会下降

**面试口语：**

`__slots__` 可以限制对象属性，并减少实例字典带来的内存开销。如果一个类会创建大量实例，且属性固定，可以考虑使用。

## 魔术方法和对象模型

### 1. 🔥 __new__ 和 __init__

**简要总结：**

- `__new__` 负责创建对象
- `__init__` 负责初始化对象
- 先执行 `__new__`，再执行 `__init__`
- `__new__` 返回实例后，才会调用 `__init__`

**面试口语：**

`__new__` 是创建对象的方法，`__init__` 是初始化对象的方法。大多数时候只写 `__init__`，只有控制对象创建过程时才需要重写 `__new__`。

### 2. ⭐ 常见魔术方法

**简要总结：**

- `__str__`：面向用户的字符串表示
- `__repr__`：面向开发者的字符串表示
- `__len__`：支持 `len()`
- `__call__`：让对象可调用
- `__iter__` / `__next__`：支持迭代协议
- `__enter__` / `__exit__`：支持上下文管理器

**面试口语：**

魔术方法是 Python 对象模型的扩展点。比如 `len(obj)` 实际会调用 `obj.__len__()`，`with obj` 会调用 `__enter__` 和 `__exit__`。

### 3. 🔥 属性访问过程

**简要总结：**

- `__getattribute__` 会拦截几乎所有属性访问
- 属性不存在时才会调用 `__getattr__`
- `__setattr__` 拦截属性赋值
- 描述符优先级会影响属性查找

**面试口语：**

访问属性时，Python 会先走 `__getattribute__`。如果找不到属性，才会调用 `__getattr__`。所以重写 `__getattribute__` 要非常谨慎，否则容易递归调用。

⚠️ 注意：在 `__getattribute__` 里访问属性时，通常要用 `object.__getattribute__` 避免无限递归。

### 4. 🔥 描述符 Descriptor

**简要总结：**

- 实现 `__get__`、`__set__`、`__delete__` 中任意方法的对象就是描述符
- 数据描述符：实现 `__set__` 或 `__delete__`
- 非数据描述符：只实现 `__get__`
- `property`、函数绑定方法、ORM 字段都和描述符有关

**面试口语：**

描述符是 Python 属性访问机制的核心。只要一个对象实现了 `__get__`、`__set__` 或 `__delete__`，它就可以控制另一个对象属性的读取、赋值和删除。

📌 重点记忆：`property` 本质就是描述符。

## 迭代器与生成器

### 1. 🔥 Iterable 和 Iterator

**简要总结：**

- Iterable：可迭代对象，实现 `__iter__`
- Iterator：迭代器，实现 `__iter__` 和 `__next__`
- `iter()` 获取迭代器
- `next()` 获取下一个值
- 迭代结束抛出 `StopIteration`

**面试口语：**

可迭代对象是能被 `for` 遍历的对象，迭代器是真正负责一个个产出值的对象。`for` 循环底层就是先调用 `iter()`，再不断调用 `next()`。

### 2. 🔥 生成器

**简要总结：**

- 包含 `yield` 的函数会变成生成器函数
- 调用生成器函数不会立即执行函数体
- 每次 `next()` 执行到下一个 `yield`
- 生成器按需产出数据，更节省内存

**面试口语：**

生成器是一种特殊迭代器，可以用 `yield` 暂停和恢复函数执行。它不会一次性把所有数据放进内存，而是用到一个产出一个，所以适合大文件读取、分页数据、无限序列等场景。

```python
def count():
    i = 0

    while True:
        yield i
        i += 1
```

### 3. ⭐ yield from

**简要总结：**

- 可以把子生成器的值直接交给外层生成器产出
- 简化嵌套迭代代码
- 也可以用于生成器之间传值

**面试口语：**

`yield from` 可以把一个可迭代对象里的值逐个产出，相当于帮我们写了一层循环，常用于组合多个生成器。

### 4. ⭐ 生成器表达式和列表推导式

**简要总结：**

- 列表推导式立即生成完整列表
- 生成器表达式按需计算
- 数据量大时生成器表达式更省内存
- 需要多次遍历时列表更合适

**面试口语：**

列表推导式会一次性生成所有结果，生成器表达式是惰性计算，用到时才产出值。如果数据量很大，生成器表达式更节省内存。

## 装饰器

### 1. 🔥 装饰器原理

**简要总结：**

- 装饰器本质是高阶函数
- 接收函数作为参数
- 返回一个增强后的函数
- 常用于日志、权限、缓存、统计耗时

**面试口语：**

装饰器本质是一个函数，它接收原函数，返回一个新函数。调用新函数时，可以在原函数执行前后增加逻辑，但不修改原函数源码。

```python
import functools

def log(func):
    @functools.wraps(func)
    def wrapper(*args, **kwargs):
        print(f'call {func.__name__}')
        return func(*args, **kwargs)

    return wrapper
```

### 2. ⭐ 带参数的装饰器

**简要总结：**

- 外层函数接收装饰器参数
- 中层函数接收被装饰函数
- 内层函数接收原函数调用参数

**面试口语：**

带参数的装饰器比普通装饰器多包一层。最外层接收配置参数，中间层接收原函数，最内层才是真正执行时调用的 wrapper。

### 3. ⭐ 多个装饰器执行顺序

**简要总结：**

- 装饰时：从下往上包裹
- 执行时：从上往下进入
- 写法类似函数嵌套

**面试口语：**

多个装饰器时，离函数最近的装饰器最先装饰原函数；真正执行时，最外层装饰器先进入，最后才执行原函数。

### 4. 🔥 functools.wraps

**简要总结：**

- 保留原函数的 `__name__`
- 保留原函数的 `__doc__`
- 保留原函数的元信息
- 避免调试、日志、框架注册时出现 wrapper 名称

**面试口语：**

`wraps` 的作用是把原函数的元信息复制到 wrapper 上。如果不用它，被装饰后的函数名字会变成 `wrapper`，可能影响调试和一些框架的函数识别。

## 内存管理与垃圾回收

### 1. 🔥 内存管理机制

**简要总结：**

- Python 对象主要分配在堆上
- 变量保存的是对象引用
- CPython 主要使用引用计数管理对象生命周期
- 循环引用由垃圾回收器处理

**面试口语：**

Python 的变量本质上是对象引用。CPython 中对象主要靠引用计数释放，引用计数变成 0 时对象会被回收。但循环引用的对象引用计数可能不为 0，所以还需要 GC。

### 2. 🔥 引用计数和 GC

**简要总结：**

- 每个对象记录被引用次数
- 新增引用时计数加 1
- 引用删除时计数减 1
- 计数为 0 时对象释放
- 循环引用需要 GC 处理

**面试口语：**

引用计数的优点是简单、回收及时；缺点是处理不了循环引用。Python 的分代 GC 会定期扫描容器对象，找出不可达的循环引用并清理。

### 3. ⭐ del / id / 对象释放

**简要总结：**

- `del` 删除的是变量名或容器中的引用
- `del` 不一定马上删除对象
- 只有对象引用计数为 0 时才会释放
- `id()` 返回对象身份标识，CPython 中通常可理解为内存地址

**面试口语：**

`del` 删除的是引用，不是直接删除对象。如果这个对象还有其他变量引用它，它仍然存在。只有引用计数归零时，对象才会真正释放。

### 4. 💡 小整数缓存和字符串驻留

**简要总结：**

- CPython 会缓存一部分小整数对象
- 一些字符串会被驻留复用
- 这可能导致两个变量 `is` 判断为 `True`
- 不应该依赖这些实现细节写业务逻辑

**面试口语：**

小整数缓存和字符串驻留是 CPython 的优化。它们可能让两个值相同的变量指向同一个对象，但这是实现细节，比较值还是应该用 `==`。

### 5. ⭐ 内存泄漏排查

**简要总结：**

- 常见原因：全局缓存、循环引用、未关闭资源、长生命周期对象持有引用
- 常用工具：`tracemalloc`、`gc`、`objgraph`
- 排查方向：看对象数量是否持续增长，找引用链

**面试口语：**

Python 内存泄漏通常不是对象完全无法回收，而是还有引用链持有它。排查时可以用 `tracemalloc` 看内存分配位置，用 `gc` 或 `objgraph` 找对象引用关系。

## GIL 与并发基础

### 1. 🔥 GIL

**简要总结：**

- GIL 是全局解释器锁
- CPython 中同一时刻只有一个线程执行 Python 字节码
- GIL 简化了内存管理和 C 扩展安全问题
- GIL 会限制 CPU 密集型多线程性能

**面试口语：**

GIL 是 CPython 的全局解释器锁，它保证同一时刻只有一个线程执行 Python 字节码。所以 CPU 密集型任务用多线程通常不能充分利用多核，但 IO 密集型任务仍然可以受益。

📌 重点记忆：GIL 限制的是 CPython 多线程执行 Python 字节码，不代表 Python 完全不能并发。

### 2. 🔥 CPU 密集型和 IO 密集型

**简要总结：**

- CPU 密集型：大量计算，瓶颈在 CPU
- IO 密集型：网络、磁盘、数据库等等待多
- CPU 密集型适合多进程
- IO 密集型适合多线程或异步 IO

**面试口语：**

CPU 密集型任务主要消耗计算资源，适合用多进程绕开 GIL；IO 密集型任务大量时间在等待外部资源，多线程或 asyncio 都能提升吞吐。

### 3. ⭐ 多线程和多进程

**简要总结：**

- 线程共享进程内存
- 进程之间内存隔离
- 线程切换开销小，但要注意线程安全
- 进程能利用多核，但创建和通信成本更高

**面试口语：**

多线程适合 IO 密集型任务，因为线程之间共享内存，通信方便；多进程适合 CPU 密集型任务，可以利用多核，但进程之间内存隔离，通信成本更高。

### 4. 🔥 线程安全、竞态条件和锁

**简要总结：**

- 多线程同时访问共享数据可能产生竞态条件
- `Lock`：普通互斥锁
- `RLock`：可重入锁，同一线程可重复获取
- `Semaphore`：限制同时访问资源的线程数量
- 死锁通常来自多个锁互相等待

**面试口语：**

线程安全问题通常发生在多个线程同时读写共享数据时。可以用锁保护临界区，但锁使用不当可能造成死锁，比如两个线程互相等待对方持有的锁。

### 5. ⭐ ThreadPoolExecutor 和 ProcessPoolExecutor

**简要总结：**

- `ThreadPoolExecutor`：线程池，适合 IO 密集型
- `ProcessPoolExecutor`：进程池，适合 CPU 密集型
- 池化可以复用线程或进程，减少创建销毁成本

**面试口语：**

线程池适合发请求、读写文件、数据库访问这类 IO 任务；进程池适合图片处理、数据计算这类 CPU 任务。选择时主要看瓶颈在等待还是计算。

## 异步编程

### 1. 🔥 同步、异步、并发、并行

**简要总结：**

- 同步：任务按顺序执行，一个完成后再执行下一个
- 异步：发起任务后不阻塞等待结果
- 并发：多个任务交替推进
- 并行：多个任务真正同时执行

**面试口语：**

并发强调一段时间内处理多个任务，不一定同时执行；并行强调同一时刻多个任务真的在同时执行。asyncio 是单线程并发，不是多线程并行。

### 2. 🔥 async / await 和协程

**简要总结：**

- `async def` 定义协程函数
- 调用协程函数会返回 coroutine 对象
- `await` 用来挂起当前协程，等待异步结果
- 协程由事件循环调度

**面试口语：**

协程是用户态的轻量级并发单位。执行到 `await` 时，当前协程会让出控制权，事件循环可以去执行其他任务，等等待的 IO 完成后再恢复执行。

### 3. 🔥 Event Loop

**简要总结：**

- 事件循环负责调度协程任务
- 遇到 IO 等待时挂起当前任务
- IO 就绪后恢复对应任务
- 单线程内通过任务切换实现高并发

**面试口语：**

asyncio 的事件循环就是一个调度器。它会运行就绪任务，任务遇到 `await` 时让出执行权，事件循环再去执行其他任务，等 IO 完成后再回来继续执行。

### 4. ⭐ coroutine / Task / Future

**简要总结：**

- coroutine：协程对象，只是可等待任务的描述
- Task：把 coroutine 包装后交给事件循环调度
- Future：表示一个未来会完成的结果
- `asyncio.create_task()` 会创建并调度 Task

**面试口语：**

协程对象本身不会自动并发执行，需要交给事件循环。`create_task` 会把协程包装成 Task 并安排执行，Future 更偏底层，用来表示未来某个结果。

### 5. ⭐ gather 和 wait

**简要总结：**

- `asyncio.gather()` 聚合多个 awaitable 的结果
- 返回结果顺序和传入顺序一致
- `asyncio.wait()` 返回已完成和未完成任务集合
- `wait` 更适合控制超时和任务状态

**面试口语：**

`gather` 更适合并发执行多个任务并收集结果；`wait` 更底层一些，会返回完成和未完成的任务集合，适合需要自己控制任务状态的场景。

### 6. 🔥 异步中不能随便调用阻塞函数

**简要总结：**

- 阻塞函数会卡住事件循环
- 事件循环被卡住后，其他协程也无法推进
- 同步数据库驱动、`time.sleep`、CPU 大计算都可能阻塞
- 可以用异步驱动或线程池处理阻塞任务

**面试口语：**

异步接口里如果调用阻塞函数，会把整个事件循环卡住，导致其他请求也不能执行。所以 FastAPI 异步接口里应该使用异步数据库驱动，或者把阻塞任务丢到线程池执行。

## 高级函数与函数式特性

### 1. ⭐ 高阶函数和偏函数

**简要总结：**

- 高阶函数：接收函数作为参数，或返回函数
- 偏函数：提前固定一部分参数
- `functools.partial` 可以创建偏函数

**面试口语：**

高阶函数体现了 Python 函数是一等公民，函数可以像普通对象一样传递。偏函数则是先固定一部分参数，得到一个更具体的新函数。

### 2. ⭐ lru_cache

**简要总结：**

- `functools.lru_cache` 用于缓存函数结果
- 相同参数再次调用直接返回缓存
- LRU 表示最近最少使用淘汰
- 适合纯函数、递归、重复查询场景

**面试口语：**

`lru_cache` 可以缓存函数调用结果，避免相同参数重复计算。它适合无副作用、返回值只由参数决定的函数，比如递归计算或字典类查询。

⚠️ 注意：参数必须可哈希，且不要缓存会频繁变化的外部状态。

### 3. ⭐ 闭包和对象保存状态

**简要总结：**

- 闭包适合保存少量私有状态
- 对象适合保存复杂状态和多个行为
- 闭包更轻量
- 类更清晰、可扩展性更好

**面试口语：**

闭包和对象都能保存状态。简单计数、装饰器这类场景用闭包很方便；如果状态复杂、行为很多，用类会更清晰。

## 元类与高级对象机制

### 1. 🔥 一切皆对象和 type

**简要总结：**

- Python 中函数、类、模块都是对象
- 类本身也是对象
- `type(obj)` 可以查看对象类型
- `type(name, bases, namespace)` 可以动态创建类
- 类默认由 `type` 创建

**面试口语：**

Python 里类本身也是对象，而创建类的“类”叫元类。默认情况下，类是由 `type` 创建出来的，所以 `type` 既能查看类型，也能动态创建类。

### 2. 💡 元类 Metaclass

**简要总结：**

- 元类是创建类的类
- 可以控制类的创建过程
- 常用于 ORM、框架注册、类属性校验
- 普通业务代码不建议滥用

**面试口语：**

元类可以拦截类的创建过程，在类创建时自动收集字段、注册类或修改类属性。ORM 经常用元类把模型类里的字段收集成表结构映射。

📌 重点记忆：对象由类创建，类由元类创建。

### 3. 💡 __init_subclass__

**简要总结：**

- 子类创建时自动调用
- 可以用于校验子类、自动注册子类
- 比元类更轻量
- 很多场景可以替代简单元类

**面试口语：**

`__init_subclass__` 会在子类定义完成时触发，适合做插件注册、子类约束检查等逻辑。相比元类，它更简单，也更容易维护。

## 模块、包与导入机制

### 1. 🔥 模块和包

**简要总结：**

- 一个 `.py` 文件就是一个模块
- 包是包含模块的目录
- 传统包通常有 `__init__.py`
- `__init__.py` 可用于包初始化和导出控制

**面试口语：**

模块是 Python 代码组织的基本单位，包是模块的集合。`__init__.py` 表示这个目录是包，也可以在里面做包初始化或统一导出。

### 2. 🔥 import 执行过程

**简要总结：**

- 先检查 `sys.modules` 是否已有缓存
- 没有缓存则按 `sys.path` 查找模块
- 找到后执行模块代码
- 创建模块对象并缓存到 `sys.modules`
- 后续重复导入不会再次执行模块顶层代码

**面试口语：**

Python 导入模块时会先看 `sys.modules`。如果已经导入过，就直接复用缓存；如果没有，就按搜索路径查找并执行模块代码，然后放进缓存。

📌 重点记忆：模块第一次导入会执行顶层代码，重复导入通常不会重复执行。

### 3. ⭐ 绝对导入和相对导入

**简要总结：**

- 绝对导入从项目或环境搜索路径开始查找
- 相对导入用 `.` 表示当前包
- 相对导入更依赖包结构
- 项目中优先保持导入路径清晰一致

**面试口语：**

绝对导入路径更清晰，适合大多数项目。相对导入适合同一个包内部模块之间引用，但层级太深时可读性会下降。

### 4. 🔥 循环导入

**简要总结：**

- A 导入 B，B 又导入 A
- 可能拿到未初始化完成的模块
- 常见解决：调整模块职责、延迟导入、抽公共模块
- 根因通常是模块之间耦合过高

**面试口语：**

循环导入的问题在于模块第一次导入时会执行顶层代码，如果两个模块互相依赖，可能某个模块还没初始化完成就被另一个模块使用了。解决方式通常是拆公共依赖或把导入放到函数内部延迟执行。

### 5. ⭐ if __name__ == "__main__"

**简要总结：**

- 文件直接执行时，`__name__` 是 `"__main__"`
- 文件被导入时，`__name__` 是模块名
- 常用于区分脚本执行和模块导入

**面试口语：**

这段判断用来保证某些代码只在文件被直接运行时执行，被其他模块导入时不会执行，常用于脚本入口或简单测试代码。

### 6. 💡 pyproject.toml

**简要总结：**

- 现代 Python 项目的标准配置文件
- 可以配置构建系统、项目元信息、依赖、工具配置
- 常见工具：Poetry、PDM、Hatch、uv

**面试口语：**

`pyproject.toml` 是现代 Python 项目的统一配置入口，可以放项目元信息、构建配置、依赖管理和格式化、类型检查等工具配置。

## 类型注解与现代 Python

### 1. 🔥 类型注解作用

**简要总结：**

- 提升代码可读性
- 帮助 IDE 自动补全
- 配合 mypy、pyright 做静态检查
- FastAPI 等框架会利用类型注解做参数解析和文档生成
- 默认不会在运行时强制校验

**面试口语：**

Python 是动态语言，类型注解不会默认强制运行时校验，但它能提升可维护性，帮助 IDE 和静态检查工具发现问题。在 FastAPI 里，类型注解还会参与请求参数解析和接口文档生成。

### 2. 🔥 Optional / Union / Literal

**简要总结：**

- `Union[A, B]`：可以是 A 或 B
- `A | B`：Python 3.10+ 的联合类型写法
- `Optional[T]` 等价于 `T | None`
- `Literal` 限制只能取固定字面量值

**面试口语：**

`Union` 表示一个值可能有多种类型，`Optional` 表示可能为 `None`，`Literal` 用来限制固定取值，比如状态只能是几个字符串之一。

```python
from typing import Literal

Status = Literal['pending', 'success', 'error']
```

### 3. ⭐ TypeVar 和泛型

**简要总结：**

- `TypeVar` 定义类型变量
- 泛型可以保留输入和输出之间的类型关系
- 常用于通用函数、容器、仓储类、分页响应

**面试口语：**

泛型的价值是复用逻辑的同时保留具体类型。比如写一个通用函数，传入字符串就返回字符串，传入数字就返回数字，这种关系可以用泛型表达。

```python
from typing import TypeVar

T = TypeVar('T')

def first(items: list[T]) -> T:
    return items[0]
```

### 4. ⭐ Protocol 和结构化子类型

**简要总结：**

- `Protocol` 用来描述对象需要具备的行为
- 不要求显式继承
- 只要结构匹配，就被认为满足协议
- 更接近鸭子类型的静态类型表达

**面试口语：**

`Protocol` 可以把鸭子类型写进类型系统。一个对象不需要继承某个父类，只要有协议要求的方法，就能被类型检查器认为符合要求。

### 5. ⭐ TypedDict

**简要总结：**

- 用来描述字典结构
- 可以约束 key 和 value 的类型
- 适合 JSON、接口响应、配置字典
- 比普通 `dict[str, Any]` 更精确

**面试口语：**

`TypedDict` 适合给字典形状加类型，比如接口返回的 JSON。它可以约束有哪些 key，每个 key 对应什么类型。

### 6. ⭐ Any 和 object

**简要总结：**

- `Any` 会关闭类型检查
- `object` 表示所有对象的基类
- `object` 使用前通常需要类型收窄
- 不确定类型时优先考虑 `unknown` 的思路，在 Python 中可用 `object` 加判断

**面试口语：**

`Any` 表示类型检查器别管了，任何操作都允许；`object` 表示它可以是任意对象，但你不能随便调用具体方法，使用前需要先判断类型。所以 `object` 比 `Any` 更安全。

### 7. ⭐ NamedTuple / dataclass / 普通 class

**简要总结：**

- `NamedTuple`：不可变、轻量、像元组
- `dataclass`：适合数据类，自动生成常用方法
- 普通 class：最灵活，适合有复杂行为的对象

**面试口语：**

如果只是不可变的数据结构，可以用 `NamedTuple`；如果是普通数据对象，用 `dataclass` 很方便；如果对象有复杂行为、继承或生命周期逻辑，就用普通 class。

### 第一优先级

- 🔥 `is` 和 `==`
- 🔥 浅拷贝和深拷贝
- 🔥 参数传递机制
- 🔥 LEGB 和闭包
- 🔥 默认可变参数
- 🔥 `dict` / `set` 底层原理
- 🔥 装饰器原理
