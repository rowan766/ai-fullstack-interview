## 测试基础

### 1. 🔥 为什么需要测试

**简要总结：**

- 防止回归
- 支撑重构
- 保证核心业务稳定
- 降低人工回归成本
- CI 中形成质量门禁

**面试口语：**

测试的价值不是为了覆盖率好看，而是把核心业务规则固化下来。尤其是支付、权限、订单状态流转这类逻辑，有测试才能放心重构。

**底层原理 / 背后逻辑：**

测试本质是可重复执行的行为验证。输入固定数据，执行目标代码，断言输出或副作用是否符合预期。后端测试尤其要关注数据库、缓存、外部接口这些边界，因为很多 bug 出在集成处。

### 2. 🔥 pytest

**简要总结：**

- Python 常用测试框架
- 测试函数以 `test_` 开头
- 使用 assert 断言
- fixture 管理测试依赖
- 插件生态丰富

**面试口语：**

pytest 写法简洁，直接用 assert 断言。它的 fixture 很强，可以用来准备数据库、客户端、登录用户等测试依赖。

```python
def add(a: int, b: int) -> int:
    return a + b

def test_add():
    assert add(1, 2) == 3
```

### 3. 🔥 fixture

**简要总结：**

- 用于准备和清理测试资源
- 可以控制作用域：function、module、session
- 可以复用测试数据
- yield 后写清理逻辑

**面试口语：**

fixture 就是测试依赖管理。比如每个测试都需要数据库连接或测试客户端，就可以写成 fixture，避免重复准备。

```python
import pytest

@pytest.fixture
def user():
    return {"id": 1, "name": "Tom"}

def test_user_name(user):
    assert user["name"] == "Tom"
```

**底层原理 / 背后逻辑：**

pytest 会根据测试函数参数名查找同名 fixture，先执行 fixture 得到结果，再注入测试函数。fixture 可以依赖其他 fixture，因此能组成依赖图。使用 `yield` 时，yield 前是准备逻辑，yield 后是清理逻辑。

### 4. 🔥 Mock

**简要总结：**

- 替换外部依赖
- 常用于 HTTP、邮件、支付、时间、随机数
- 让测试更快更稳定
- 避免过度 Mock

**面试口语：**

Mock 是为了隔离不可控依赖。比如测试下单逻辑时，不应该真的调用支付接口，而是 Mock 支付服务返回成功或失败。

```python
from unittest.mock import Mock

def test_pay_success():
    payment = Mock()
    payment.charge.return_value = {"status": "success"}

    result = create_order(payment)

    assert result["paid"] is True
```

### 5. ⭐ monkeypatch

**简要总结：**

- pytest 提供的动态替换工具
- 可替换函数、环境变量、属性
- 测试结束后自动恢复

**面试口语：**

monkeypatch 适合临时替换环境变量、函数或对象属性。它比手动改全局变量更安全，因为测试结束会自动恢复。

```python
def test_env(monkeypatch):
    monkeypatch.setenv("APP_ENV", "test")
    assert get_env() == "test"
```

### 6. 🔥 FastAPI 接口测试

**简要总结：**

- 使用 TestClient 测试接口
- 可以覆盖路由、参数校验、响应格式
- 可替换依赖
- 不一定要启动真实服务

**面试口语：**

FastAPI 测试可以用 TestClient，不需要真正启动 uvicorn。它能直接请求 app，验证状态码和响应数据。

```python
from fastapi.testclient import TestClient

client = TestClient(app)

def test_health():
    response = client.get("/health")

    assert response.status_code == 200
    assert response.json() == {"status": "ok"}
```

### 7. ⭐ 数据库测试

**简要总结：**

- 使用测试数据库
- 每个用例后回滚或清理数据
- 避免污染开发和生产数据
- 测试数据要可重复

**面试口语：**

数据库测试一定要隔离环境，不能连生产库。常见做法是使用测试库，每个测试事务回滚，或者用 fixture 创建和清理数据。

**底层原理 / 背后逻辑：**

数据库测试的问题是状态会残留。如果一个测试留下的数据影响下一个测试，测试就会变得不稳定。事务回滚、临时库、容器数据库都是为了解决测试隔离。

### 8. ⭐ 覆盖率和 CI

**简要总结：**

- coverage 统计代码执行情况
- 覆盖率高不等于测试质量高
- CI 中运行 lint、type check、test
- 核心分支可设置覆盖率阈值

**面试口语：**

覆盖率是参考指标，不是最终目标。高覆盖率只能说明代码执行过，关键还要看断言是否有效、核心路径是否覆盖。

```bash
pytest --cov=app --cov-report=term-missing
```

```yaml
steps:
  - run: ruff check .
  - run: mypy app
  - run: pytest --cov=app
```
