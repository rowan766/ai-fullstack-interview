# LLM 基础

> 图标说明：⭐ 重点｜🔥 高频｜⚠️ 注意｜💡 提示｜📌 重点记忆

## LLM 基础概念

### 1. 🔥 什么是 LLM

**简要总结：**

- LLM 是 Large Language Model，大语言模型
- 通过大规模文本数据训练，学习语言规律和知识模式
- 核心能力包括文本生成、问答、总结、翻译、代码生成、推理等
- 现代 LLM 大多基于 Transformer 架构

**面试口语：**

大语言模型可以理解成在海量文本上训练出来的生成式模型。它输入一段上下文，然后预测接下来最可能出现的 Token，因此可以完成对话、写作、总结、代码生成等任务。

📌 重点记忆：LLM 的基础目标通常是“根据上下文预测下一个 Token”。

### 2. 🔥 LLM 和传统 NLP 模型区别

**简要总结：**

- 传统 NLP 通常针对单一任务训练，比如分类、分词、NER
- LLM 是通用模型，可以通过 Prompt 适配多种任务
- LLM 具有更强的上下文学习能力和生成能力
- LLM 参数量、训练数据、计算成本都更大

**面试口语：**

传统 NLP 模型通常是一个任务训练一个模型，而 LLM 更像通用语言能力底座。它可以通过 Prompt、少样本示例或指令微调完成很多任务，不一定每个任务都重新训练模型。

### 3. ⭐ Base Model / Chat Model / Instruction Model

**简要总结：**

- Base Model：预训练基础模型，主要学语言建模能力
- Instruction Model：经过指令微调，更会按任务要求回答
- Chat Model：面向多轮对话优化，通常有角色模板
- Base Model 不适合直接做聊天机器人

**面试口语：**

Base Model 是基础模型，主要会续写文本；Instruction Model 经过指令数据训练，能更好理解任务；Chat Model 进一步面向对话场景优化，能处理 system、user、assistant 这类消息角色。

⚠️ 注意：同一个模型系列里，Base 和 Chat 版本的用法、提示模板和输出风格可能不一样。

## Transformer 架构

### 1. 🔥 Transformer 是什么

**简要总结：**

- Transformer 是一种基于 Attention 的神经网络架构
- 核心组件包括 Embedding、Position Encoding、Multi-Head Attention、FFN、LayerNorm、Residual
- 相比 RNN / LSTM，Transformer 更适合并行训练
- GPT、BERT 等模型都基于 Transformer

**面试口语：**

Transformer 是现在大模型的核心架构。它不再像 RNN 那样按顺序处理文本，而是通过 Self-Attention 让每个 Token 和上下文中的其他 Token 建立关系，因此训练并行度更高，也更擅长捕捉长距离依赖。

### 2. 🔥 Encoder / Decoder / GPT / BERT

**简要总结：**

- Encoder：更适合理解任务，比如分类、检索、语义表示
- Decoder：更适合生成任务，比如续写、对话、代码生成
- Encoder-Decoder：适合翻译、摘要等输入到输出任务
- BERT 主要是 Encoder 架构
- GPT 主要是 Decoder-only 架构

**面试口语：**

BERT 偏理解，使用 Encoder，可以双向看上下文；GPT 偏生成，使用 Decoder-only，并通过因果 Mask 只能看当前位置之前的内容，所以适合自回归生成。

📌 重点记忆：BERT 双向理解，GPT 单向自回归生成。

### 3. 🔥 自回归模型和因果语言模型

**简要总结：**

- 自回归是一步一步根据前文生成后文
- 当前 Token 的生成依赖之前已经生成的 Token
- 因果语言模型使用 Causal Mask 防止看到未来 Token
- GPT 属于典型自回归语言模型

**面试口语：**

自回归生成就是模型每次预测一个下一个 Token，然后把这个 Token 拼回上下文，再继续预测下一个。为了保证训练和生成一致，GPT 会使用 Causal Mask，让当前位置只能看到前面的内容。

## Token 和 Tokenizer

### 1. 🔥 Token 是什么

**简要总结：**

- Token 是模型处理文本的基本单位
- Token 不一定等于单词，也不一定等于字符
- 英文中一个单词可能拆成多个 Token
- 中文中一个字或词也可能对应不同数量 Token
- 输入和输出 Token 都会影响上下文和成本

**面试口语：**

模型不能直接理解字符串，需要先通过 Tokenizer 把文本切成 Token，再转成数字 ID。Token 可以是一个词、一个词片段、一个汉字，具体取决于模型使用的分词器。

⚠️ 注意：不同模型的 Tokenizer 不同，同一段文本在不同模型里的 Token 数可能不一样。

### 2. ⭐ BPE / WordPiece / SentencePiece

**简要总结：**

- BPE：从字符开始，逐步合并高频片段
- WordPiece：常见于 BERT 系列，目标是找到更合适的子词切分
- SentencePiece：把文本当作原始字符流处理，不强依赖空格
- 中文、英文、代码的 Token 消耗差异很大

**面试口语：**

Tokenizer 的目标是把文本切成模型能处理的子词单元。BPE 会把高频字符片段不断合并，SentencePiece 不依赖天然空格，所以对中文、多语言场景更友好。

### 3. 🔥 Token 数为什么重要

**简要总结：**

- Token 数影响 API 调用成本
- Token 数影响上下文窗口占用
- Token 数影响推理延迟和显存中的 KV Cache
- 输出越长，生成耗时通常越长

**面试口语：**

Token 是大模型计费、上下文限制和推理性能的核心单位。输入和输出都会占用 Token，长文本不仅更贵，也会让模型推理更慢，占用更多显存。

## Embedding 和位置编码

### 1. 🔥 Embedding

**简要总结：**

- Embedding 把 Token ID 转成向量
- 向量能表达 Token 的语义和上下文关系
- Token Embedding 表示词元含义
- Position Embedding 表示位置信息

**面试口语：**

模型内部不能直接处理文字，Tokenizer 会把文本转成 Token ID，Embedding 再把 ID 映射成向量。向量空间里语义相近的内容通常距离也更近。

### 2. 🔥 为什么需要位置编码

**简要总结：**

- Attention 本身不天然知道 Token 顺序
- 位置编码用于注入顺序信息
- 没有位置编码，模型很难区分“我爱你”和“你爱我”
- 位置编码有绝对位置和相对位置等方式

**面试口语：**

Self-Attention 计算的是 Token 之间的关系，但它本身不包含顺序概念，所以 Transformer 需要位置编码告诉模型每个 Token 在序列里的位置。

### 3. ⭐ RoPE

**简要总结：**

- RoPE 是 Rotary Position Embedding，旋转位置编码
- 通过旋转向量的方式注入相对位置信息
- 对长上下文扩展比较友好
- 很多现代大模型采用 RoPE 或其变体

**面试口语：**

RoPE 不是简单给 Token 加一个位置向量，而是通过旋转 Q、K 向量的方式编码相对位置关系。它对长上下文和相对位置建模更友好，所以现代大模型里很常见。

## Attention 机制

### 1. 🔥 Attention 是什么

**简要总结：**

- Attention 用来计算不同 Token 之间的关联程度
- 模型会根据相关性给上下文不同位置分配权重
- 权重越高，表示当前位置越关注对应 Token
- Self-Attention 是同一个序列内部做 Attention

**面试口语：**

Attention 可以理解成模型在生成或理解某个 Token 时，动态判断上下文里哪些 Token 更重要。Self-Attention 就是让一句话里的每个 Token 都和其他 Token 建立关系。

### 2. 🔥 Q / K / V

**简要总结：**

- Query：当前位置想查询什么
- Key：每个位置能提供什么匹配信息
- Value：每个位置真正携带的内容
- Attention Score 由 `QK^T` 计算
- 再经过 Softmax 得到权重

**面试口语：**

Q、K、V 可以类比成检索过程。Query 是当前 Token 的查询，Key 是其他 Token 的索引，Value 是实际内容。模型先用 Query 和 Key 算相关性，再用相关性加权 Value。

📌 重点记忆：Attention 公式常写作 `softmax(QK^T / sqrt(d_k))V`。

### 3. 🔥 为什么除以 sqrt(d_k)

**简要总结：**

- `QK^T` 的值可能随维度增大而变大
- 分数太大会让 Softmax 过于尖锐
- 除以 `sqrt(d_k)` 可以稳定梯度
- 这叫 Scaled Dot-Product Attention

**面试口语：**

如果不缩放，维度越高点积值可能越大，Softmax 后概率会非常集中，梯度变小，不利于训练。所以要除以 `sqrt(d_k)` 稳定数值。

### 4. 🔥 Multi-Head Attention

**简要总结：**

- 多头注意力会并行计算多组 Attention
- 不同 Head 可以关注不同关系
- 有的 Head 关注语法，有的关注实体，有的关注远距离依赖
- 最后把多个 Head 的结果拼接再线性变换

**面试口语：**

多头注意力就是让模型从多个子空间同时看上下文。单个 Attention Head 表达能力有限，多头可以让模型学习不同类型的关系，最后把这些信息融合起来。

### 5. 🔥 Masked Attention / Causal Mask

**简要总结：**

- Mask 用来屏蔽不应该看到的位置
- GPT 使用 Causal Mask 防止当前位置看到未来 Token
- 这样训练时也符合从左到右生成的过程
- Padding Mask 用来忽略补齐 Token

**面试口语：**

GPT 是自回归生成模型，预测当前 Token 时不能看到未来答案，所以要用 Causal Mask 把未来位置遮住。否则训练时模型会偷看后文，生成时就不成立。

## Transformer Block

### 1. 🔥 一个 Transformer Block 包含什么

**简要总结：**

- Multi-Head Attention
- Residual Connection
- LayerNorm
- Feed Forward Network
- 多个 Block 堆叠形成深层模型

**面试口语：**

一个 Transformer Block 通常由注意力层、前馈网络、残差连接和归一化组成。Attention 负责建模 Token 之间的关系，FFN 负责进一步做非线性特征变换。

### 2. ⭐ FFN

**简要总结：**

- FFN 是每个位置独立计算的前馈网络
- 通常先升维再降维
- 引入非线性表达能力
- Attention 混合序列信息，FFN 处理每个 Token 的特征

**面试口语：**

Attention 主要负责让 Token 之间交换信息，FFN 则对每个位置的向量做非线性变换，提升模型表达能力。

### 3. ⭐ LayerNorm 和 Residual

**简要总结：**

- LayerNorm 对单个样本的特征维度做归一化
- Transformer 更常用 LayerNorm，而不是 BatchNorm
- Residual Connection 可以缓解深层网络训练困难
- 残差让梯度更容易向前传播

**面试口语：**

LayerNorm 能稳定每层输入分布，适合变长序列和小 batch 场景。残差连接可以让信息和梯度更顺畅地穿过深层网络，所以深层 Transformer 更容易训练。

## 生成过程和采样参数

### 1. 🔥 下一个 Token 预测

**简要总结：**

- 模型根据上下文输出 logits
- logits 是未归一化分数
- Softmax 把 logits 转成概率分布
- 解码策略从概率分布中选择下一个 Token
- 生成的 Token 会加入上下文继续下一步生成

**面试口语：**

LLM 生成时不是一次生成整段文字，而是一步一步预测下一个 Token。每一步模型输出所有候选 Token 的 logits，经过 Softmax 得到概率，再按解码策略选出下一个 Token。

### 2. 🔥 Greedy / Beam / Sampling

**简要总结：**

- Greedy Search：每次选择概率最高的 Token
- Beam Search：保留多个候选序列
- Sampling：按概率随机采样
- 对话和创作场景更常用 Sampling

**面试口语：**

Greedy 每次选概率最高的 Token，稳定但容易死板。Beam Search 会保留多条候选路径，适合翻译等任务。Sampling 会按概率随机采样，更适合开放式生成。

### 3. 🔥 Temperature

**简要总结：**

- Temperature 控制概率分布的平滑程度
- 温度越低，输出越稳定保守
- 温度越高，输出越随机发散
- `temperature = 0` 通常表示尽量确定性解码

**面试口语：**

Temperature 可以控制模型输出的随机性。温度低时，模型更倾向选择高概率 Token；温度高时，低概率 Token 也更容易被选中，结果更有创造性但也更不稳定。

⚠️ 注意：`temperature = 0` 不代表模型“绝对确定”，工程实现、并发和底层算子仍可能带来细微差异。

### 4. 🔥 Top-K 和 Top-P

**简要总结：**

- Top-K：只从概率最高的 K 个 Token 中采样
- Top-P：从累计概率达到 P 的候选集合中采样
- Top-K 固定候选数量
- Top-P 根据概率分布动态调整候选数量

**面试口语：**

Top-K 是固定只看前 K 个候选，Top-P 是按累计概率截断候选集合。Top-P 更灵活，概率分布集中时候选少，分布分散时候选多。

📌 重点记忆：Temperature 控制随机强度，Top-K / Top-P 控制候选范围。

### 5. ⭐ 重复惩罚

**简要总结：**

- Repetition Penalty：惩罚重复 Token
- Frequency Penalty：出现次数越多惩罚越强
- Presence Penalty：只要出现过就施加惩罚
- 用于减少模型反复输出相同内容

**面试口语：**

重复惩罚类参数主要用来降低模型复读。Frequency penalty 更关注出现频率，presence penalty 更关注是否出现过。

## 上下文窗口和长上下文

### 1. 🔥 Context Window

**简要总结：**

- 上下文窗口限制模型一次能处理的 Token 总量
- 输入 Token 和输出 Token 都占用上下文窗口
- 超过窗口的内容无法同时被模型看到
- 窗口越大，计算和显存成本通常越高

**面试口语：**

上下文窗口就是模型一次请求里最多能看的 Token 数。用户输入、历史消息、系统提示、工具结果和模型输出都会占用这个窗口。

### 2. 🔥 长上下文问题

**简要总结：**

- 长上下文会增加推理延迟和 KV Cache 占用
- 模型不一定能同等关注所有位置
- 中间信息容易被忽略，叫 Lost in the Middle
- 上下文越长不一定效果越好

**面试口语：**

长上下文能放更多信息，但不是越长越好。上下文变长后，成本、延迟和显存都会增加，而且模型可能更关注开头和结尾，中间信息容易被忽略。

📌 重点记忆：长上下文解决“放得下”，不等于保证“用得好”。

### 3. ⭐ LLM 是否有长期记忆

**简要总结：**

- 模型本身通常没有跨会话长期记忆
- 多轮对话依赖系统把历史消息重新传给模型
- 长期记忆需要应用层自己实现
- 常见做法：摘要、向量检索、用户画像、数据库存储

**面试口语：**

LLM 每次调用本质上只看到当前请求里的上下文。聊天系统所谓记忆，通常是应用层把历史消息、摘要或检索结果重新放进上下文里。

## 参数量、精度和量化

### 1. 🔥 模型参数量

**简要总结：**

- 7B、14B、70B 表示约 70 亿、140 亿、700 亿参数
- 参数量越大，容量通常越强，但成本也更高
- 参数中存储的是模型训练学到的权重
- 参数量不是评价模型效果的唯一标准

**面试口语：**

参数量可以理解成模型内部可学习权重的数量。参数越大，模型容量通常越强，但推理显存、延迟和成本也更高。数据质量、训练方法、架构同样重要。

### 2. 🔥 FP32 / FP16 / BF16

**简要总结：**

- FP32：精度高，占用大
- FP16：占用更小，推理训练更快，但数值范围较小
- BF16：指数位更大，数值范围接近 FP32
- 大模型推理常用 FP16 或 BF16 降低显存和提升速度

**面试口语：**

FP32 更精确但显存占用大。FP16 和 BF16 都是半精度，能降低显存和提升计算效率。BF16 的数值范围更大，训练稳定性通常更好。

### 3. 🔥 量化

**简要总结：**

- 量化是用更低位宽表示模型权重或激活
- 常见有 INT8、INT4
- 可以显著降低显存占用
- 通常会带来一定精度损失
- GPTQ、AWQ、GGUF 都和模型量化或格式有关

**面试口语：**

量化就是把原来 FP16 或 FP32 的权重，用 INT8、INT4 这类更低精度表示。这样模型更省显存、推理更快，但可能牺牲一点效果。

📌 重点记忆：量化主要解决部署成本和显存占用问题，不是提升模型能力。

### 4. ⭐ 显存粗略估算

**简要总结：**

- FP16 / BF16 每个参数约 2 字节
- 7B FP16 权重约 `7B * 2 = 14GB`
- 实际显存还包括 KV Cache、激活、框架开销、batch 等
- 上下文越长，KV Cache 越大

**面试口语：**

估算模型权重显存时，可以用参数量乘以每个参数字节数。比如 7B 模型用 FP16，大约 14GB 只放权重；真正运行时还要加 KV Cache 和框架开销，所以会更高。

## 推理过程和性能指标

### 1. 🔥 推理、Prefill 和 Decode

**简要总结：**

- 推理是模型根据输入生成输出的过程
- Prefill：处理输入 Prompt，生成首个 Token 前的准备阶段
- Decode：逐个生成后续 Token
- Prefill 更偏计算密集，可以并行处理输入 Token
- Decode 逐 Token 生成，更容易受内存带宽和 KV Cache 影响

**面试口语：**

大模型推理可以分成 Prefill 和 Decode。Prefill 是把输入上下文整体过一遍，算出 KV Cache；Decode 是一个 Token 一个 Token 生成。首 Token 延迟主要和 Prefill 有关，生成速度主要看 Decode。

### 2. 🔥 KV Cache

**简要总结：**

- KV Cache 缓存历史 Token 的 Key 和 Value
- 避免每次生成都重复计算所有历史上下文
- 能显著提升自回归生成速度
- 会占用显存
- 上下文越长，batch 越大，KV Cache 越大

**面试口语：**

自回归生成时，每一步都要用到前面 Token 的 K 和 V。KV Cache 把这些结果缓存起来，下一步生成时直接复用，不用重复计算整段历史，所以能提升推理速度。

### 3. 🔥 TTFT / TPS / Throughput / Latency

**简要总结：**

- Latency：整体请求延迟
- TTFT：Time To First Token，首 Token 时间
- TPS：Tokens Per Second，每秒生成 Token 数
- Throughput：系统整体吞吐量
- TTFT 和 TPS 要分开看

**面试口语：**

LLM 服务不能只看总耗时。TTFT 反映用户多久看到第一个字，TPS 反映后续生成速度，吞吐量反映服务整体能处理多少请求。

### 4. ⭐ Batch Inference 和 Continuous Batching

**简要总结：**

- Batch Inference 把多个请求合并推理，提高吞吐
- Batch Size 变大通常提升吞吐，但也可能增加单请求延迟
- Continuous Batching 可以动态加入和移除请求
- 适合不同用户请求长度不一致的大模型服务

**面试口语：**

普通 batch 要等一批请求一起处理，容易被长请求拖慢。Continuous Batching 可以在生成过程中动态调度请求，完成的请求退出，新请求加入，所以更适合在线 LLM 服务。

### 5. ⭐ PagedAttention 和 vLLM

**简要总结：**

- PagedAttention 借鉴虚拟内存分页思想管理 KV Cache
- 减少 KV Cache 内存碎片和浪费
- vLLM 通过 PagedAttention、连续批处理等提升吞吐
- 主要优化大模型在线推理服务

**面试口语：**

PagedAttention 主要解决 KV Cache 管理效率问题，把 KV Cache 像分页内存一样管理，减少浪费。vLLM 利用这类机制提升并发推理吞吐。

## 训练、微调与对齐

### 1. 🔥 预训练和微调

**简要总结：**

- 预训练：在大规模通用语料上学习语言能力
- 微调：在特定任务或指令数据上继续训练
- 预训练成本极高
- 微调成本相对低，用于适配任务、风格或领域

**面试口语：**

预训练像让模型读大量文本，学通用语言能力；微调是在这个基础上用更小、更有针对性的数据继续训练，让模型更适合某类任务或对话风格。

### 2. 🔥 SFT / Instruction Tuning

**简要总结：**

- SFT 是 Supervised Fine-Tuning，监督微调
- Instruction Tuning 是用指令数据训练模型按要求回答
- 数据通常是 `instruction / input / output` 或对话格式
- 让 Base Model 更像可用助手

**面试口语：**

SFT 是用人工或高质量生成的问答数据训练模型，让它学会按照指令输出。Instruction Tuning 可以看作 SFT 的重要形式，目标是提升模型遵循指令的能力。

### 3. 🔥 LoRA / QLoRA / PEFT

**简要总结：**

- PEFT 是参数高效微调
- LoRA 冻结原模型，只训练低秩适配矩阵
- LoRA 大幅减少训练参数和显存需求
- QLoRA 在量化基础上做 LoRA，进一步降低显存

**面试口语：**

LoRA 的思路是不直接改动大模型全部权重，而是在部分线性层旁边加小的低秩矩阵，只训练这些小参数。QLoRA 则把底座模型量化后再做 LoRA，显存成本更低。

📌 重点记忆：全参微调改全部权重，LoRA 只训练少量适配参数。

### 4. 🔥 RLHF 和 DPO

**简要总结：**

- RLHF：基于人类反馈的强化学习
- 典型流程：SFT → Reward Model → PPO 优化
- Reward Model 学习人类偏好
- DPO 直接用偏好数据优化模型，不一定需要单独训练奖励模型
- DPO 流程更简单，训练更稳定

**面试口语：**

RLHF 是让模型输出更符合人类偏好的方法，通常先训练奖励模型，再用 PPO 优化策略模型。DPO 则直接利用偏好对数据优化模型，省去了复杂的强化学习流程。

### 5. ⭐ Alignment

**简要总结：**

- Alignment 是模型对齐
- 目标是让模型更有帮助、更诚实、更安全
- 常见方法包括 SFT、RLHF、DPO、规则和安全过滤
- 对齐不是单纯提升知识量

**面试口语：**

模型对齐主要解决模型行为是否符合人类期望的问题，比如是否遵循指令、是否减少有害输出、是否承认不确定性。它不只是让模型更聪明，而是让模型更可用、更可靠。

## Prompt 和消息格式

### 1. 🔥 System / User / Assistant

**简要总结：**

- System Prompt：定义模型行为、角色和边界
- User Message：用户输入的问题或任务
- Assistant Message：模型历史回复
- 多轮对话通常把历史消息一起传入模型

**面试口语：**

聊天模型通常不是只接收一段纯文本，而是接收带角色的消息列表。System 用来设定全局行为，User 是用户请求，Assistant 是历史回答。

### 2. ⭐ Prompt Template 和 Chat Template

**简要总结：**

- Prompt Template 是应用层组织提示词的模板
- Chat Template 是模型训练时使用的对话格式
- 不同模型可能需要不同特殊 Token 和消息格式
- 模板不匹配可能导致效果变差

**面试口语：**

Prompt Template 是我们应用里拼接提示词的方式；Chat Template 是模型理解多轮对话的格式。不同模型训练时用的模板不同，所以本地部署开源模型时要特别注意模板是否匹配。

### 3. ⭐ Special Token

**简要总结：**

- BOS：序列开始 Token
- EOS：序列结束 Token
- PAD：补齐 Token
- 角色 Token：区分 system、user、assistant
- 特殊 Token 帮助模型理解结构边界

**面试口语：**

特殊 Token 用来告诉模型文本结构，比如哪里开始、哪里结束、谁在说话。对 Chat Model 来说，角色相关的特殊 Token 很重要。

## 幻觉、能力和推理

### 1. 🔥 Hallucination 幻觉

**简要总结：**

- 幻觉是模型生成看似合理但实际错误的内容
- 原因包括训练数据缺失、概率生成机制、上下文不足、模型过度自信
- 幻觉不能彻底消除，只能降低
- 常见降低方法：RAG、工具调用、约束输出、引用来源、拒答机制

**面试口语：**

LLM 本质是生成概率最高的语言结果，不是数据库查询系统。当上下文不足或知识不确定时，它可能生成听起来合理但不真实的答案，这就是幻觉。

⚠️ 注意：模型回答流畅不代表事实正确。

### 2. 🔥 LLM 是不是下一个 Token 预测器

**简要总结：**

- 训练目标通常是下一个 Token 预测
- 但大规模训练后会形成复杂能力
- 只说“概率预测器”能解释生成机制
- 但不能完整描述模型在推理、工具使用、上下文学习中的表现

**面试口语：**

从训练目标看，LLM 确实是在做下一个 Token 预测；但当模型规模、数据和训练方法足够复杂后，会表现出推理、规划、上下文学习等能力。所以这句话对，但不完整。

### 3. ⭐ In-Context Learning / Zero-shot / Few-shot

**简要总结：**

- Zero-shot：不给示例，直接让模型完成任务
- One-shot：给一个示例
- Few-shot：给少量示例
- In-Context Learning 是模型通过上下文示例理解任务模式

**面试口语：**

Few-shot 能提升效果，是因为示例告诉模型任务格式、判断标准和输出风格。模型不是更新了参数，而是在当前上下文里学习了任务模式。

### 4. ⭐ Chain of Thought 和 Reasoning Model

**简要总结：**

- CoT 是让模型显式展开推理步骤的提示方法
- 对数学、逻辑、复杂规划任务更有帮助
- 不适合所有任务，简单问题可能增加成本
- Reasoning Model 通常会投入更多计算做推理，因此响应更慢

**面试口语：**

Chain of Thought 可以让模型把复杂问题拆成步骤，提升推理类任务表现。推理模型通常会在回答前做更多内部推理或搜索，所以延迟和成本更高。

## MoE、蒸馏和模型压缩

### 1. 🔥 MoE

**简要总结：**

- MoE 是 Mixture of Experts，混合专家模型
- 模型包含多个 Expert
- Router 决定每个 Token 走哪些 Expert
- 总参数量可以很大，但每次只激活部分参数
- 激活参数 Active Parameters 决定单次推理主要计算量

**面试口语：**

MoE 的核心是把模型分成多个专家，每个 Token 只路由到其中一部分专家。这样模型总容量很大，但每次推理只激活部分参数，所以能在控制计算成本的同时扩大模型容量。

⚠️ 注意：MoE 也有路由不均衡、通信成本高、部署复杂等问题。

### 2. ⭐ Dense Model 和 MoE Model

**简要总结：**

- Dense Model 每次推理使用全部参数
- MoE Model 每次推理只使用部分专家参数
- Dense 部署相对简单
- MoE 更依赖路由和分布式通信优化

**面试口语：**

Dense 模型是所有参数都参与计算，MoE 是总参数很多但只激活一部分。比如 100B 总参数、10B 激活参数，表示模型容量有 100B，但单次推理主要计算约 10B 参数。

### 3. 💡 蒸馏和剪枝

**简要总结：**

- 蒸馏：用大模型 Teacher 指导小模型 Student
- 目标是让小模型学到大模型能力，降低部署成本
- 剪枝：移除不重要的权重、通道或结构
- 量化是降低数值精度，剪枝是减少结构或参数

**面试口语：**

蒸馏是让小模型模仿大模型输出，用更低成本获得接近的效果。剪枝是删掉模型里不重要的部分，量化则是把参数表示得更低精度，两者解决的问题相似但手段不同。

## 评测与效果判断

### 1. 🔥 如何评估 LLM

**简要总结：**

- 看任务类型：问答、总结、代码、检索、推理、对话
- 自动指标：Accuracy、BLEU、ROUGE、Perplexity
- 人工评价：有用性、事实性、完整性、安全性、风格
- 线上指标：用户满意度、采纳率、延迟、成本

**面试口语：**

LLM 评测不能只看一个指标，要结合任务目标。分类题可以看准确率，摘要可以参考 ROUGE，但开放式问答通常还需要人工评价或 LLM-as-a-Judge。

### 2. ⭐ Perplexity / BLEU / ROUGE

**简要总结：**

- Perplexity 衡量模型对文本的困惑程度，越低表示越能预测数据
- BLEU 常用于机器翻译，关注 n-gram 重合
- ROUGE 常用于摘要，关注召回
- 这些指标不适合所有生成任务

**面试口语：**

自动指标方便批量评估，但不一定能衡量答案是否真正有用。比如开放问答里，答案可以表达不同但都正确，BLEU 或 ROUGE 可能低估质量。

### 3. ⭐ LLM-as-a-Judge

**简要总结：**

- 用另一个 LLM 作为评委给答案打分
- 适合开放式生成任务的快速评估
- 需要设计评分标准和样例
- 存在偏见、位置偏差、模型偏好等问题

**面试口语：**

LLM-as-a-Judge 可以降低人工评测成本，但它不是绝对客观。评委模型可能偏好更长答案、特定表达方式，或者被提示词影响，所以重要评测仍要结合人工抽检。

## RAG、微调和知识更新

### 1. 🔥 RAG 和 Fine-tuning 区别

**简要总结：**

- RAG：检索外部知识，把相关内容放进上下文
- Fine-tuning：更新模型参数，让模型学习任务模式或风格
- 知识频繁更新更适合 RAG
- 输出格式、领域风格、任务习惯更适合微调

**面试口语：**

RAG 更适合解决“模型不知道最新或私有知识”的问题，微调更适合解决“模型不会按某种方式做事”的问题。如果只是知识更新，通常不建议重新微调模型。

📌 重点记忆：RAG 改上下文，微调改参数。

### 2. ⭐ 模型是否能访问互联网

**简要总结：**

- LLM 本身通常不能自动访问互联网
- 实时信息需要搜索、工具调用或 RAG 系统提供
- 知识截止日期表示训练数据覆盖到的大致时间
- 微调不能让模型自动实时更新知识

**面试口语：**

模型本身只是根据训练得到的参数和当前上下文生成答案。如果需要实时信息，应用层要接入搜索、数据库、工具或 RAG，把最新信息提供给模型。

## 模型部署和并发服务

### 1. 🔥 本地模型和云端 API

**本地模型：**

- 数据可控
- 可定制部署
- 成本可控但需要硬件和运维
- 延迟受本地资源影响

**云端 API：**

- 接入简单
- 模型能力强、更新快
- 不需要自己维护推理集群
- 成本、数据合规和网络依赖需要评估

**面试口语：**

本地模型适合对数据安全、成本控制和私有化部署要求高的场景；云端 API 适合快速接入强模型能力，减少运维成本。真实项目要综合能力、成本、合规、延迟和团队维护能力。

### 2. 🔥 多 GPU 推理

**简要总结：**

- Tensor Parallel：把单层矩阵计算切到多张 GPU
- Pipeline Parallel：把不同层放到不同 GPU
- Data Parallel：复制多份模型处理不同请求
- 推理大模型常用 Tensor Parallel 放下单个大模型
- 多 GPU 会带来通信开销

**面试口语：**

如果单张 GPU 放不下模型，就需要模型并行。Tensor Parallel 是把模型内部的大矩阵拆到多张卡上，推理大模型时很常见；Data Parallel 更像复制多份模型提高并发。

### 3. ⭐ Speculative Decoding

**简要总结：**

- 使用小 Draft Model 先快速生成候选 Token
- 大模型一次验证多个候选
- 如果候选通过，就能减少大模型逐 Token 调用次数
- 用于提升生成速度

**面试口语：**

Speculative Decoding 的思路是让小模型先草拟几个 Token，大模型再验证。如果验证通过，就相当于大模型一次接受多个 Token，从而提升生成速度。

### 4. ⭐ FlashAttention

**简要总结：**

- FlashAttention 是高效 Attention 计算方法
- 通过优化显存读写提升速度
- 减少中间矩阵显存占用
- 不改变 Attention 的数学结果

**面试口语：**

FlashAttention 主要优化 Attention 的计算和显存访问方式，让它更快、更省显存。它不是改 Attention 公式，而是用更高效的实现得到同样数学结果。

### 5. ⭐ LLM 服务稳定性

**简要总结：**

- 关注 TTFT、TPS、总延迟、吞吐量
- 关注错误率、超时率、排队时间
- 关注显存利用率和 KV Cache 占用
- 关注高并发下延迟抖动
- 需要限流、超时、降级和监控

**面试口语：**

LLM 服务稳定性不能只看单次请求速度，还要看并发上来后的延迟、吞吐、错误率和资源占用。线上一般要配合限流、排队、超时、监控和降级策略。
