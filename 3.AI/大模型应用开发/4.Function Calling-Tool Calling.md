# Function Calling / Tool Calling

## 工具调用基础

### 1. 🔥 Function Calling 是什么

**简要总结：**

- 让模型根据上下文选择调用外部函数
- 开发者提供工具名称、描述和参数 schema
- 模型输出工具调用意图和参数
- 应用代码真正执行函数，再把结果返回给模型

**面试口语：**

Function Calling 不是模型自己执行代码，而是模型判断应该调用哪个函数，并生成结构化参数。真正执行函数的是我们的后端程序，执行结果再交给模型继续生成最终答案。

**底层原理 / 背后逻辑：**

模型本质仍然在生成 Token，只是输出被约束成工具调用结构。工具描述和 JSON Schema 会进入上下文，帮助模型判断工具用途和参数格式。安全边界必须在代码层控制，因为模型生成的参数不可信。

### 2. 🔥 Tool Calling 流程

**简要总结：**

- 定义工具 schema
- 用户提出问题
- 模型选择工具并生成参数
- 后端校验参数并执行工具
- 把工具结果返回给模型
- 模型生成最终回复

**面试口语：**

工具调用的完整链路是：模型决定调用工具，但业务系统负责执行工具。比如用户问天气，模型生成 `get_weather(city="上海")`，后端查天气接口，再把结果给模型组织自然语言回答。

```python
tools = [{
    "type": "function",
    "name": "get_weather",
    "description": "查询城市天气",
    "parameters": {
        "type": "object",
        "properties": {
            "city": {"type": "string"}
        },
        "required": ["city"]
    }
}]
```

### 3. 🔥 为什么需要 Tool Calling

**简要总结：**

- 访问实时数据
- 查询私有系统
- 执行业务动作
- 降低幻觉
- 输出结构化结果

**面试口语：**

模型参数里的知识不是实时数据库。需要查订单、查库存、发邮件、创建工单时，就必须通过工具调用连接真实系统。这样模型负责理解和编排，系统负责事实和执行。

### 4. ⚠️ 工具调用安全

**简要总结：**

- 模型参数不可信，要二次校验
- 工具权限不能只靠 Prompt 控制
- 高风险操作需要用户确认
- 工具结果要做脱敏
- 要记录审计日志

**面试口语：**

工具调用最大的风险是模型可能调用不该调用的工具，或者生成危险参数。所以后端必须做权限校验、参数校验和操作审计。删除、转账、发消息这类高风险动作要二次确认。

```python
def execute_tool(user, name: str, args: dict):
    if not has_permission(user, name):
        raise PermissionError("无工具权限")
    if name == "delete_order" and not args.get("confirmed"):
        raise ValueError("需要用户确认")
    return TOOL_REGISTRY[name](**args)
```

### 5. ⭐ Tool Calling 和 RAG 区别

**简要总结：**

- RAG 主要用于检索知识
- Tool Calling 主要用于调用能力
- RAG 返回上下文给模型
- Tool Calling 可以执行真实业务动作
- 两者可以组合

**面试口语：**

RAG 解决“模型需要哪些知识”，Tool Calling 解决“模型需要调用哪些能力”。比如先用 RAG 查产品文档，再用工具查用户订单状态，最后合成回答。
