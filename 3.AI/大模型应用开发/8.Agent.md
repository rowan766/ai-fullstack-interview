## Agent 基础

### 1. 🔥 Agent 是什么

**简要总结：**

- Agent 是能感知任务、规划步骤、调用工具并迭代完成目标的系统
- LLM 通常负责理解、推理和决策
- 工具负责访问外部系统或执行动作
- 记忆负责保存上下文、用户偏好或历史经验
- 控制器负责循环、终止、权限和错误处理

**面试口语：**

Agent 不是简单多调用几次模型，而是让模型具备“根据目标选择下一步动作”的能力。它通常会结合工具调用、记忆、规划和反馈循环，逐步完成复杂任务。

**底层原理 / 背后逻辑：**

LLM 单次调用更像“输入到输出”；Agent 则是一个控制循环：观察当前状态，思考下一步，选择工具，执行动作，拿到结果后继续判断是否完成。工程难点不在概念，而在如何限制循环、控制权限、处理失败和评估结果。

```txt
Goal -> Plan -> Tool Call -> Observation -> Next Step -> Final Answer
```

### 2. 🔥 Agent 核心组件

**简要总结：**

- Planner：拆解任务和安排步骤
- Tool Executor：执行工具
- Memory：短期记忆和长期记忆
- State：任务当前状态
- Guardrail：安全边界和权限控制

**面试口语：**

我会把 Agent 拆成模型、工具、记忆、状态和控制器。模型负责决策，工具负责执行，状态记录当前进度，控制器负责防止无限循环和危险操作。

### 3. 🔥 ReAct 思路

**简要总结：**

- ReAct = Reasoning + Acting
- 模型交替进行推理和行动
- 行动通常是调用工具
- 工具结果作为 Observation 进入下一轮

**面试口语：**

ReAct 的核心是边想边做。模型先判断需要什么信息，调用工具拿到观察结果，再基于结果继续推理，直到得到最终答案。

```python
for _ in range(max_steps):
    action = llm.decide(state)
    if action.type == "final":
        return action.answer
    observation = execute_tool(action.tool, action.args)
    state.add_observation(observation)
```

### 4. ⚠️ Agent 常见问题

**常见问题：**

- 无限循环
- 工具误用
- 幻觉规划
- 成本不可控
- 权限越界
- 中间状态不可追踪

**面试口语：**

Agent 上线最怕不可控。要设置最大步数、工具白名单、权限校验、超时、成本预算和审计日志。高风险操作要加人工确认，不应该让模型直接执行。

### 5. ⭐ Agent 和 Workflow 区别

**简要总结：**

- Workflow：流程固定，节点和顺序由代码定义
- Agent：下一步由模型根据状态动态决定
- Workflow 更稳定可控
- Agent 更灵活但不确定性更高

**面试口语：**

能用固定流程解决的业务，我更倾向 Workflow，因为稳定、可测试、成本可控。Agent 更适合步骤不固定、需要动态探索和工具选择的任务。
