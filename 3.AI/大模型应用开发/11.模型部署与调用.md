## 部署基础

### 1. 🔥 云端 API 和私有化部署

**简要总结：**

- 云端 API：接入快、能力强、免运维
- 私有化部署：数据可控、可定制、需要 GPU 和运维
- 选型要看能力、成本、合规、延迟、稳定性

**面试口语：**

如果要快速验证业务，云端 API 成本低、上线快；如果数据敏感、调用量大或需要内网部署，可以考虑私有化模型。但私有化要承担 GPU、推理服务、监控、扩容和模型更新成本。

### 2. 🔥 推理服务核心指标

**简要总结：**

- TTFT：首 Token 延迟
- TPS：每秒生成 Token
- Latency：整体延迟
- Throughput：吞吐量
- GPU 利用率、显存占用、排队时间

**面试口语：**

LLM 服务不能只看平均耗时。聊天场景要看首 Token 时间和生成速度，高并发服务要看吞吐、排队时间和 P95/P99 延迟。

### 3. 🔥 vLLM / TGI / llama.cpp

**简要总结：**

- vLLM：适合高吞吐在线推理，支持 PagedAttention
- TGI：Hugging Face 推理服务方案
- llama.cpp：适合 CPU、本地、小设备或 GGUF 模型
- 选择取决于硬件、模型格式、并发和运维能力

**面试口语：**

部署开源模型时，vLLM 常用于服务端高并发推理；llama.cpp 更适合本地或边缘设备。不同框架支持的模型格式、量化方式和吞吐能力不一样。

### 4. 🔥 量化部署

**简要总结：**

- FP16 / BF16 效果稳定但显存高
- INT8 / INT4 降低显存和成本
- 量化可能带来效果损失
- 要用业务评测集验证

**面试口语：**

量化不是为了让模型更聪明，而是为了更便宜、更省显存地部署。量化后一定要用业务数据评测，因为通用榜单不代表业务效果。

### 5. ⭐ 多 GPU 和扩容

**简要总结：**

- 单模型放不下可用 Tensor Parallel
- 并发高可做多副本部署
- 请求前面通常需要队列和负载均衡
- 扩容要关注 KV Cache 和显存

**面试口语：**

如果单卡放不下模型，需要模型并行；如果单实例吞吐不够，可以复制多份模型做数据并行。线上还要有限流、排队和降级，否则高峰流量会把 GPU 打满。

### 6. 🔥 调用侧工程封装

**简要总结：**

- 统一 LLM Gateway
- 超时、重试、熔断
- 流式输出
- 成本统计
- 审计和权限
- 多模型路由和降级

```python
def call_llm(prompt: str, *, timeout: float = 10) -> str:
    try:
        return client.chat(prompt, timeout=timeout)
    except TimeoutError:
        return fallback_client.chat(prompt, timeout=timeout)
```

**面试口语：**

业务代码不应该直接散落调用模型。最好封装统一网关，处理超时、重试、降级、日志、成本和权限，这样模型供应商切换也更容易。
