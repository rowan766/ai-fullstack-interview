# AI 应用评测

> 图标说明：⭐ 重点｜🔥 高频｜⚠️ 注意｜💡 提示｜📌 重点记忆

## 评测基础

### 1. 🔥 为什么 AI 应用需要评测

**简要总结：**

- LLM 输出不完全确定
- Prompt、模型、RAG、工具变更都会影响效果
- 需要防止效果回退
- 需要量化质量、成本和延迟

**面试口语：**

AI 应用不能只靠肉眼试几个问题。Prompt 改动、模型切换、知识库更新都可能让效果变好或变坏，所以要有固定评测集和指标，像测试一样持续回归。

**底层原理 / 背后逻辑：**

传统程序多是确定性逻辑，AI 应用是概率输出加工程链路。一次回答好不代表整体好，单个样例通过不代表边界场景没问题。评测集就是把业务预期固化下来，模型或系统变更后批量检查。

### 2. 🔥 评测维度

**简要总结：**

- 正确性
- 完整性
- 事实性
- 引用准确性
- 安全性
- 格式遵循
- 延迟和成本

**面试口语：**

不同 AI 应用评测维度不同。RAG 问答要看答案是否基于文档、引用是否准确；结构化抽取要看字段准确率；客服机器人还要看安全性、拒答和转人工策略。

### 3. 🔥 RAG 评测

**简要总结：**

- 检索层：Recall@K、Hit Rate、MRR
- 生成层：答案正确性、忠实度、引用准确性
- 端到端：用户问题是否解决
- 要先判断问题出在检索还是生成

**面试口语：**

RAG 评测一定要拆开看。如果正确文档没有被检索出来，是召回问题；如果检索到了但模型答错，是生成或 Prompt 问题。

### 4. ⭐ LLM-as-a-Judge

**简要总结：**

- 用模型作为评委给回答打分
- 适合开放式生成任务
- 需要明确 rubric
- 要防位置偏差、长度偏好和评委模型偏见

**面试口语：**

LLM-as-a-Judge 可以降低人工评测成本，但不能完全替代人工。重要场景要抽样人工复核，并设计清晰评分标准。

```text
请根据以下标准评分：
1 分：答非所问
3 分：部分正确但缺少关键点
5 分：完全正确，且依据充分
```

### 5. 🔥 线上评测和 A/B

**简要总结：**

- 用户满意度
- 采纳率
- 转人工率
- 任务完成率
- 延迟、错误率、成本
- A/B 对比不同 Prompt 或模型

**面试口语：**

离线评测能保证基础质量，线上指标反映真实用户效果。比如客服场景可以看问题解决率、转人工率和用户差评率。

### 6. ⭐ OpenAI Evals 思路

**简要总结：**

- 建立评测数据集
- 定义评分标准或 grader
- 对不同模型、Prompt、参数跑评测
- 记录结果用于回归和对比

**面试口语：**

OpenAI 平台也提供 evals 相关能力，思路和工程测试类似：先定义数据和评分标准，再批量运行评测，用结果比较模型或 Prompt 改动是否带来提升。
