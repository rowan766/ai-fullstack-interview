# MCP

## MCP 基础

### 1. 🔥 MCP 是什么

**简要总结：**

- MCP 是 Model Context Protocol
- 用统一协议把模型应用连接到外部工具、数据源和系统
- 核心角色通常包括 MCP Client、MCP Server、Host
- Server 暴露 tools、resources、prompts 等能力

**面试口语：**

MCP 可以理解成 AI 应用连接外部工具的标准协议。以前每接一个系统都要写一套定制集成，MCP 希望把工具、资源和提示能力标准化，让模型应用用统一方式发现和调用外部能力。

**底层原理 / 背后逻辑：**

Agent 和 Tool Calling 最大的问题是集成碎片化。MCP 把“有哪些工具、参数是什么、如何调用、有哪些资源可读”抽象成协议。模型应用作为 client 连接 MCP server，server 负责对接真实系统，比如 GitHub、数据库、文件系统、内部工单系统。

### 2. 🔥 MCP 和 Function Calling 区别

**简要总结：**

- Function Calling 是模型接口层的工具调用能力
- MCP 是工具和上下文接入协议
- Function Calling 关注模型如何选择函数
- MCP 关注工具如何被标准化暴露和调用
- 两者可以结合使用

**面试口语：**

Function Calling 更像模型输出“我要调用哪个函数和参数”；MCP 更像后端工具生态的标准接口。应用可以从 MCP server 获取工具定义，再提供给模型做 tool calling。

### 3. 🔥 MCP Server 提供什么

**简要总结：**

- Tools：可执行动作，如查订单、建工单
- Resources：可读取上下文，如文件、文档、配置
- Prompts：可复用提示模板
- Transport：通信方式，如 stdio、HTTP 等

**面试口语：**

MCP server 不是模型，它是能力提供方。它可以暴露工具给模型应用调用，也可以暴露资源给模型应用读取。

```txt
AI App / Host
  -> MCP Client
    -> MCP Server
      -> GitHub / DB / Files / Internal API
```

### 4. ⚠️ MCP 安全

**简要总结：**

- 工具调用要做权限控制
- 资源读取要做访问控制
- 高风险工具要二次确认
- 需要审计日志
- 不要把敏感资源无差别暴露给模型

**面试口语：**

MCP 让模型应用更容易接入外部系统，也意味着权限风险更大。不能因为工具走了 MCP 就默认安全，server 端仍然要校验用户身份、资源权限和操作范围。

### 5. ⭐ MCP 适用场景

**简要总结：**

- 企业内部系统接入 Agent
- IDE / 文档 / 数据库工具集成
- 多模型应用共享同一套工具
- 插件化工具生态

**面试口语：**

如果公司有很多内部系统都想接入 AI 助手，MCP 很适合做统一工具协议。否则每个系统都写一套 prompt 和函数适配，维护成本会很高。
