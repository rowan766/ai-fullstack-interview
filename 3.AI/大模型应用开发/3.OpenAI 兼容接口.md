## 接口基础

### 1. 🔥 什么是 OpenAI 兼容接口

**简要总结：**

- 指第三方模型服务实现类似 OpenAI API 的请求格式
- 常见兼容点：`base_url`、`api_key`、`model`、messages/input、stream
- 方便应用在不同模型供应商之间切换
- 兼容不代表能力、参数、返回字段完全一致

**面试口语：**

OpenAI 兼容接口就是很多模型服务按 OpenAI API 风格提供接口。这样应用层可以用类似 SDK 或请求格式调用不同模型，只需要换 base_url、api_key 和 model。但兼容通常是“形状兼容”，不代表所有参数和能力都一样。

**底层原理 / 背后逻辑：**

大模型应用通常希望把模型供应商抽象成统一客户端。OpenAI 兼容接口降低了接入成本，但不同服务对工具调用、流式事件、视觉输入、JSON 输出、错误码、限流策略支持不同，所以生产系统要做能力探测和适配层。

### 2. 🔥 Responses API 调用

**简要总结：**

- OpenAI 官方当前推荐使用 Responses API 构建文本、视觉、工具调用等能力
- 核心参数包括 `model`、`input`、`tools`、`stream`
- API Key 应放在服务端环境变量，不要暴露给前端

**面试口语：**

调用大模型 API 时，后端通常封装一个模型客户端。前端不要直接持有 API Key，而是请求自己的后端，由后端完成鉴权、限流、审计和模型调用。

```python
from openai import OpenAI

client = OpenAI()

response = client.responses.create(
    model="gpt-5",
    input="用一句话解释 RAG 是什么"
)

print(response.output_text)
```

### 3. ⭐ Chat Completions 兼容

**简要总结：**

- 很多兼容服务仍支持 `/v1/chat/completions`
- 常见请求结构是 `messages`
- 角色包括 `system`、`user`、`assistant`
- 新项目要关注官方推荐接口和供应商实际支持能力

**面试口语：**

Chat Completions 是很多兼容生态使用最多的格式。即使官方新能力逐步集中到 Responses API，很多第三方服务仍用 chat completions 作为兼容层。

```python
from openai import OpenAI

client = OpenAI(base_url="https://api.example.com/v1", api_key="xxx")

response = client.chat.completions.create(
    model="some-model",
    messages=[
        {"role": "system", "content": "你是后端面试助手"},
        {"role": "user", "content": "解释 JWT"}
    ],
)
```

### 4. 🔥 流式输出

**简要总结：**

- 流式输出可以更快展示首 token
- 常用 SSE 或事件流
- 后端要处理断开、超时、错误和取消
- 前端逐块渲染，改善感知延迟

**面试口语：**

流式输出不一定减少总生成时间，但能显著降低用户等待第一个字的时间。聊天产品一般都会用 stream，让模型边生成边展示。

**底层原理 / 背后逻辑：**

LLM 解码是逐 Token 生成的。非流式要等全部生成完再返回，流式则把每次生成的增量事件推给客户端。工程上要注意代理缓冲、连接超时和用户取消，否则流式体验会被基础设施吃掉。

### 5. 🔥 接口封装要点

**简要总结：**

- 统一模型客户端
- 统一错误处理和重试
- 统一超时、限流、日志
- 隐藏不同供应商差异
- 记录 token、延迟、成本和请求 id

**面试口语：**

生产项目里不会在业务代码到处直接调模型 API，而是封装模型网关或 LLM client。它负责供应商切换、超时重试、日志审计、成本统计和错误兜底。

```python
class LLMClient:
    def __init__(self, client, model: str):
        self.client = client
        self.model = model

    def chat(self, prompt: str) -> str:
        response = self.client.responses.create(
            model=self.model,
            input=prompt,
        )
        return response.output_text
```
