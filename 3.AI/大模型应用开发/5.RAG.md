## RAG 基础

### 1. 🔥 RAG 是什么

**简要总结：**

- RAG 是 Retrieval-Augmented Generation，检索增强生成
- 先从外部知识库检索相关内容
- 再把检索结果放进 Prompt
- 模型基于上下文生成答案
- 适合私有知识、最新知识、文档问答

**面试口语：**

RAG 的核心是让模型回答前先查资料。模型本身不一定知道企业内部文档或最新信息，所以我们先检索相关片段，再把片段作为上下文交给模型回答。

**底层原理 / 背后逻辑：**

RAG 不改变模型参数，而是改变模型当前上下文。它把“知识记忆”从模型参数中拆出来，放到外部知识库里管理。知识更新时只需要更新索引，不需要重新训练模型。

📌 重点记忆：RAG 改上下文，Fine-tuning 改参数。

### 2. 🔥 RAG 核心流程

**简要总结：**

- 文档加载
- 文本切分 chunking
- Embedding 向量化
- 写入向量数据库
- 用户问题向量化
- 相似度检索
- Prompt 拼接
- LLM 生成答案

```txt
文档 -> 切分 -> Embedding -> 向量库
问题 -> Embedding -> 检索 TopK -> 拼 Prompt -> 生成答案
```

### 3. 🔥 Chunking

**简要总结：**

- chunk 太大：召回内容噪声多，占用上下文
- chunk 太小：语义不完整
- overlap 可以减少切断语义
- 应按文档结构、标题、段落切分

**面试口语：**

切分是 RAG 效果的关键。chunk 太大，检索回来很多无关内容；chunk 太小，答案需要的信息可能被拆散。一般会结合标题、段落和一定 overlap。

**底层原理 / 背后逻辑：**

Embedding 表示的是一段文本整体语义。chunk 边界会直接影响向量表达和召回质量。好的 chunk 应该语义完整、信息密度高、长度适中，并保留来源元数据，方便引用和过滤。

### 4. 🔥 检索和重排

**简要总结：**

- 向量检索适合语义相似
- 关键词检索适合精确词匹配
- Hybrid Search 结合向量和关键词
- Rerank 对候选结果重新排序

**面试口语：**

RAG 不一定只用向量检索。向量检索擅长语义相似，关键词检索擅长精确匹配编号、术语、代码。实际项目常用混合检索，再用 reranker 提高排序质量。

### 5. 🔥 RAG 常见问题

**常见问题：**

- 检索不到正确内容
- 检索内容太多太杂
- 模型不按资料回答
- 引用来源不准确
- 权限过滤缺失导致越权

**面试口语：**

RAG 出错通常不是模型单点问题，而是加载、切分、召回、重排、Prompt、权限过滤任何一环都有可能出问题。排查时先看是否检索到了正确 chunk，再看模型是否正确使用上下文。

### 6. ⭐ RAG 评估

**简要总结：**

- 检索评估：Recall@K、MRR、Hit Rate
- 生成评估：事实性、完整性、引用准确性
- 端到端评估：用户问题能否得到正确答案
- 要维护一套问答测试集

**面试口语：**

RAG 评估要分检索和生成两层。先看正确文档有没有被召回，再看模型是否基于文档生成了正确答案。如果检索都错了，后面 Prompt 再好也很难救。
