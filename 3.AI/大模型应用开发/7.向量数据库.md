# 向量数据库

## 向量数据库基础

### 1. 🔥 向量数据库是什么

**简要总结：**

- 存储和检索高维向量
- 支持相似度搜索
- 常用于 RAG、语义搜索、推荐、去重
- 常见产品：Milvus、FAISS、Qdrant、Weaviate、Pinecone、pgvector

**面试口语：**

向量数据库就是用来存 embedding 向量并做相似度检索的系统。用户问题转成向量后，可以从库里找语义最相近的文档片段。

**底层原理 / 背后逻辑：**

高维向量如果暴力全量比较，数据量大时成本很高。向量数据库通过 ANN 近似最近邻索引，在召回精度和查询速度之间做平衡。它通常还会存储文本、文档 id、权限、标签等 metadata，用于过滤和引用。

### 2. 🔥 ANN 索引

**简要总结：**

- ANN 是 Approximate Nearest Neighbor
- 用近似结果换查询速度
- 常见索引：HNSW、IVF、PQ
- 参数会影响召回率、延迟和内存

**面试口语：**

向量检索常用近似最近邻，不一定保证绝对最精确，但速度快很多。业务上通常接受一点召回误差，换取更低延迟。

**底层原理 / 背后逻辑：**

HNSW 可以理解成多层图索引，查询时从高层快速定位大概区域，再到底层精细搜索。IVF 是先聚类分桶，查询时只查最相关的几个桶。PQ 是压缩向量，减少存储和计算成本。

### 3. 🔥 Metadata 过滤

**简要总结：**

- 按租户、用户、文档类型、权限过滤
- 防止越权访问
- 缩小检索范围
- 提升相关性和安全性

**面试口语：**

RAG 系统一定要做 metadata 过滤。比如用户只能查自己部门文档，向量检索前或检索时就要带上部门、租户、权限条件，不能等模型回答时再靠 Prompt 控制。

```json
{
  "text": "退款规则...",
  "vector": [0.12, 0.08, -0.33],
  "metadata": {
    "tenant_id": "t1",
    "department": "sales",
    "doc_id": "refund-policy"
  }
}
```

### 4. ⭐ pgvector 和专用向量库选择

**简要总结：**

- pgvector 适合已有 PostgreSQL、数据规模中小、事务关系强
- 专用向量库适合大规模向量、高并发检索、复杂索引
- 选择要看数据量、延迟、运维、过滤能力、成本

**面试口语：**

如果团队本来就用 PostgreSQL，数据量不大，用 pgvector 很省事；如果向量规模很大、检索 QPS 高，就更适合 Milvus、Qdrant 这类专用向量数据库。

### 5. 🔥 向量库常见坑

**常见问题：**

- 向量和文本版本不同步
- 删除文档后索引未删除
- 权限过滤缺失
- TopK 设置不合理
- 只做向量检索，不处理关键词精确匹配

**面试口语：**

向量数据库上线后最容易出问题的是数据同步和权限。文档更新、删除、权限变化后，向量索引必须同步更新，否则会返回旧内容或越权内容。
