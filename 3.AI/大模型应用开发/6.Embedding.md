## Embedding 基础

### 1. 🔥 Embedding 是什么

**简要总结：**

- Embedding 是把文本、图片等数据映射成向量
- 向量距离可以表示语义相似度
- 常用于搜索、推荐、聚类、去重、RAG
- 文本越相似，向量通常越接近

**面试口语：**

Embedding 可以理解成把文本转换成一串数字向量。这样计算机就能用余弦相似度、点积等方式判断两段文本语义是否接近。

**底层原理 / 背后逻辑：**

Embedding 模型通过训练学习语义空间，把相似含义的内容映射到相近位置。它不是关键词匹配，所以“如何退款”和“退货流程是什么”即使用词不同，也可能被判断为相似。

### 2. 🔥 相似度计算

**简要总结：**

- Cosine Similarity：看方向相似度
- Dot Product：点积，受向量长度影响
- Euclidean Distance：欧氏距离
- 向量数据库通常会针对某种距离做索引优化

```python
import numpy as np

def cosine(a, b):
    a = np.array(a)
    b = np.array(b)
    return float(a @ b / (np.linalg.norm(a) * np.linalg.norm(b)))
```

**面试口语：**

文本检索里常用余弦相似度，因为它更关注向量方向，能衡量语义接近程度。具体用哪种距离，要和 embedding 模型以及向量数据库配置保持一致。

### 3. 🔥 Embedding 在 RAG 中的作用

**简要总结：**

- 文档 chunk 转成向量入库
- 用户 query 转成向量
- 向量相似度检索 TopK 文档
- 检索结果作为上下文交给 LLM

**面试口语：**

RAG 里的 Embedding 负责召回候选知识。生成答案的是 LLM，但能不能找到正确资料，很大程度取决于 Embedding、切分和检索策略。

### 4. ⭐ Embedding 常见问题

**常见问题：**

- 短 query 信息不足
- 专有名词、代码、编号语义不明显
- 多语言或领域文本效果差
- 向量维度和距离函数不匹配
- 文档更新后索引未同步

**面试口语：**

Embedding 不是万能语义搜索。像订单号、错误码、专业缩写这类精确匹配内容，纯向量检索可能不如关键词检索，所以实际项目常结合 BM25 或元数据过滤。

### 5. ⭐ Embedding 优化

**简要总结：**

- 选择适合领域和语言的模型
- 优化 chunk 粒度
- 使用 Query Rewrite
- Hybrid Search
- Rerank
- 建立评估集持续对比

**底层原理 / 背后逻辑：**

Embedding 优化最终要看召回效果，而不是只看模型排行榜。业务问题、文档结构和用户问法会决定实际效果。面试里可以说：先建立一批真实问题和标准文档，再评估 Recall@K，否则调参没有方向。
