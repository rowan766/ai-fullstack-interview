# AI 成本与性能优化

> 图标说明：⭐ 重点｜🔥 高频｜⚠️ 注意｜💡 提示｜📌 重点记忆

## 成本基础

### 1. 🔥 AI 应用成本来自哪里

**简要总结：**

- 输入 Token
- 输出 Token
- Embedding 调用
- Rerank 调用
- 工具和下游接口
- 向量库、缓存、GPU 或 API 费用

**面试口语：**

AI 应用成本不只是模型生成费用。RAG 里还有 embedding、向量数据库、rerank；Agent 里可能多轮调用模型和工具；私有化部署还有 GPU 和运维成本。

**底层原理 / 背后逻辑：**

LLM 推理成本和 Token 数强相关。输入越长，Prefill 成本越高；输出越长，Decode 时间和费用越高。Agent 多轮循环会放大调用次数，所以要控制上下文、步数和工具链路。

### 2. 🔥 Token 优化

**简要总结：**

- 压缩系统提示和历史消息
- RAG 只放必要 chunk
- 限制最大输出长度
- 对历史对话做摘要
- 避免重复传大段不变上下文

**面试口语：**

Token 优化最直接影响成本和延迟。比如 RAG 不应该把 TopK 文档全量塞进去，而是控制 chunk 数量、做 rerank，并保留真正相关内容。

```python
def build_prompt(question: str, chunks: list[str]) -> str:
    context = "\n\n".join(chunks[:3])
    return f"基于资料回答问题。\n资料：{context}\n问题：{question}"
```

### 3. 🔥 缓存

**简要总结：**

- Prompt 结果缓存
- Embedding 缓存
- RAG 检索缓存
- 工具结果缓存
- 注意权限和数据过期

**面试口语：**

缓存适合重复问题、固定文档摘要、embedding 结果和慢工具查询。但 AI 缓存要特别注意用户权限，不同用户看到的数据不同，缓存 key 里要包含权限维度。

**底层原理 / 背后逻辑：**

缓存是用空间换时间和成本。AI 场景缓存 key 不能只看问题文本，还要看模型、参数、系统提示、用户权限、知识库版本。否则可能出现旧答案或越权答案。

### 4. 🔥 模型路由

**简要总结：**

- 简单任务用小模型
- 复杂任务用强模型
- 失败时升级模型
- 高峰期降级模型
- 按成本、延迟、质量动态选择

**面试口语：**

不是所有请求都要用最强模型。分类、改写、格式化可以用便宜小模型，复杂推理再用强模型。这样能明显降低成本。

```python
def choose_model(task_type: str) -> str:
    if task_type in {"classify", "rewrite"}:
        return "small-model"
    return "strong-model"
```

### 5. ⭐ 流式输出和体验优化

**简要总结：**

- 降低首字等待感
- 不一定降低总耗时
- 前端逐 token 渲染
- 后端要处理取消和超时

**面试口语：**

流式输出主要优化体感延迟。用户更快看到第一个字，会觉得系统响应更快，但总生成时间主要还是由模型 decode 速度决定。

### 6. 🔥 并发和限流

**简要总结：**

- 控制用户级、租户级、接口级限流
- Agent 设置最大步数
- 工具调用设置超时
- 任务队列削峰
- 高峰期降级

**面试口语：**

AI 接口成本高、延迟长，所以一定要限流和预算控制。Agent 尤其要限制最大轮数，否则一次用户请求可能变成几十次模型调用。

### 7. ⭐ RAG 性能优化

**简要总结：**

- 减少检索范围
- 使用 metadata 过滤
- TopK 不宜过大
- rerank 只处理候选集
- 向量库索引参数调优

**面试口语：**

RAG 慢可能慢在 embedding、向量检索、rerank 或 LLM 生成。优化时要拆链路看耗时，不要只盯模型。

### 8. ⭐ 监控指标

**简要总结：**

- Token 使用量
- 单请求成本
- TTFT、总延迟、TPS
- 模型错误率和超时率
- 缓存命中率
- RAG 召回率

**面试口语：**

AI 应用上线一定要监控成本和质量。只监控接口 200 不够，还要看 token、模型耗时、工具耗时、缓存命中率和用户反馈。
