# 文件与权限

## 文件系统

### 1. 🔥 Linux 目录结构

**简要总结：**

- `/etc`：配置文件
- `/var/log`：日志
- `/usr/bin`、`/usr/local/bin`：命令程序
- `/home`：用户目录
- `/tmp`：临时文件
- `/proc`：内核暴露的进程和系统信息

**面试口语：**

Linux 目录结构是有职责划分的。排查服务时，我会去 `/etc` 或应用目录看配置，去 `/var/log` 或应用日志目录看日志，去 `/proc` 看进程和系统状态。

**底层原理 / 背后逻辑：**

Linux 把系统资源组织成统一的文件树。普通文件、设备、进程信息都可以通过路径访问，这让命令行工具可以用统一方式读取和处理系统状态。

### 2. 🔥 文件权限 rwx

**简要总结：**

- `r`：读权限
- `w`：写权限
- `x`：执行权限
- 三组权限：所有者、所属组、其他人
- `chmod` 修改权限，`chown` 修改所有者

**面试口语：**

Linux 文件权限分为所有者、所属组和其他人三组。比如脚本不能执行，可能是没有 x 权限；服务不能写日志，可能是目录 owner 或写权限不对。

**底层原理 / 背后逻辑：**

权限控制是操作系统保护资源的基础。进程是以某个用户身份运行的，它能不能读配置、写日志、执行脚本，取决于该用户对目标文件和目录是否有权限。

### 3. 🔥 目录权限和文件权限区别

**简要总结：**

- 文件 `r`：读取文件内容
- 文件 `w`：修改文件内容
- 文件 `x`：执行文件
- 目录 `r`：列出目录文件名
- 目录 `w`：创建、删除、重命名目录项
- 目录 `x`：进入目录、访问路径

**面试口语：**

目录的 x 权限很重要，没有 x 权限即使知道文件名也访问不了。服务写日志失败时，不只要看日志文件权限，还要看上级目录有没有进入和写入权限。

**底层原理 / 背后逻辑：**

目录本质上保存文件名到 inode 的映射。对目录写入不是修改文件内容，而是修改目录项，所以删除文件看的是目录写权限，不只是文件本身写权限。

## 权限问题排查

### 1. ⭐ 常见权限问题

**简要总结：**

- Permission denied
- 脚本不可执行
- 日志无法写入
- Nginx 无法读取静态文件
- SSH key 权限过宽导致拒绝登录

**面试口语：**

遇到 Permission denied，我会先确认当前用户是谁，再看目标文件和上级目录权限，然后看服务进程实际用哪个用户启动。很多问题不是文件不存在，而是进程用户没有权限。

**底层原理 / 背后逻辑：**

权限问题的关键是“哪个用户访问哪个资源”。同一条命令手动执行成功，不代表服务进程能执行成功，因为服务可能是 `nginx`、`www-data` 或独立应用用户在运行。
