# 磁盘

## 磁盘空间

### 1. 🔥 磁盘满怎么排查

**简要总结：**

- `df -h`：看文件系统空间
- `du -sh *`：看目录占用
- 日志文件最常见
- Docker 镜像、容器日志也常见
- 删除文件后空间不释放，要查进程占用

**面试口语：**

磁盘满我会先用 `df -h` 看哪个分区满了，再进入对应目录用 `du -sh *` 找大目录。常见原因是日志没切割、上传文件堆积、Docker 日志或镜像占用太多。

**底层原理 / 背后逻辑：**

`df` 看的是文件系统整体空间，`du` 统计的是目录中文件占用。两者不一致时，常见原因是文件被删除了，但仍被进程打开，磁盘块还没真正释放。

### 2. 🔥 inode 满

**简要总结：**

- `df -i` 查看 inode 使用
- inode 记录文件元数据
- 小文件太多会导致 inode 用完
- inode 满了即使磁盘空间还有，也不能创建新文件

**面试口语：**

磁盘问题不只是空间满，也可能是 inode 满。比如大量小日志、小缓存文件会耗尽 inode，导致系统提示不能创建文件，但 `df -h` 看空间还没满。

**底层原理 / 背后逻辑：**

文件系统创建文件不仅需要数据块，也需要 inode 记录文件元信息。每个文件至少占一个 inode，小文件特别多时，inode 可能先耗尽。

## 磁盘 IO

### 1. ⭐ 磁盘 IO 高

**简要总结：**

- `iostat` 可看磁盘 IO
- `iotop` 可看进程 IO
- 数据库、日志、大文件读写容易造成 IO 高
- IO 等待高会拖慢整个服务

**面试口语：**

如果 CPU 看起来不高但服务很慢，我会看 IO wait。数据库查询、大量日志写入、文件上传下载都可能让磁盘 IO 成为瓶颈。

**底层原理 / 背后逻辑：**

进程读写磁盘时，如果数据不在缓存里，就要等待磁盘完成 IO。CPU 可能没满，但进程都在等磁盘，接口同样会慢。数据库慢查询和大日志写入尤其容易放大 IO 压力。

### 2. ⭐ 日志切割

**简要总结：**

- 日志持续增长会打满磁盘
- logrotate 可定期切割
- 应用也可以按日期或大小切分日志
- 要保留合理天数

**面试口语：**

线上日志必须有切割和保留策略，否则服务跑久了磁盘一定会被打满。排查磁盘满时，日志目录是第一优先级。

**底层原理 / 背后逻辑：**

服务长期运行会不断写日志。如果没有轮转，单个日志文件会越来越大，读取困难，也可能占满磁盘。切割的核心是控制增长速度和保留周期。
