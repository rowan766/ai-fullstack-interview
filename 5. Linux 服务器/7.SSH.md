## SSH 基础

### 1. 🔥 SSH 是什么

**简要总结：**

- SSH 用于远程登录服务器
- 通信是加密的
- 支持密码登录和密钥登录
- 常用于部署、排查、文件传输
- 默认端口是 22

**面试口语：**

SSH 是我们远程管理 Linux 服务器最常用的方式。它会建立加密连接，登录后可以执行命令、看日志、改配置、部署服务。

**底层原理 / 背后逻辑：**

远程管理服务器必须保证身份认证和通信加密。SSH 通过加密协议防止账号密码和命令内容在网络中明文传输，同时通过密码或密钥确认登录者身份。

### 2. 🔥 密钥登录

**简要总结：**

- 私钥保存在客户端
- 公钥放到服务器 `authorized_keys`
- 私钥不能泄露
- 私钥权限通常不能过宽
- 比密码登录更适合自动化部署

**面试口语：**

密钥登录是客户端持有私钥，服务器保存公钥。登录时不是把私钥发过去，而是通过加密挑战证明客户端确实拥有私钥。

**底层原理 / 背后逻辑：**

公钥可以公开，私钥必须保密。服务器用公钥验证客户端对挑战数据的签名。如果私钥权限太宽，SSH 会认为它不安全而拒绝使用，这是为了避免私钥被其他用户读取。

## 常见操作

### 1. ⭐ scp 和 rsync

**简要总结：**

- `scp`：简单复制文件
- `rsync`：适合增量同步
- rsync 可减少重复传输
- 部署大目录时 rsync 更高效

**面试口语：**

临时传一个文件用 scp 就够了。如果同步项目目录或大量文件，rsync 更合适，因为它可以增量比较，只传变化部分。

**底层原理 / 背后逻辑：**

文件传输的核心是网络和磁盘成本。全量复制简单但浪费，增量同步会比较差异，只传必要内容，适合部署静态资源、备份或同步配置。

### 2. ⭐ SSH 连接不上怎么排查

**简要总结：**

- 服务器 IP 是否正确
- 22 端口是否开放
- SSH 服务是否运行
- 防火墙或安全组是否放行
- 用户名、密码、密钥是否正确
- key 权限是否过宽

**面试口语：**

SSH 连不上我会先区分是网络不通、端口不通、服务没启动，还是认证失败。端口不通看防火墙和安全组，认证失败看用户名、密钥和服务器 authorized_keys。

**底层原理 / 背后逻辑：**

SSH 登录链路包括网络到达、TCP 连接、服务端 SSHD 响应、身份认证、创建 shell。每一步失败表现不同，分层排查比反复换密码更有效。

## 安全实践

### 1. 🔥 SSH 安全

**简要总结：**

- 禁止 root 直接登录
- 优先使用密钥登录
- 关闭密码登录或限制来源 IP
- 使用普通用户加 sudo
- 定期轮换密钥

**面试口语：**

生产服务器不建议开放 root 密码登录。更好的方式是普通用户密钥登录，需要管理权限时用 sudo，并通过安全组限制来源 IP。

**底层原理 / 背后逻辑：**

SSH 是服务器入口，一旦暴露在公网，就会持续受到扫描和爆破。减少可登录用户、关闭弱认证、限制来源，可以显著降低被入侵概率。
