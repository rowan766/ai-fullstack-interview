## 系统基础

### 1. 🔥 Linux 在后端部署中扮演什么角色

**简要总结：**

- Linux 是服务运行环境
- 后端服务、数据库、Nginx、Docker 常部署在 Linux 上
- 面试重点不是背命令，而是会排查线上问题
- 常见能力：文件、权限、进程、网络、磁盘、日志、安全

**面试口语：**

Linux 对后端来说就是线上服务的运行底座。代码最终不是只在 IDE 里跑，而是部署到服务器上，所以要能看进程、看端口、看日志、看资源占用，并能判断问题在应用、系统还是网络。

**底层原理 / 背后逻辑：**

Linux 把很多东西都抽象成文件，比如普通文件、目录、设备、进程信息、网络状态。服务运行时，本质上是在操作系统分配的 CPU、内存、磁盘、网络资源上执行。线上排查就是沿着这些资源边界去定位瓶颈。

### 2. 🔥 常用基础命令

**简要总结：**

- `pwd`：查看当前目录
- `ls`：查看文件
- `cd`：切换目录
- `cat` / `less` / `tail`：查看内容
- `cp` / `mv` / `mkdir`：文件操作
- `which` / `whereis`：查命令位置

**面试口语：**

基础命令我主要按场景使用，比如定位配置文件先 `pwd`、`ls`、`find`，看日志用 `tail -f` 或 `less`，确认命令路径用 `which`。核心是知道每个命令帮我确认哪类信息。

**底层原理 / 背后逻辑：**

命令行不是为了炫技，而是直接和操作系统交互。服务器通常没有图形界面，所有排查都要通过命令观察系统状态。命令组合能力越强，定位问题越快。

## 系统信息

### 1. 🔥 查看系统和资源

**简要总结：**

- `uname -a`：内核信息
- `cat /etc/os-release`：系统发行版
- `uptime`：运行时间和负载
- `free -h`：内存
- `df -h`：磁盘空间
- `top` / `htop`：实时资源

**面试口语：**

如果线上服务变慢，我会先看系统整体状态，比如负载、CPU、内存、磁盘空间，再进一步看具体进程和日志。这样能先判断是不是机器资源层面的问题。

**底层原理 / 背后逻辑：**

应用性能不是只由代码决定。CPU 打满、内存不足触发 swap、磁盘满、IO 等待高，都会让接口变慢甚至不可用。系统信息命令就是从操作系统视角看服务是否有足够资源。

### 2. ⭐ PATH 环境变量

**简要总结：**

- PATH 决定 shell 去哪些目录找命令
- `echo $PATH` 查看
- `which python` 可确认实际执行哪个程序
- 环境变量不同会导致本地和线上表现不同

**面试口语：**

PATH 决定输入一个命令时系统去哪里找可执行文件。线上如果发现 python、node、nginx 版本不对，我会先用 `which` 和版本命令确认实际执行的是哪个路径下的程序。

**底层原理 / 背后逻辑：**

shell 执行命令时，如果不是绝对路径，就会按 PATH 顺序查找。多个版本共存时，PATH 顺序会影响执行结果，所以部署脚本里最好明确环境和路径。
