# 进程管理

## 进程基础

### 1. 🔥 进程和线程

**简要总结：**

- 进程是资源分配单位
- 线程是 CPU 调度单位
- 同一进程内线程共享内存
- 不同进程之间资源隔离
- 后端服务通常以进程形式运行

**面试口语：**

进程可以理解为一个正在运行的程序实例，它有自己的内存、文件描述符和运行状态。线程在进程内部执行，多个线程共享进程资源。

**底层原理 / 背后逻辑：**

操作系统需要隔离不同程序的资源，所以用进程管理内存空间、打开的文件、网络连接等。CPU 真正执行时会在线程之间调度。线上排查时看到的是进程占了多少 CPU、内存、端口和文件描述符。

### 2. 🔥 查看进程

**简要总结：**

- `ps aux`：查看进程快照
- `top` / `htop`：实时进程资源
- `pgrep`：按名称查 PID
- `pstree`：看父子进程关系
- `kill`：发送信号

**面试口语：**

如果服务异常，我会先用 `ps` 或 `pgrep` 看进程是否存在，再用 `top` 看 CPU 和内存，再结合日志判断是进程挂了、卡住了还是资源打满。

**底层原理 / 背后逻辑：**

进程状态由内核维护，`ps`、`top` 这些命令本质上是在读取内核暴露的进程信息。排查服务不是只看端口通不通，还要看对应进程是否健康。

## 信号与后台运行

### 1. 🔥 kill 不是只能杀进程

**简要总结：**

- `kill` 本质是发送信号
- `SIGTERM`：请求进程优雅退出
- `SIGKILL`：强制终止，无法捕获
- `SIGHUP`：常用于重载配置
- 优先用优雅退出

**面试口语：**

`kill` 不是简单杀进程，它是给进程发送信号。默认通常是 SIGTERM，让进程有机会清理资源；`kill -9` 是强制杀掉，应该最后再用。

**底层原理 / 背后逻辑：**

进程收到信号后可以执行清理逻辑，比如关闭连接、刷日志、释放锁。`SIGKILL` 由内核直接终止进程，应用没有机会处理，可能造成请求中断或临时文件残留。

### 2. ⭐ 前台、后台和守护进程

**简要总结：**

- 前台进程绑定当前终端
- 后台进程可继续运行
- 守护进程长期运行，不依赖终端
- 生产服务通常交给 systemd 管理

**面试口语：**

生产环境不应该靠手动 `python app.py` 挂着服务，而应该用 systemd、Docker 或进程管理工具托管，这样进程异常退出后可以自动拉起，也方便统一查看状态和日志。

**底层原理 / 背后逻辑：**

终端关闭会影响依赖终端的前台进程。守护进程脱离终端，由系统服务管理器维护生命周期。服务管理的价值是把启动、停止、重启、日志和失败恢复标准化。
