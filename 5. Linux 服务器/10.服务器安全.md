# 服务器安全

> 图标说明：⭐ 重点｜🔥 高频｜⚠️ 注意｜💡 提示｜📌 重点记忆

## 安全基础

### 1. 🔥 最小权限原则

**简要总结：**

- 服务用独立低权限用户运行
- 不用 root 跑普通业务服务
- 文件权限只开放必要范围
- 数据库账号只给必要权限
- 云安全组只开放必要端口

**面试口语：**

服务器安全的第一原则是最小权限。业务服务不应该用 root 跑，数据库账号也不应该给所有权限。即使服务被打穿，也要限制攻击影响范围。

**底层原理 / 背后逻辑：**

安全不是假设永远不会被入侵，而是假设某一层可能失守后，如何减少横向扩散和破坏面。权限越大，单点漏洞造成的损失越大。

### 2. 🔥 防火墙和安全组

**简要总结：**

- 只开放必要端口
- SSH 限制来源 IP
- 数据库不要直接暴露公网
- Redis、MongoDB 更不能裸奔
- 内网服务只允许内网访问

**面试口语：**

公网只应该暴露必要入口，比如 80、443 和受限制的 SSH。数据库、Redis、MongoDB 这类服务不应该直接暴露公网，应该放内网或用安全组限制来源。

**底层原理 / 背后逻辑：**

互联网上会持续有扫描器探测开放端口。一个服务只要暴露公网，就会面对爆破、漏洞扫描和未授权访问风险。减少暴露面是最基础也最有效的安全手段。

## 账号与密钥

### 1. 🔥 SSH 安全

**简要总结：**

- 禁止 root 密码登录
- 优先密钥登录
- 限制 SSH 来源 IP
- 定期更换密钥
- 离职人员及时回收权限

**面试口语：**

SSH 是服务器入口，必须重点保护。我会禁用 root 密码登录，使用普通用户密钥登录，需要管理员操作时再 sudo，并且通过安全组限制来源 IP。

**底层原理 / 背后逻辑：**

弱密码、泄露密钥和未回收账号是常见入侵入口。密钥登录提升认证强度，限制来源 IP 减少攻击面，权限回收防止长期遗留风险。

### 2. ⭐ 密钥和配置安全

**简要总结：**

- 密码、Token、API Key 不提交 Git
- 使用环境变量或密钥管理服务
- 日志不能打印敏感信息
- 备份文件要加密和限制权限

**面试口语：**

敏感配置不能写死在代码里，更不能提交到仓库。生产环境通常用环境变量、配置中心或密钥管理服务注入，日志也要做脱敏。

**底层原理 / 背后逻辑：**

代码会被多人访问、复制、构建和部署，一旦密钥进入仓库，很难确认是否已经泄露。把密钥从代码中分离，可以降低泄露概率，也方便轮换。

## 运维安全

### 1. ⭐ 更新和漏洞修复

**简要总结：**

- 及时更新系统安全补丁
- 关注 Nginx、OpenSSL、数据库、运行时漏洞
- 不使用来源不明镜像和脚本
- 更新前要评估兼容性和回滚方案

**面试口语：**

服务器安全还包括补丁管理。不是看到更新就直接在线上升级，而是关注安全漏洞，评估影响，先在测试环境验证，再安排发布和回滚方案。

**底层原理 / 背后逻辑：**

漏洞经常出现在系统组件和基础软件里。补丁不及时会暴露已知风险，但盲目升级也可能引入兼容性问题。安全和稳定要一起考虑。

### 2. 🔥 入侵迹象排查

**简要总结：**

- 异常登录记录
- 陌生进程
- 异常端口监听
- CPU 或网络异常升高
- 定时任务被篡改
- 系统账号异常

**面试口语：**

如果怀疑服务器被入侵，我会看登录记录、进程、端口、定时任务、系统账号和资源异常。重点是先隔离风险，再保留证据排查。

**底层原理 / 背后逻辑：**

入侵后攻击者通常需要维持权限和执行任务，比如开后门端口、加定时任务、创建账号、运行高资源消耗进程。排查就是寻找这些偏离正常基线的行为。
