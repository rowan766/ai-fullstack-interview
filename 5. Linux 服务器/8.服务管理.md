## systemd

### 1. 🔥 systemd 是什么

**简要总结：**

- Linux 常见服务管理器
- 管理服务启动、停止、重启
- 支持开机自启
- 统一管理服务状态和日志
- 常用命令是 `systemctl`

**面试口语：**

systemd 用来管理长期运行的服务，比如 Nginx、数据库、后端应用。它能统一启动、停止、重启、查看状态，还能配置开机自启和失败重启。

**底层原理 / 背后逻辑：**

生产服务不能依赖手动启动。服务管理器负责进程生命周期，让服务运行方式标准化。进程退出后能被发现，日志能被收集，启动顺序和依赖也能被管理。

### 2. 🔥 systemctl 常用命令

**简要总结：**

- `systemctl status nginx`
- `systemctl start nginx`
- `systemctl stop nginx`
- `systemctl restart nginx`
- `systemctl reload nginx`
- `systemctl enable nginx`

**面试口语：**

看服务状态用 status，启动停止用 start 和 stop，改配置后优先 reload，不能 reload 再 restart。enable 是开机自启，不等于立刻启动。

**底层原理 / 背后逻辑：**

restart 会停止再启动，可能中断连接；reload 通常是让服务重新加载配置，影响更小。不同服务是否支持 reload 要看它如何处理信号和配置重载。

## Unit 文件

### 1. ⭐ 服务配置文件

**简要总结：**

- Unit 文件描述服务如何运行
- 常见字段：ExecStart、WorkingDirectory、Environment、User、Restart
- 可以设置运行用户
- 可以设置失败自动重启

**面试口语：**

如果我要把一个 Python 后端服务交给 systemd 管理，会写 unit 文件，配置工作目录、启动命令、环境变量、运行用户和失败重启策略。

**底层原理 / 背后逻辑：**

服务启动不是只有一条命令。它还依赖目录、环境变量、权限、日志和重启策略。Unit 文件把这些运行条件显式写出来，减少手工操作造成的不一致。

### 2. 🔥 服务启动失败怎么排查

**简要总结：**

- `systemctl status 服务名`
- `journalctl -u 服务名`
- 检查配置文件语法
- 检查端口占用
- 检查权限和环境变量
- 检查工作目录和依赖路径

**面试口语：**

服务启动失败我会先看 systemctl status 和 journalctl，再看是不是配置错、端口被占、权限不够、环境变量缺失或启动目录不对。

**底层原理 / 背后逻辑：**

服务在 shell 里能启动，不代表 systemd 里能启动。因为 systemd 的环境变量、工作目录、用户权限可能不同。排查时要站在服务实际运行环境看问题。
